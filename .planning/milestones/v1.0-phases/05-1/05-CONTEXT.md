**Status:** Ready for planning

## Phase Boundary

사람 넷(참가자 4명, 사용자 본인 포함)을 불러 설계대로 두 번(1세션 → 정확히 1주 간격 → 2세션) 플레이하고, 여섯 가설을 채점할 근거를 손에 넣는다. EXP-01~04·MEAS-05·MEAS-06이 이 단계의 요구사항이다.

**이 단계가 만드는 것(코드):** ① 위협 시계 1개(4칸)의 실제 이야기 내용(이름·정체·캐스트·시계 칸·파국)을 데이터로 짓고, 그 내용이 AI 진행자 프롬프트에 실제로 주입되게 코드를 연결한다 — 지금은 `위협 시계 상태`가 `threat: 0/6` 같은 숫자뿐이고 이야기 내용을 전달할 통로 자체가 없다(아래 `code_context` 참조). ② 비경험자 2명용 캐릭터 만들기 구두 안내 대본을 쓴다.

**이 단계가 만드는 것(운영, 코드 아님):** 참가자 모집, 관찰 기록 양식 운용, 손으로 쓴 요약(리캡) 작성·전달, 실제 세션 두 번 진행.

**이 단계가 만들지 않는 것:** 캐릭터 만들기 화면, 매칭·로비, 리캡 자동 생성(요약을 시스템이 자동으로 만들어주는 기능 — 명시적으로 M0 범위 밖, 아래 `deferred` 참조), 안전 장치 UI, 결제·계정, 코스메틱, 룰북 저작 도구 — 전부 ROADMAP·PROJECT.md가 이미 "손으로 대체"로 확정한 항목이다.

**이미 코드로 충족된 것 (새로 만들 필요 없음):**
- 판정 종류 "10개 남짓"(EXP-01) — `rulebooks/moves.py`의 `DUNGEONWORLD_LIKE_MOVES`가 정확히 무브 10개로 이미 존재
- 캐릭터 4개 그릇(EXP-01) — `web/characters_data.py`의 `PLAYER_CHARACTERS`(브람·나리·선·호두)가 이미 존재. 다만 파일 자체가 "실험 전에 진행자가 갈아 끼워야 하는 자리표시자"라고 명시
- 자유 텍스트 정답 데이터 원천(HYP-04, Phase 6이 쓸 것) — 사건 기록이 플레이어 원문·시스템 제안·확정 여부를 이미 전부 남긴다. Phase 5가 별도로 만들 것 없음

## Implementation Decisions

### 위협 시계 시나리오 내용과 AI 주입 구조

- **D-46:** 시나리오 내용(이름·위협의 정체·그것이 원하는 것·캐스트·시계 칸 4개·파국)은 **Claude가 초안을 짓는다** — "최대한 다양한 시나리오와 플레이가 나올 수 있도록" 짓는 것이 사용자의 명시적 요청이다. 특정 톤(진지/코믹/호러) 하나로 좁히지 않고, 플레이어의 다양한 접근(전투/대화/탐색/설득 등)이 전부 말이 되도록 개방적으로 설계한다.
  - *이유:* 사용자가 직접 요청 — "클로드가 최대한 다양한 시나리오와 플레이가 나올 수 있도록 써주는게 좋을 것 같다."
  - **Reversibility:** reversible — 시나리오 데이터 자체를 교체하는 것은 로컬 변경이다.

- **D-47:** 위협 시계가 4칸(파국)까지 도달하면 **그것이 세션의 자연스러운 종료점**이다. 코드로 상한선을 강제하지 않고, 파국 이후에도 즉흥으로 계속 진행하지도 않는다 — 진행자(관찰자)가 파국 서사 직후 세션을 마무리한다.
  - *이유:* 사용자 선택. "이 실험은 도달했는가가 아니라 재미있었는가를 잰다"는 ROADMAP 취지와도 맞는다 — 코드 상한선은 이번 한 번의 실험에 굳이 필요한 안전장치가 아니다.
  - **Reversibility:** reversible.

- **D-48:** 장면에 등장하는 대상(`scene_entities`)은 **시나리오 전체 캐스트를 매 턴 고정 주입**한다. "현재 국면에 등장한 인물만 골라 보여주는" 추적 로직은 새로 짜지 않는다.
  - *이유:* 사용자 선택(추천안 채택) — 구현이 가장 단순하고, 프롬프트 캐싱 계층("세션 고정")에 그대로 들어맞아 원가 제약(3.7배)에 영향이 없다.
  - **Reversibility:** reversible.

- **후속 기술 확인(질문 아님, D-46/D-48 실행에 자연히 따라옴):** `turn/context.py`의 `PLACEHOLDER_CLOCK_SEGMENT_COUNT = 6`은 EXP-01이 요구하는 "4칸"과 숫자가 안 맞는다 — 시나리오 데이터로 교체하는 작업에서 4로 바뀌어야 한다.

### 캐릭터 준비

- **D-49:** 기존 캐릭터 4명(브람·나리·선·호두) 중 **브람·나리는 그대로 유지**(경험자 2명이 쓸 캐릭터). **선·호두 자리는 비경험자 2명이 구두 안내로 새로 만든 캐릭터 데이터로 교체**한다.
  - *이유:* 선(학자)·호두(떠돌이)가 전투보다 대화·지식 쪽에 가까운 캐릭터라, 처음 해보는 사람이 "내 캐릭터가 뭐 하는 사람인지" 감을 잡기 쉬운 자리라고 Claude가 제안했고 사용자가 수락.
  - **Reversibility:** reversible — 데이터 값 교체일 뿐, `Entity` 그릇 구조는 그대로.

- **D-50:** 비경험자용 캐릭터 만들기 구두 안내 대본은 **Claude가 미리 써둔다** — `design-plan.md` §6.1의 "7가지 동작"을 던전월드 계열 캐릭터에 맞게 구체적인 질문지 형태로 만든다. 진행자가 현장에서 그대로 읽으며 진행한다.
  - *이유:* 사용자 선택(추천안 채택) — 대본 없이 즉흥 안내하면 준비물이 남지 않고, 30분 안에 끝내야 하는 시간 제약(EXP-04)에 안전하지 않다.
  - **Reversibility:** reversible.

### 관찰·기록 양식

- **D-51:** 애착 질문("당신 캐릭터 어떤 사람이에요?", MEAS-06) 대답은 **진행자(관찰자)가 손으로 적는다.**
- **D-52:** 세션 중 관찰 기록(몰입도 신호, 자유 텍스트 마찰 사례 등)도 **손으로(종이·메모) 남긴다.**
- **D-53:** 2세션 "완주 대 흐지부지"(EXP-03) 판정은 **참석 인원 수 + 끝까지 있었는지를 관찰자가 주관적으로 판단**한다. 엄격한 기준 시간(예: "3시간 이상 참여해야 완주")은 사전에 정하지 않는다.
- **D-54:** 1세션 종료 후 리캡(MEAS-05)은 **관찰자가 세션 직후 손으로 3~5줄 요약을 써서 메신저로 공유**한다. "사건 기록을 자동 집계해 스토리 요약/수치·인벤토리 요약을 나눠 시스템이 생성"하는 아이디어는 **명시적 스코프 크립으로 확인**됨 — ROADMAP 개요와 PROJECT.md Out of Scope가 "리캡 자동 생성"을 이미 M0 범위 밖으로 못박아뒀다("손으로 써도 이어할 수 있나는 검증된다"). 사용자 확인 후 M1 백로그로 이관(아래 `deferred` 참조).
  - **Reversibility:** reversible — 관찰·기록 방식은 모두 운영 절차일 뿐 코드에 영향 없음.

### 실행 준비 (참가자·일정·모델)

- **D-55:** 참가자는 **진짜 4명**(TRPG 경험자 2 + 비경험자 2)이고, **사용자 본인이 그 4명 중 한 명으로 참여**한다. 애초에 "혼자 브라우저 4개"로 진행하는 안이 나왔으나, H1(재미)과 H6(비경험자 진입)을 검증 가능한 형태로 지키기 위해 **실제 참가자 모집으로 정정**했다 — 자세한 논의는 `specifics` 참조. 나머지 3명 모집은 사용자가 진행한다.
- **D-56:** 사용자가 플레이어로 참여하므로, **별도 전담 관찰자 없이 사용자가 플레이하면서 틈틈이 메모를 남긴다.**
  - *이유:* 사용자 선택. 세부 관찰 기록의 정밀도가 낮아질 수 있다는 트레이드오프가 있으나, 사건 기록(자동)이 정량적 데이터 상당수를 대신 채운다.
- **D-57:** 세션 일정은 **3~4시간 · 정확히 1주 간격 · 저녁 8시경 시작**이라는 구조만 확정하고, **정확한 캘린더 날짜는 미정**(참가자 모집 후 사용자가 직접 잡는다). "매일 한두 시간씩" 안은 1주 간격이라는 실험의 핵심 전제와 어긋나 기각됨(`specifics` 참조).
- **D-58:** 실행에 쓸 AI 모델은 **OpenRouter의 무료 티어 모델(Nvidia Nemotron 계열)**이다. 사용자의 예산 제약("무료 모델밖에 못 쓴다")을 그대로 받아들인다.
  - **캐비어트 (Phase 6 판정 시 반드시 참고):** D18("M0은 최상급 모델 고정 — 품질 상한선을 잰다")의 취지가 이번 실행에서는 완전히 충족되지 않는다. H1(재미) 결과가 나빴을 때 "AI 진행자 개념의 한계"인지 "무료 모델이 약해서"인지 구분이 안 된다는 유보 조건이 붙는다.
  - H5(원가) 계산은 이 캐비어트의 영향을 받지 않는다 — 무료로 써도 실제 토큰 소모량은 진짜 숫자이므로, Phase 6은 해당 모델의 실제 공개 단가를 이 토큰 수에 곱해 원가를 추정하면 된다.
  - **운영 위험:** 무료 티어는 분당 요청 제한이 있을 수 있어 3~4시간 세션 도중 막힐 수 있다. 본 세션 전 짧은 사전 점검(드라이런)을 권장한다.
  - **Reversibility:** reversible — 세션마다 바꿀 수 있는 설정값(D-19 제공자 추상화 계층 덕분).

### Claude's Discretion

계획·조사 단계에서 판단하되, 위 결정을 뒤집지 않는 선에서:

- 시나리오 데이터의 정확한 파일 형식/위치(예: `rulebooks/moves.py`와 나란한 새 모듈 vs 다른 구조) — 룰북 파일 목차(D9/§4.2)나 시나리오 형식(D9/§4.8) 컨벤션을 참고해 계획 단계가 정한다
- `위협 시계 상태` 프롬프트 블록에 시나리오 내용을 정확히 어떤 문구로 넣을지(`_format_clock_state`/`_session_block_text` 확장 방식) — D-31("매 턴 넣는 것은 네 가지로 고정")을 어기지 않는 선에서, 기존 "위협 시계 상태" 슬롯 안에 내용을 채우는 형태가 유력
- 비경험자 캐릭터 만들기 구두 대본의 정확한 문구·순서
- 새로 만든 두 캐릭터(선·호두 자리)를 실제 코드 데이터로 옮겨 적는 시점과 방법(세션 시작 직전 수동 편집)
- 사용자가 4명 중 어느 캐릭터를 플레이할지
- 무료 모델 사전 점검(드라이런)의 정확한 절차

</decisions>
