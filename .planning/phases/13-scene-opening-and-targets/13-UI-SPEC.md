# Phase 13 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

이 단계가 화면에 새로 더하는 것은 매우 적다 — **오프닝 서사 한 덩어리**뿐이다(SCENE-01/02).
3층 대상 관리(SCENE-03/04)와 명부(SCENE-05)는 13-CONTEXT.md·13-RESEARCH.md 둘 다 이번 단계의
필수 화면 요소로 못박지 않았다(Architectural Responsibility Map: 명부 화면은 "UI hint: yes"일
뿐 필수 아님). 그래서 이 문서는 기존 `frontend/src/styles.css`(04-UI-SPEC.md가 세운 어두운 판
디자인 시스템, 12.1~12.3이 그대로 이어받아 확장해 온 것)를 **그대로 재사용**하고, 새 토큰·새
컴포넌트 체계를 세우지 않는다 — 세우면 이미 있는 시스템과 어긋나는 두 번째 언어가 생긴다.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — shadcn 미도입 (아래 「shadcn 게이트 판단」 참조) |
| Preset | not applicable |
| Component library | none — Radix/Base UI 없음. 순수 React 19 + 손으로 짠 CSS(`frontend/src/styles.css`) |
| Icon library | none — 유니코드 글리프만 쓴다(`✦` 빈 상태, `◆` 시계 배너, 점 셋 `.dots`/`.waiting__dots`). 새 아이콘 라이브러리를 이 단계에서 들이지 않는다 |
| Font | UI: `Pretendard Variable`(자체 호스팅, `pretendard` npm) · 이야기/이름: `Gowun Batang`(자체 호스팅, `@fontsource/gowun-batang`) — 둘 다 저장소에 번들되어 CDN 요청이 없다(styles.css 머리말 근거: 로컬 네트워크 실험 중 바깥 요청이 늘면 화면이 늦어질 수 있다) |

### shadcn 게이트 판단

`components.json`이 없고 스택은 Vite+React이지만, **이 저장소는 이미 성숙한 디자인
시스템을 갖고 있다**(04-UI-SPEC.md가 세우고 08~12.3이 계속 확장해 온 어두운 판 토큰
체계 — `--ink-*`/`--brass*`/`--accent*`/`--space-*`, `.turn`/`.narration`/`.notice`/`.screen`
류 컴포넌트 클래스 수십 개, 콥이라이팅 사전 `labels.ts::COPY`). shadcn을 지금 들이면:
① 기존 CSS 토큰과 shadcn/Tailwind 토큰 두 체계가 공존하게 되고 ② 이 단계가 새로 만드는
화면 요소가 사실상 없어(아래 참조) 초기화할 이유 자체가 옅다 ③ 상위 지침("이 저장소의
실제 화면을 근거로 삼는다")이 새 시스템 도입보다 우선한다.
**판단: 초기화하지 않는다.** `Tool: none`으로 기록하고 레지스트리 안전 게이트는
해당 없음으로 둔다.

## Spacing Scale

Declared values (기존 `:root` 토큰 그대로 재사용 — 새 값 없음):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | 아이콘 간격, 인라인 여백(`--space-xs`) |
| sm | 8px | 조밀한 요소 간격(`--space-sm`) |
| md | 16px | 기본 요소 간격, 카드 안쪽 여백(`--space-md`) |
| lg | 24px | 섹션 여백(`--space-lg`) |
| xl | 32px | 레이아웃 간격, 이야기 칸 좌우 여백(`--space-xl`) |
| 2xl | 48px | 큰 섹션 구분, 빈 상태 위아래 여백(`--space-2xl`) |

Exceptions: `3xl`(64px) 토큰은 기존 시스템에 없다 — 이 단계도 그 규모의 간격이 필요
없으므로 새로 만들지 않는다. 터치 타깃 최소 44px(`--touch-target-min`)와 4의 배수 규율은
기존 그대로 상속한다.

## Typography

기존 `.t-*` 역할 클래스를 그대로 쓴다. 오프닝 서사 자체는 **읽는 글**이라 UI 서체가 아니라
이야기 서체(`--font-story`, 명조)를 쓰는 기존 `.narration p` 규칙을 상속한다 — 이 구분(“읽는
것”과 “화면 정보”를 서체로 가른다)은 04-UI-SPEC.md가 세운 규율이고 이 단계가 새로 정의하지
않는다.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (`.t-body`, UI 산세리프) | 15px | 400 | 1.6 |
| Label (`.t-label`) | 13px | 400 | 1.5 |
| Heading (`.t-heading`) | 19px | 600 | 1.25 |
| Display (`.t-display`) | 28px | 600 | 1.2 |
| **오프닝/이야기 본문**(`.narration p`, `--font-story` 명조) — 이 단계의 핵심 표시 | 17px | 400 | 1.75 |

두 굵기(400 본문 / 600 강조)만 쓴다 — 새 굵기를 추가하지 않는다. 오프닝 본문 서체 행은
기존 `.narration p` 규칙(이미 판정 서사에 쓰이는 것과 동일)을 그대로 물려받은 것이지 새
역할이 아니다.

## Color

기존 어두운 판 토큰(`:root`)을 그대로 쓴다. 60/30/10은 배경/표면/클릭 가능한 것의 구획이고,
**놋쇠(`--brass*`)는 이 셋과 별도로 "게임 부품"에만 예약된 넷째 축**이다(styles.css 자체
주석: "게임 부품(시계·주사위·도장)에만 쓴다") — 오프닝이 새로 색을 쓸 이유가 없으므로 이
구획을 그대로 지킨다.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--ink-900` #0b0a0f (본 배경), 상판 그라디언트 | 전체 배경 |
| Secondary (30%) | `--ink-700`/`--ink-800` 그라디언트 | 카드 표면(`.turn`, `.notice`), 사이드 판(`.pane--status`/`.pane--chat`) |
| Accent (10%) | `--accent` #5b8cff / `--accent-hi` #7ba3ff | **누를 수 있는 것에만** — `.btn--primary`, 포커스 링(`:focus-visible`), 후보 카드 호버 테두리(`.candidate:hover`). 오프닝 서사 자체에는 액센트를 안 쓴다(읽는 글이지 조작이 아니다) |
| Destructive | `--danger` #e05a4b | 오류·실패 표시 전용(`.turn__error`, `.composer__status--error`, `disconnected` 배너 점). 이 단계는 새 파괴적 동작을 추가하지 않으므로 이 색을 새로 쓸 자리도 없다 |
| (넷째 축) 놋쇠 `--brass` #c9a227 | 게임 부품 전용 | 오프닝은 이 축을 쓰지 않는다 — 오프닝은 시계·주사위·판정 같은 "부품"이 아니라 이야기 문단이다 |

Accent reserved for: `.btn--primary`(기존 확정/제출류 버튼), 포커스 링, `.candidate`/`.char-card` 호버 강조 — 이 목록에 오프닝 관련 새 항목을 추가하지 않는다(오프닝에는 새 버튼이 없다, D-02가 자동 발동을 요구했고 재시도 버튼만 예외로 아래 Copywriting Contract에서 다룬다).

## Copywriting Contract

이 단계가 실제로 더하는 문구는 적다 — 오프닝은 자동 발동(D-02)이라 새 1차 CTA가 없다.
아래는 `frontend/src/labels.ts::COPY`에 추가할 항목과, **기존 문구를 그대로 재사용하는
자리**를 구분해 적는다(새 문구를 만들 필요가 없는 곳에 새로 안 만드는 것도 계약의 일부다).

| Element | Copy |
|---------|------|
| Primary CTA | 없음 — 오프닝은 `party_roster_locked` 감지 즉시 화면이 스스로 부른다(D-02). 사람이 누르는 1차 동작이 이 단계에 없다 |
| 오프닝 대기 표시 (신규, `COPY.openingWaiting`) | "진행자가 이야기를 여는 중이에요" — 기존 `Waiting` 컴포넌트(`.narration__waiting`/`.waiting__dots` 점 셋 패턴, `creationAnnouncing`과 같은 결)를 그대로 재사용해 얹는다. 새 애니메이션·새 컴포넌트를 만들지 않는다 |
| 오프닝 재시도 (신규, `COPY.openingRetry`, 예외 상황 전용) | "오프닝을 다시 불러오기" — **오프닝 API 요청 자체**가 실패했을 때만 뜬다(D-09가 이미 처리하는 "AI가 이상하게 답함"과는 다른 자리 — 그건 서버가 시나리오 원문으로 조용히 대체하므로 화면에 오류가 안 보인다). 12.3 D-13의 `creationAnnounceRetry`와 정확히 같은 모양의 예외 재시도 |
| Empty state heading | 기존 `COPY.emptyHeading`("아직 아무 일도 일어나지 않았어요") 그대로 재사용 — `party_roster_locked` 도달 전(파티 명단이 아직 안 잠긴 극히 짧은 창)에만 보이고, 새 문구를 만들지 않는다 |
| Empty state body | 기존 `COPY.emptyBody`("첫 행동을 입력해서 이야기를 시작해 보세요") — **주의:** 오프닝이 뜨는 정상 경로에서는 이 문구가 거의 안 보인다(명단 잠금 직후 즉시 오프닝 호출로 전환되므로). 이 문구를 오프닝 도착 후 문구로 바꿔 쓰지 않는다 — 여전히 "빈 이야기 판" 그 자체의 설명이다 |
| Error state — 오프닝 AI 설정 자체 없음(503) | 기존 `COPY.creationGmUnavailable`("진행자를 쓸 수 없는 상태입니다 — 운영자에게 알리세요") 재사용. 새 문구를 만들지 않는다(12.3 D-13 ②와 같은 갈래, D-09 원문에도 이 갈래는 "12.3의 처리를 그대로 따른다"고 명시) |
| Error state — 연결 끊김 | 기존 `COPY.disconnected`("연결이 끊겼어요. 자동으로 다시 시도하고 있어요 — 새로고침하지 마세요") + 상단 `.topstrip` 배너 재사용. D-09 ③과 같은 갈래 |
| Error state — AI가 오프닝을 이상하게 냄(다섯 요소 검사 실패, D-08/D-09 ①) | **화면에 오류 문구를 보이지 않는다.** 서버가 시나리오 원문을 그대로 오프닝으로 대체해 정상 응답처럼 내려준다 — 이것이 D-09의 설계 의도다("빈 화면이 생기는 순간을 만들지 않는다"). 화면은 받은 문단을 평소 오프닝과 똑같이 그린다 |
| Destructive confirmation | 해당 없음 — 이 단계는 되돌릴 수 없는 파괴적 동작(삭제·차단류)을 화면에 추가하지 않는다 |

## Component Notes (Phase 13)

새 CSS 클래스가 **원칙적으로 필요 없다** — 오프닝 서사는 기존 `.turn` 카드 골격 중 **본문
(`.narration`)만** 재사용하고 머리말·인용문·판정 줄은 렌더하지 않는 변형으로 그린다.

- **오프닝 카드(신규 컴포넌트, 기존 클래스만 재사용):** 컨테이너는 `.turn`(테두리·그라디언트·
  `turn-in` 320ms 입장 애니메이션 그대로) 안에 `.narration p`(명조 17px/1.75) 문단만 넣는다.
  `.turn__head`(행위자·무브)와 `.turn__quote`(플레이어 원문 인용)는 **렌더하지 않는다** —
  오프닝에는 행위자도 판정도 없다(D-01, 오프닝은 `declare_seq` 없이 뜬다). 기존 `TurnCard.tsx`를
  그대로 재사용하지 않는 이유: 그 컴포넌트는 `turn.rawText`(플레이어 인용)를 항상 필수로
  그린다 — 오프닝에는 그 값 자체가 없다.
- **오프닝 대기:** 기존 `Waiting`(`frontend/src/components/Waiting.tsx`) 컴포넌트를 그대로
  가져다 `label={COPY.openingWaiting}`로 쓴다. 새 스피너·새 점 애니메이션을 만들지 않는다.
- **재시도 단추(예외 갈래만):** 기존 `.btn`/`.btn--ghost` 클래스 재사용 — `CreationScreen`의
  `creationAnnounceRetry` 단추와 같은 시각 처리.
- **명부 화면:** 이 단계는 만들지 않는다(CONTEXT.md Claude's Discretion — "UI hint: yes"이나
  필수 아님). 계획이 만들기로 하면 `StatusPane`의 기존 목록 패턴(`.chip`/`.stat-row`류)을
  따를 것 — 새 목록 컴포넌트 체계를 만들지 않는다.
- **대상 지목 표시(굴리기 전, D-13①):** 이 단계 화면 계약에 포함하지 않는다 — SCENE-04의
  성공 조건은 "결정론적으로 처리되는가"이지 "화면에 대상이 어떻게 보이는가"가 아니다.
  분류기 확인 카드(`.candidate`)에 대상 칩을 더하는 것은 선택 사항이며, 만들면
  `.candidate__stat`(회색, 우측 정렬, 12px)과 같은 시각 무게를 쓴다.
