    - `PLACEHOLDER_CLOCK_SEGMENT_COUNT = 6`을 선언하고, `cli/turn_flow.py`의 같은 이름 상수와 같은 이유(시나리오 데이터가 없으니 D-21이 적은 "4~6칸" 중 하나를 자리 표시자로 쓴다, 실제 칸 수는 EXP-01의 준비물에서 와야 한다)를 도크스트링에 적는다. `web`은 `cli`를 import할 수 없으므로 값을 다시 선언하는 것이 유일한 방법이다 — 두 자리가 어긋나면 화면과 프롬프트의 시계 칸 수가 달라진다는 경고도 함께 적는다.

    - 처리기는 `store.read_events(session_id, from_seq=from_seq)`와 `rebuild_state(store, session_id)`만 부른다. `from_seq: int = Query(0, ge=0)`. **접기 로직을 여기서 다시 짜지 않는다** — 상태 숫자를 만드는 곳은 리듀서 하나뿐이다.
    - `GameEvent`를 응답 모델로 그대로 쓴다. 사건의 두 번째 전송용 스키마를 손으로 만들지 않는다.

    `frontend/src/session_view.ts`에 그리기만 담는다.

    `frontend/src/main.ts`에 폴링 루프를 둔다.
    - `POLL_INTERVAL_MS = 1500` (D-38의 1~2초), `DISCONNECT_AFTER_FAILURES = 7` (1.5초 × 7 ≈ 10.5초, D-40의 "약 10초"). 두 값 모두 그 근거를 주석에 적는다.

    - 요청이 실패하면(네트워크 오류 또는 응답이 정상이 아님) 연속 실패 수를 하나 늘린다. `DISCONNECT_AFTER_FAILURES` 이상이면 화면 맨 위에 화면 폭 전체를 차지하는 배너를 보조면 색으로 띄우고 라벨 역할(14px/400) 굵은 글자로 `연결이 끊겼어요. 자동으로 다시 시도하고 있어요 — 새로고침하지 마세요`를 찍는다. 성공하면 연속 실패 수를 0으로 되돌리고 배너를 제거한다. 재연결 알림 문구는 만들지 않는다 — 배너가 사라지는 것 자체가 신호다. 다시 시도 버튼도 만들지 않는다 — 루프가 이미 1.5초마다 다시 시도하므로 버튼은 그것과 경주할 뿐이다.
    - 폴링 주기를 0.5초로 줄이지 않는다. 한 번에 문장 여러 개가 모여 나와도 된다(D-39).
