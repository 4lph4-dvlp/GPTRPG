    `mountActionInput(root, sessionId, playerId, characterId)`:
    - 서사 피드 아래에 붙는 한 줄 — 본문 역할 글자(16px/400)의 텍스트 입력 칸 하나와 제출 버튼 하나. 바깥 여백 24px, 버튼 최소 높이 44px, 버튼 색은 강조 `#2563EB`. 이 강조 색은 이 단계에서 세 곳(입장 버튼, 행동 확인 버튼, 행동 제출 버튼)에만 쓰인다.
    - 제출하면 `POST /api/sessions/{id}/actions/declare`에 `{player_id, character_id, raw_text}`를 보낸다. 보내는 동안 `setSubmitBusy(true, "AI가 분류하는 중…")`으로 버튼을 눌리지 않는 상태로 만들고 옆에 라벨 역할(14px/400) 글자로 그 문구를 띄운다. 응답이 오면 `setSubmitBusy(false, null)`.
    - 요청이 실패하면(응답이 정상이 아니거나 네트워크 오류) 입력 칸 값을 지우지 않는다 — 사람이 다시 칠 필요가 없어야 한다.

    `renderProposal(root, proposal, onConfirm, onReject)` — 응답의 `tier` 값에 따라 세 갈래로 그린다. **이 세 갈래는 Phase 3이 이미 정한 것을 화면 모양으로 옮기는 것일 뿐, 갈래를 나누는 규칙 자체는 손대지 않는다.**
    - `none`: 확인 버튼을 하나도 만들지 않고 `인식된 행동이 없어요. 다른 문장으로 다시 말해 보세요`만 찍는다. 입력 칸은 그대로 남아 바로 다시 칠 수 있다. **분류가 재시도까지 실패한 경우도 서버가 같은 `none`을 돌려주므로 화면이 두 경우를 구별하지 않는다** — 「무엇이 잘못됐는지」를 나눠 보여 줘도 플레이어가 할 수 있는 일은 다시 치는 것 하나뿐이다.
    - `single`: 카드 하나에 제안된 무브와 능력치를 본문 역할 글자로 찍고 버튼 둘 — `이 행동으로 진행`(강조 색)과 `다시 쓰기`(강조도 파괴도 아닌 기본 글자 버튼). 제안을 물리는 것은 위험한 동작이 아니라 판단을 바꾸는 것이므로 확인 대화상자를 만들지 않는다.
    - `several`: 후보 카드를 세로로 쌓는다(사이 간격 8px). 서버가 최대 셋까지만 보내므로 화면도 셋이 상한이다. **각 카드의 확인 버튼 문구에 그 후보의 무브 이름을 그대로 넣는다** — 예를 들어 무브 이름이 `강타`면 버튼 문구가 `"강타"로 진행`이 된다. 이렇게 해야 세 개의 버튼이 위치가 아니라 글자만으로 구별된다. 카드 묶음 아래에 `다시 쓰기` 하나를 공유로 둔다.
    - **신뢰도 숫자를 어디에도 찍지 않는다.** 화면 강도는 후보 개수만으로 정해지고, 임계값 기반 폴백 화면은 이 프로젝트가 범위 밖으로 밀어 둔 항목이다.
    - 확인을 누르면 `POST /api/sessions/{id}/actions/confirm`에 `{player_id, character_id, move, stat, suggestion_move, suggestion_stat, confirmed: true, declare_seq}`를 보낸다. `suggestion_*`은 **서버가 처음 내민 첫 번째 후보**를 그대로 넣는다 — 사람이 몇 번째를 골랐든 이 값은 안 바뀐다. 「첫 제안이 맞았나 / 후보에서 골랐나 / 직접 찾았나」가 이 두 값의 대조로 계산되기 때문이다. `modifiers`는 보내지 않는다(수정치 입력 화면은 이 단계에서 만들지 않는다).
    - `다시 쓰기`를 누르면 같은 경로에 `confirmed: false`로 보내고 제안 카드를 지운다 — 거부도 기록에 남아야 정답 데이터가 완성된다.
    - 확인 요청을 보내는 동안 카드의 버튼들을 눌리지 않는 상태로 만들고 서사 피드에 `AI가 생각하는 중…`을 라벨 역할 글자로 한 줄 띄운다(`renderInlineNotice`). 응답이 오면 그 줄을 지운다 — 실제 서사는 폴링이 가져온다.
    - 확인 요청이 502를 받으면 서사 피드에 `이번 턴을 처리하지 못했어요. 다시 시도해 주세요`를 한 줄로 남긴다. 503이면 같은 자리에 서버 설정 문제임이 드러나는 한 줄을 남긴다. 어느 경우든 응답 본문의 원문을 그대로 화면에 쏟지 않는다.

    확인·거부 응답을 받은 뒤 화면을 직접 갱신하지 않는다 — 행동을 낸 사람도 다른 세 명과 **똑같이 폴링으로** 결과를 본다. 렌더 경로가 둘이 되면 행동한 사람과 구경한 사람이 서로 다른 화면을 보게 되고, 그건 「같은 세션 화면을 동시에 본다」가 깨진 것이다.
