것이 이 계획이다. 여기서 뚫은 경로 위에 09-02(상황판단/서술 분리)와 09-03(병렬 판단

  `recent_turns` 길이가 `CLOCK_JUDGE_RECENT_TURNS_LIMIT`을 넘으면 `ContextCapExceeded`를
  던진다. **이 값 객체에는 위협의 정체·원하는 것·파국 문장을 담는 칸이 아예 없다** —
  조건 검사에 필요 없는 시나리오 원문을 타입 차원에서 막는 것이 이 객체의 목적이다.
  도크스트링에 그 이유를 적는다.

**④ `src/gptrpg/agents/invoke.py`** — `CLOCK_JUDGE_TIMEOUT_S = 5.0` 한 상수를
`CLASSIFIER_TIMEOUT_S` 옆에 같은 도크스트링 관례로 추가한다. 근거를 적을 것: 닫힌 신호
하나를 돌려받는 경량 판단이므로 분류기와 같은 층의 값이고, D-27이 잠근 두 값
(`CLASSIFIER_TIMEOUT_S`·`GM_TIMEOUT_S`)은 건드리지 않는다. `MAX_ATTEMPTS`도 그대로다.

**⑤ `src/gptrpg/agents/config.py`** — 세 가지를 바꾼다.
- `AGENT_ROLES`를 `("action_classifier", "master_gm", "situation_judge",
  "scene_entity_judge", "clock_judge")` 다섯으로 늘린다. 도크스트링에 D-32의 두 역할이
  D-64로 다섯이 됐다는 것과 각 역할이 무엇을 하는지 한 줄씩 적는다.
- `STRICT_AGENT_ROLES: tuple[str, ...] = ("action_classifier", "master_gm")`와
  `ROLE_FALLBACKS: dict[str, str] = {"situation_judge": "master_gm",
  "scene_entity_judge": "action_classifier", "clock_judge": "action_classifier"}`를
  선언한다. 대체 대상 선택 근거를 도크스트링에 적는다 — 상황판단은 서술과 같은 급의
  추론이 필요하므로 `master_gm`을, 닫힌 판단 둘은 분류기와 같은 급이므로
  `action_classifier`를 물려받는다.
- `load_config`의 역할 순회를 고친다. `STRICT_AGENT_ROLES`에 든 역할이 파일에 없으면
  지금처럼 `InvalidAgentConfig`를 던진다. `ROLE_FALLBACKS`에 든 역할이 파일에 없으면
  대체 역할의 `AgentChoice`를 그대로 물려주고 **표준오류에 한 줄** 찍는다 — 어떤 역할이
  어떤 역할의 무슨 제공자/모델을 물려받았는지와 `gptrpg agents set --role <역할>`로 따로
  정할 수 있다는 안내를 담는다. 도크스트링에 "이것은 조용한 대체가 아니다"를 명시할
  것: 대체가 일어났다는 사실이 stderr에 보이고, 실제로 어느 모델을 썼는지는
  `RecordAiCall`이 역할별로 계속 정확히 기록하므로 Phase 6의 계측이 흐려지지 않는다.
  `load_partial_config`와 `save_config`·`resolve_provider`의 본문은 손대지 않는다.

**⑥ `src/gptrpg/agents/prompt_assembly.py`** — 조립 함수 둘을 추가한다. 기존
`build_classifier_prompt`/`build_gm_prompt`와 `_format_*` 헬퍼는 이 태스크에서 손대지
않는다. 두 함수 모두 모듈 도크스트링의 순서 규약(영구 고정 → 세션 고정 → 턴마다 변함)을
지키고, `system`의 두 조각에 `_cached_block`을 그대로 쓴다.
- `build_clock_signal_prompt(*, rulebook_display_name: str, ctx: ClockJudgeContext)`:
  `permanent` 조각은 역할 지시문 + 닫힌 출력 계약이다. 계약 내용 — 응답은 원소가 정확히
  하나인 JSON 배열이고 그 원소는 `signal` 칸과 `why` 칸을 갖는 객체이며, `signal`은
  `"check"` 또는 `"skip"` 두 값만 허용하고, 칸 번호·수치·판정 결과를 절대 돌려주지
  않는다는 것을 지시문에 못박는다. `session` 조각은 `ctx.clock_position`과
  `ctx.next_segment_description`, `messages`(턴 조각)는 `ctx.recent_turns`와
  `ctx.check_summary`다.
- `build_clock_condition_prompt(*, rulebook_display_name: str, ctx: ClockJudgeContext,
  narration_text: str)`: 같은 모양이되 `permanent`는 "다음 칸에 적힌 일이 실제로
  일어났다고 볼 수 있는가"를 묻는 더 깊은 지시문이고, 출력 계약은 `verdict` 칸(`"advance"`
  또는 `"hold"`)과 `why` 칸이다. `messages`에 `narration_text`(이번 턴에 실제로 나간 서사)를
  덧붙인다 — 배경 작업은 서사가 끝난 뒤에 돌므로 이 값을 볼 수 있다.
  두 함수 모두 지시문에 **칸을 실제로 넘기는 것은 시스템이 하고 너는 판단만 한다**를
  명시한다(D14).

**⑦ `src/gptrpg/agents/clock_judge.py` (신규)** — `action_classifier.py`의 구조를 그대로
복제한다.
- `@dataclass(frozen=True) class ClockSignal`: `should_check: bool`, `why: str`,
  `ai: AgentResult`.
- `@dataclass(frozen=True) class ClockConditionVerdict`: `condition_met: bool`,
  `why: str`, `ai: AgentResult`.
- `judge_clock_signal(*, provider, model, ctx: ClockJudgeContext,
  rulebook_display_name) -> ClockSignal`: `build_clock_signal_prompt`로 조립하고,
  `provider.complete(...)`를 무인자 클로저로 감싸 `call_with_one_retry(..., timeout_s=
  CLOCK_JUDGE_TIMEOUT_S)`에 넘긴다. `max_tokens`는 분류기와 같은 1024. 실패하면
  **예외를 던지지 않고** `ClockSignal(should_check=False, why="", ai=result)`를 돌려준다 —
  "없으면 없는 대로 진행"이 정상 경로다(D-05/ARCH-05).
- `judge_clock_condition(*, provider, model, ctx, rulebook_display_name,
  narration_text) -> ClockConditionVerdict`: 같은 모양, 실패 시
  `condition_met=False`.
- 파싱은 `json_parsing.try_parse_json_array`를 쓰고, 배열이 비었거나 첫 원소가 dict가
  아니거나 값이 닫힌 목록 밖이면 **거짓 쪽으로 떨어진다**(예외를 던지지 않는다). 여기서는
  `UnknownMove`에 대응하는 예외를 만들지 않는다 — 무브 이름과 달리 이 판단의 닫힌 목록은
  두 값뿐이라, 목록 밖 값은 "판단 못 함"과 구분할 실익이 없다. 이 판단 근거를 모듈
  도크스트링에 적는다.
- 모듈 도크스트링에 D14를 못박는다: 이 모듈은 참/거짓 신호와 이유 문자열만 돌려주고
  칸 번호를 계산하거나 돌려주는 코드가 한 줄도 없다.

**⑧ `src/gptrpg/turn/clock_condition.py` (신규)** — 웹과 CLI가 **같은 함수**를 부르게
하는 자리다(두 경로가 갈리지 않게 하는 것이 이 파일의 존재 이유이고, 그 사실을 모듈
도크스트링에 적는다). `gptrpg.turn`은 `agents`와 `session_actor`를 둘 다 내려다볼 수
있는 유일한 층이다(contract:2).
- `build_clock_judge_context(ctx: TurnContext, check_summary: str) -> ClockJudgeContext`:
  `TurnContext.clock_state`에서 `clock_position`(현재 칸/전체 칸)과
  `next_segment_description`(다음 칸 설명, 없으면 빈 문자열)만 꺼내고 `recent_turns`는
  뒤에서 `CLOCK_JUDGE_RECENT_TURNS_LIMIT`개만 잘라 넘긴다. **정체·원하는 것·파국 문장은
  옮기지 않는다.**
- `async def run_clock_condition_check(*, actor: SessionActor, provider: Provider,
  model: str, judge_ctx: ClockJudgeContext, rulebook_display_name: str,
  narration_text: str, resolve_seq: int, clock_id: str, clock_segment_count: int) -> None`:
  `_illustrate_scene`의 3단 구조를 그대로 복제한다.
  1. `asyncio.to_thread`로 `judge_clock_condition`을 작업 스레드에 내보낸다(막는 AI
     호출이 이벤트 루프를 잡지 않게 — `routes_actions.py` 모듈 도크스트링의 제약).
  2. 어떤 예외도 위로 던지지 않는다. `Exception`을 잡아 stderr에 경고 한 줄만 남기고
     반환한다. `condition_met`이 거짓이면 아무 일도 하지 않고 그냥 반환한다(정상 경로).
  3. 조건 충족이면 **코드가** 다음 칸 번호를 정한다: `actor.state.clock_segment`를 읽어
     `clock_segment_count` 이상이면 아무것도 제출하지 않고 반환하고(상한 검사 —
     `_prepare_clock`은 이 검사를 하지 않으므로 여기서 해야 한다), 그렇지 않으면
     `actor.submit(AdvanceClock(clock_id=..., segment_index=actor.state.clock_segment + 1,
     trigger="condition", caused_by_seq=resolve_seq))`를 부른다. 제출 실패도 삼키고
     stderr 한 줄로 끝낸다.
  - `actor.state` 읽기와 `actor.submit`은 반드시 이벤트 루프 스레드에서 한다(작업
     스레드로 내보내지 않는다 — sqlite3 스레드 제약).
  - 도크스트링에 D3를 못박는다: 이 함수 밖에 배경 산출물을 사건으로 남기는 다른 경로를
     만들지 않는다.
