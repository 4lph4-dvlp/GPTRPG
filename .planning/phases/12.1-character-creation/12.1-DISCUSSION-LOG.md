## 스코프 정정 (논의 시작 직후)

첫 질문 묶음이 거절됐다. 사장님 원문:

> "지금 너의 질문의 스코프가 잘못됐어. 너는 지금 현재 테스트에 쓰이는 시나리오, 룰북에만
> 고정되어 캐릭터 소개 기능을 개발하려고 하고 있어. 일단, 게임 세팅에 의해 인원이
> 몇명인지부터 파악하여 방대한 종류의 룰북, 시나리오에 맞는 캐릭터 소개 기능이 필요한거야."

**철회된 질문 넷:** 만든 캐릭터가 어디 사나 / 룰북이 절차를 어떻게 적나 / 파티 전원 대기
규칙(「네 명」 전제) / 한 줄 소개를 누가 쓰나.

**정정 후 확인한 사실:** `web/routes_actions.py:129`의 `_current_party_state()`가 「저장소에
선언된 캐릭터 전부를 파티로 본다」이고, `agents/context.py:64` 주석에 "실제 파티는 넷이다"가
적혀 있다. 인원 개념이 코드에 없다는 것이 확인됐다.

> 모든 시나리오는 룰북에 의해 짜여질테고 그러면 두 내용은 서로 다른 것을 가리킬 수 없잖아"

부수적으로 「시스템 무관 시나리오」가 실제로 존재한다는 점만 짚고 Phase 13으로 넘김.

## 확정된 인원과 만들기가 만나는 지점 (시작 시점)

| Option | Description | Selected |
|--------|-------------|----------|
| 방을 연 사람이 시작을 누른다 | 시스템은 「몇 명 중 몇 명이 끝났다」만 보여줌 | |
| 전원이 끝나야 자동으로 열린다 | 다 차면 그 순간 시작 | |
| 만든 사람부터 바로 들어간다 | 대기 없음, 늦은 사람은 중간 합류 | |
| 게임 세팅이 선언한다 | 룰북·시나리오가 「전원 필요」를 적음 | |

**User's choice:** 넷 다 아님 — 자유 서술. 사장님 원문:

> "캐릭터 만들기는 자기소개처럼 되야 한다. GM이 캐릭터를 만들 때 필수적으로 들어가야하는
> 내용을 말해주면 자신의 순서에서 한명씩 돌아가며 자기 캐릭터의 서사를 얘기한다. 이때
> 필수적으로 들어가야하는 내용이 파악되지 않거나, 부족하다고 판단되면, GM이 해당 부분에
> 대해 되묻거나 추가적인 질문을 하여 내용을 채워나간다. 그렇게 모든 사람들이 자시소개를
> 끝내면 GM이 한번 정리를 해주고 이렇게 게임을 진행할까요? 해서 모두의 최종 동의를 받고
> 게임을 시작한다"

**Notes:** 이 답이 두 번째 스코프 정정이다. 「일곱 가지 동작 = 화면 위젯 일곱 개」라는
전제가 무너지고, 룰북이 선언하는 것이 **「무엇이 있어야 캐릭터가 완성인가」의 항목
목록**임이 확정됐다. ROADMAP이 미정으로 남긴 「파티 전원 대기 규칙」도 여기서 답이 났다
— 전원이 끝나고 동의까지 받아야 시작. → CONTEXT D-03, D-10.

## 자기소개 대화 안에서 숫자를 정하는 방식

| Option | Description | Selected |
|--------|-------------|----------|
| GM이 제안하고 본인이 확인 | 서사에서 배치를 뽑아 보여주고 사람이 확인 | |
| 숫자도 GM이 그자리에서 정한다 | 대화가 가장 끊김없지만 검산 불가 | |
| 서사가 끝난 뒤 따로 정한다 | 대화와 숫자를 분리 | |
| 룰북이 항목마다 정한다 | 「이 항목은 말로, 이 항목은 직접 고르기로」 | |

**User's choice:** 룰북이 정한다 — 다만 조사가 선행되어야 한다는 조건 추가. 사장님 원문:

> "룰북마다 정하는 방식이 다르다고 알고 있다. 어떤 룰북은 완전히 주사위를 굴려서 정하고,
> 어떤 룰북은 정해진 숫자들을 각 능력치들에 플레이어가 재량껏 배치하여 벨런스를 맞춘다.
> 이러한 능력치 설정 방식에는 몇가지 유형들이 있으니 이를 조사하고 룰북에서 규정하는
> 방식에 맞는 UI를 사용해서 진행하도록 해야할 것 같다."

**Notes:** D22가 일곱 가지를 적어 두었으나 검증된 적이 없고 `RULEBOOK-SURVEY.md`에도 이
항목이 없음을 확인해 **조사 과제로 명시**했다. 조작 유형과 오가는 정보까지가 이 단계,
화면 생김새는 Phase 16이라는 경계도 함께 확인. → CONTEXT D-04.

## GM이 「부족하다」고 판단하는 기준

| Option | Description | Selected |
|--------|-------------|----------|
| 룰북이 항목마다 적는다 | 누가 해도 같은 데서 끝남 | |
| GM이 읽고 판단한다 | 사람 GM과 비슷하나 때마다 통과가 갈림 | |
| 둘을 섞는다 | 룰북이 최소선, 그 위는 GM 재량 | ✓ |
| 되묻지 않는다 | 받은 대로 받고 넘어감 | |

**User's choice:** 둘을 섞는다
**Notes:** 재량의 **목적**이 함께 규정됐다. 사장님 원문:

> "룰북마다 규정하는 상세함 정도가 다르다. 그러니 룰북을 기반으로 하되, GM이 판단하여
> 게임 플레이에 플레이어에게 특징이 될만한 서사 두어가지가 있으면 좋겠다는 마음으로
> 자세한 서사를 물어볼 수 있다."

되묻는 목적이 「더 자세하게」가 아니라 「나중에 이야기에서 걸 수 있는 갈고리 확보」라는
점이 핵심. Phase 13.1·14와 연결됨. → CONTEXT D-05.

## 만든 캐릭터의 수명

| Option | Description | Selected |
|--------|-------------|----------|
| 그 판에서만 산다 | 다음에 하면 새로 만듦 | |
| 남아서 다음에 다시 데려온다 | 계정이 필요 | |
| 한 판짜리로 두되 남길 자리를 비워 둔다 | 나중에 계정이 생기면 확장 | |

**User's choice:** 셋 다 아님 — 질문 전제 자체를 교정. 사장님 원문:

> "캐릭터를 만들면 세션에서만 쓰는게 아니라 시작부터 끝까지 해당 캐릭터로 진행을
> 해야하는거야. 중간에 캐릭터를 추가하거나 뺄 수가 없지. 원래 TRPG가 그렇잖아."

**Notes:** 「한 판」을 접속 한 번으로 읽은 질문이 틀렸다. 캐릭터는 **이야기 단위**로 살고
파티 명단은 시작 시점에 잠긴다. D22의 「정원이 안 차도 진행한다」는 출석 얘기이지 명단
얘기가 아니라는 ROADMAP 경고가 여기서 확인됨 — 두 규칙은 양립한다. 「캐릭터 변경하기」
할 일의 설계 판단도 이걸로 확정(점유를 놓는 경로는 만들지 않는다). 계정 부재로 인한
한계를 명시하기로 함. → CONTEXT D-08, 접힌 할 일.
