## Pattern Assignments

### `rules_core/rulebook.py` — `CreationStepDecl`/`CreationStepKind`/`CreationStepTarget` 신설

**아날로그:** `ResourceAxisDecl`(`rules_core/rulebook.py:109-131`), `GradeBand`(`64-107`)

**"이름은 룰북 것, 형태는 플랫폼 것" 분업 패턴** (109-123행):
```python
@dataclass(frozen=True)
class ResourceAxisDecl:
    """룰북이 선언하는 자원 축 하나 — 이름과 그 값이 담기는 표현 형태.

    `name`이 룰북 어휘("체력" 같은 이름)를 담당하고, `form`은 플랫폼이
    아는 여섯 종 표현 형태(`ResourceAxisForm`)를 담당한다 ...
    """

    name: str
    form: ResourceAxisForm
    none_kind: NoneKind | None = None
    slot_count: int | None = None
    stat_usage: StatUsage | None = None
```
`CreationStepDecl`도 이 분업을 그대로 베낀다: `kind`(플랫폼 어휘, Literal)·`target`(플랫폼
어휘, Literal) vs `step_id`/`label`(룰북 콘텐츠). RESEARCH.md 472-507행의 스케치가 이미
이 모양으로 초안을 잡아 두었다 — 그대로 채택하되 Format Test가 발견한 "조건부 건너뛰기"
랜드마인(RESEARCH.md 530행)을 `optional`/`skip_if` 류 필드로 보강할 것.

**Rulebook 컨테이너에 필드 추가하는 자리** (`rulebook.py:301-324`):
```python
@dataclass(frozen=True)
class Rulebook:
    rulebook_id: str
    display_name: str
    resolution_method: str
    grade_bands: tuple[GradeBand, ...]
    resource_axes: tuple[ResourceAxisDecl, ...]
    check_trigger_mode: CheckTriggerMode
    difficulty_levels: tuple[DifficultyLevelDecl, ...] = ()
    outcome_list: OutcomeList = OutcomeList(categories=())
    retro_declaration: RetroDeclarationDecl = RetroDeclarationDecl(allowed=False)

    def __post_init__(self) -> None:
        names = [axis.name for axis in self.resource_axes]
        if len(names) != len(set(names)):
            raise InvalidResourceAxis(...)
```
`party_size_range`·`creation_steps` 신설 필드는 여기 같은 자리에 기본값 없이(D-02가 요구하는
"필수 선언" 강제) 또는 「이 룰북엔 그 개념이 없다」를 표현할 명시적 기본값과 함께 추가한다
(`outcome_list`/`retro_declaration`이 쓰는 "빈 값 = 개념 없음" 관례 참고, 316-324행).

**예외 패턴 — "모르는 것을 조용히 넘기지 않는다"** (`InvalidResourceAxis`, 341-354행):
```python
class InvalidResourceAxis(Exception):
    """... 조용히 통과하면 룰북이 선언한 목록과 실제로 개체가 갖는 값의 형태가
    어긋난 채로 등록되고, 그 어긋남은 화면·판정 코드에 닿기 전까지 어디서도
    드러나지 않는다 — `NoMatchingGradeBand`/`UnknownGradeName`이 세운 "조용히
    넘기지 않는다" 규율을 그대로 따른다.
    """

    def __init__(self, reason: str, name: str | None = None) -> None:
        super().__init__(f"자원 축 선언이 유효하지 않다: {reason} (name={name!r})")
        self.reason = reason
        self.name = name
```
D-02가 요구하는 "시나리오 인원 범위가 룰북 범위 밖이면 적재 시점에 거절"용 신설 예외
(`PartySizeOutOfRange` 류)는 정확히 이 모양(`reason`+식별자, 사람이 읽을 문구를
`super().__init__`에 조립)을 베낀다.

### `event_log/schema.py` — 신설 사건 종류(캐릭터 만들기 완료/파티 명단 잠금 등)

**아날로그:** `CharacterOccupied`(`event_log/schema.py:268-279`)

```python
class CharacterOccupied(EventEnvelope):
    """캐릭터를 처음 점유했다 — 먼저 잡은 사람이 임자다(D-05/D-06).

    놓기 사건은 없다(D-07) — 한 번 잡으면 놓을 수 없다는 결정이 사건 종류
    목록에도 그대로 반영된다. 서버를 껐다 켜도 이 사건을 다시 읽으면 점유가
    복원된다.
    """

    event_type: Literal["character_occupied"]
    character_id: str
    browser_id: str
```
신설 사건(예: `CharacterCreated`/`PartyRosterLocked`)은 `EventEnvelope`를 상속하고
`event_type: Literal[...]` 하나 + 최소 페이로드로 구성하는 이 모양을 그대로 따른다.
`pydantic`이 "빠진 필드·오타 필드를 거부한다"(schema.py:1)는 계약도 그대로 유지된다.

**판 올림 도크스트링 패턴** (`EVENT_SCHEMA_VERSION`, 19-33행) — 새 판을 열 때 "판 N -> 판 N+1"
문단을 이 자리에 이어 쓰고, 어떤 사건이 늘었는지·`caused_by_seq`가 무엇을 가리키는지·
`reducer.py` 어느 분기와 같은 커밋이어야 하는지를 반드시 명시한다(8→9 승격 시 이 문단
바로 앞에 이어 붙일 것).

**아날로그:** `character_occupied` 분기(`reducer.py:285-292`)

if event_type == "character_occupied":

### `session_actor/actor.py` — 만들기 완료 → 자동 점유 (CHAR-05)

**아날로그:** `OccupyCharacter`/`_prepare_occupy`(`session_actor/actor.py:646-684`)

```python
def _prepare_occupy(self, command: OccupyCharacter) -> tuple[str, int | None, dict]:
    """캐릭터 점유 판정 — 먼저 잡은 사람이 임자다(D-05). 놓기는 없다(D-07).

    검증 순서가 중요하다(주석은 각 단계가 무엇을 지키는지 적는다).
    """
    if not command.character_id.strip():
        raise CommandRejected("character_id는 비어 있을 수 없다")
    if not command.browser_id.strip():
        raise CommandRejected("browser_id는 비어 있을 수 없다")

    # D-14: 사건이 존재하는데(last_seq >= 0) 점유 사건이 하나도 없으면
    # 옛 세션(판 5 미만 기록)이다 — 다시보기만 된다.
    if self.state.last_seq >= 0 and not self.state.occupied_by:
        raise CommandRejected("이 세션은 점유 기록이 없는 옛 세션이다 — 다시보기만 된다")

    holder = self.state.occupied_by.get(command.character_id)
    if holder is not None and holder == command.browser_id:
        raise AlreadyOccupied("이미 이 캐릭터를 점유하고 있다")
    if holder is not None:
        raise CommandRejected("이미 다른 분이 고른 캐릭터예요")

    for occupied_character_id, occupied_browser_id in self.state.occupied_by.items():
        if occupied_browser_id == command.browser_id and occupied_character_id != (
            command.character_id
        ):
            raise CommandRejected("이 브라우저는 이미 다른 캐릭터를 점유하고 있다")

    return (
        "character_occupied",
        None,
        {"character_id": command.character_id, "browser_id": command.browser_id},
    )
```

**순서 위험 (RESEARCH.md RQ-5 결합 절):** `if self.state.last_seq >= 0 and not
self.state.occupied_by:`(661행)가 "사건이 있는데 점유가 없으면 옛 세션"으로 읽는다.
따라서 **만들기 완료 사건 → 점유 명령 제출** 순서를 반드시 지켜야 한다(거꾸로 하면
`last_seq >= 0`이 아직 안 된 상태에서 점유를 먼저 넣게 되어 위 로직과 어긋날 위험은 없지만,
반대로 완료 사건 없이 점유부터 하면 "완료도 안 됐는데 점유"라는 CHAR-05 취지 위반이 된다).

**호출부 재사용 패턴** (`web/routes_characters.py:283-286`, `select_character`):
```python
actor = request.app.state.registry.get_or_create(session_id)
try:
    await actor.submit(
        OccupyCharacter(character_id=body.character_id, browser_id=browser_id)
    )
except AlreadyOccupied:
    pass  # 본인 재접속 — 성공으로 진행한다(D-05).
```
만들기 완료 직후 이 `actor.submit(OccupyCharacter(...))` 호출을 그대로 재사용한다 — 새
명령/권한 개념을 만들지 않는다(Claude's Discretion이 명시).

### 신설 값 결정 조작 — 주사위 유형(⑤ `roll_to_fill`)

**아날로그(결과를 사건에 영구 기록하는 계약):** `rules_core/resource_change.py:138`
```python
def roll_amount(roller: DieRoller, amount: int | str) -> tuple[int, tuple[int, ...]]:
    ...  # LiveRoller 주입 → (합계, 실제 눈 튜플) → 사건에 그대로 기록
```
새 「주사위 굴려 채우기」 만들기 단계도 이 시그니처와 같은 3단 계약을 따른다: ①

사건을 다시 접어 같은 값이 나오는지 결정성 시험으로 증명한다.

**정정할 오해 (반드시 계획에 반영):** `event_log/replay_roller.py`의 `ReplayRoller`는
**프로덕션 재구성(replay) 경로에서 쓰이지 않는다** — `session_actor/projection.py`의
`rebuild_state_from_events`는 사건에 이미 기록된 `rolls`/`amount`를 그대로 읽을 뿐 다시
굴리지 않는다. `ReplayRoller`를 실제로 인스턴스화하는 곳은 `tests/test_dice_replay.py`·
`tests/test_resolution_d100.py`·`tests/test_dice_amount.py` 셋뿐 — **전부 테스트 파일**이다.
"주사위 유형은 `Roller`와 `replay_roller`를 탄다"(D-04)의 정확한 의미는 "커맨드 제출
시점에 `LiveRoller`로 굴리고, 그 결정성을 테스트에서 `ReplayRoller`로 증명한다"는 것이지
"재생 시 `ReplayRoller`가 다시 굴린다"는 뜻이 아니다.

**기존 파서의 한계 (랜드마인):** `resource_change.py:60`의 `_DICE_EXPR`는 `NdM±flat`만
지원한다 — D22 원문이 예시로 든 `4d6k3`(keep-highest 3) 표기를 지원하지 않는다. 「주사위
굴려 채우기」 단계를 구현할 때 이 파서를 그대로 재사용하면 D22의 예시조차 표현 불가능

파서를 만들지 판단해야 한다.

## `characters_data.py` 이동 위치

D-12가 요구하는 "제품에서 지우고 시험 재료로만 남긴다"의 실제 목적지를 저장소 관례에서
찾은 결과: `tests/fixtures/`는 이미 `README.md` + `session1_events.jsonl` +
`session1_expected_state.json`이라는 **비-파이썬 픽스처 데이터** 디렉터리로 쓰이고 있다.
반면 `PLAYER_CHARACTERS`는 **파이썬 `Entity`/`StatEntry` 객체**이고 지금은
`test_web_characters.py`(26-32행에서 직접 import) 외에 `test_web_actions.py`·
`test_imagery.py`·`test_reducer_resource_change.py`·`test_rulebook.py`가 전부 이 상수를
직접 import해서 쓴다(`grep -rln PLAYER_CHARACTERS tests/`로 확인). 이런 다중 소비처를 가진
파이썬 픽스처는 이 저장소에 아직 전례가 없다 — 계획이 실제로 정할 것은 다음 둘 중 하나다:

1. `tests/fixtures/characters.py`(신설 — `test_` 접두어가 없어 pytest가 자동 수집하지
   않는다, 기존 `tests/fixtures/` 디렉터리의 "데이터 전용, 수집 대상 아님" 성격과 일치)로
   `PLAYER_CHARACTERS`/`CHARACTER_ARCHETYPES`/`NEW_CHARACTER_*` 상수를 그대로 옮기고
   테스트들이 이 경로에서 import하도록 고친다.
2. `tests/conftest.py`에 `pytest.fixture`로 감싸 제공한다(공용 픽스처 관례를 따르는 방법이나,
   지금 소비처들이 "세션 스코프 딕셔너리를 직접 변형"(`test_web_characters.py:91,149`에서
   `PLAYER_CHARACTERS[test_character_id] = test_entity`로 임시 삽입 후 삭제하는 패턴)하므로
   모듈 상수 형태를 유지하는 옵션 1이 기존 테스트 코드 변경을 최소화한다.

**권고:** 옵션 1 — `conftest.py`의 기존 역할("프로젝트 루트 상수 + 임시 사건 기록 경로 픽스처")과
겹치지 않게, `tests/fixtures/characters.py`라는 새 이름 없는 데이터 모듈로 옮기고 기존
다섯 테스트 파일의 import 문만 `gptrpg.web.characters_data` → `tests.fixtures.characters`로
