## 사전 정리 — "코어"와 "백엔드"

사용자가 논의 시작 시점에 물었다: *"혹시 phase 1에서 웹을 만드는거야? 나는 개인적으로 웹이든 CLI든 모든 클라이언트에서 사용할 수 있는 '코어'를 만드는게 중요하다고 생각하는데, 어떻게 생각해? 곧 python 백엔드가 코어가 되려나?"*

정리한 내용:

- Phase 1에 화면은 없다. 화면은 Phase 3, 여러 명 동시 접속은 Phase 4
- 사용자의 직관은 잠금 결정 D3의 4계층 구조와 일치한다 — 맨 위가 전송 어댑터인 이유가 정확히 "웹이든 CLI든 여기만 갈아끼운다"이다
- **"백엔드"는 위치 개념(서버에서 도는 것 전부), "코어"는 역할 개념(그중 게임의 진실을 다루는 부분).** 백엔드가 코어를 품는 관계지 같은 말이 아니다
- 사용자가 코어에 포함시켜 생각한 세 가지 일 중 ②주사위·판정만 규칙 코어다. ①룰북 변환은 Phase 2, ③AI 진행은 Phase 3이며 **AI는 규칙 코어 바깥에 있다**
- 정직하게 밝힌 함정: Python 코어는 TypeScript 프런트엔드에서 네트워크 너머로만 쓸 수 있다. 브라우저 안에서 규칙이 돌아야 하는 상황이 생기면 코어를 두 번 짜거나 언어를 바꿔야 한다

**제시한 배경:** 로드맵이 이 단계를 두고 "이 단계의 유일한 숙제는 기록에 필드를 빠뜨리지 않는 것"이라고 적은 이유 — 빠뜨린 필드는 Phase 6에 가서야 발견되는데, 그때는 이미 끝난 두 세션을 다시 할 수 없고 프로젝트 존폐를 가르는 숫자가 날아간다.

## 주사위 되감기

**먼저 정리한 사실:** 잠금 결정이 정한 암호학적 난수는 원래 재현 불가능하게 설계된 물건이라 "씨앗을 남겨두고 나중에 다시 굴린다"가 원리적으로 안 된다. 되감으려면 굴러 나온 눈을 그대로 기록에 남기는 수밖에 없다.

### Q13. 주사위를 굴리는 일을 규칙 코어와 어떻게 연결할까요?

| Option | Description | Selected |
|--------|-------------|----------|
| 굴리는 도구를 건네준다 | 진행할 땐 진짜 굴리는 도구를, 되감을 땐 기록에서 읽어오는 도구를 건넴. 같은 코드가 그대로 돌고 재굴림도 한 번 더 부르면 끝 | ✓ |
| 왕복해서 받아온다 | 흐름이 눈에 보이나 재굴림마다 왕복이 늘고 되감기용 별도 경로가 필요 | |
| 미리 넉넉하게 굴려둔다 | 가장 단순하나 몇 개 필요할지 미리 알 수 없고 안 쓴 굴림이 기록에 섞여 집계를 방해 | |

**Notes:** Phase 2의 룰북 수정치 네 유형 중 "재굴림"이 이 선택을 가른다는 점을 근거로 제시.

전체 요약 후, 논의 중 언급했다 넘어간 두 항목을 짚을지 물었고 사용자가 "두 개 더 짚기"를 선택했다.

### Q16. '누가 볼 수 있는지' 항목을 지금 넣을까요?

| Option | Description | Selected |
|--------|-------------|----------|
| 항목만 넣고 전부 공개로 | 항목은 두되 M0에서는 값이 항상 "전체 공개". 귓속말 기능은 안 만듦. 비용은 항목 하나 | ✓ |
| 안 넣는다 | 필요해지면 판 번호를 올려 추가. 판 번호 체계를 정했으니 실제로 가능한 선택 | |
| 넣고 동작까지 | 최소 도구 범위에 없는 기능을 늘리는 선택 | |

**Notes:** "기능을 만드느냐"가 아니라 "자리를 비워두느냐"의 문제임을 명시. 설계 문서 §3.7이 이미 모양을 정해뒀고 M4의 시야 계산도 같은 장치를 재사용한다는 점을 근거로 제시.

### Q17. AI 관련해 Phase 1이 어디까지 해둘까요?

| Option | Description | Selected |
|--------|-------------|----------|
| 기록 자리만 지금 | "AI를 불렀다" 사건 종류를 정의(역할·모델·토큰·소요 시간). 실제 호출 코드는 Phase 3 | ✓ |
| 코드 껍데기까지 | 제공자 추상화를 미리 짬. 아직 아무도 안 쓰는 껍데기를 상상으로 짜게 되고 Phase 3에서 다시 고칠 가능성이 큼 | |
| 둘 다 Phase 3에서 | 가장 깔끔하나 Phase 3에서 기록 모양을 다시 손대야 하고, 이 단계의 숙제를 뒤로 미루는 선택 | |

**Notes:** D19가 "제공자 추상화를 M0에 넣는다"고 정했으나 그건 "M0 안에서"이지 "Phase 1에서"가 아니라는 점을 밝힘. 다만 D-11이 산출해야 할 여섯 숫자 중 둘(토큰 소모량, 응답 속도)이 AI 호출에서 나오고 원가가 프로젝트를 멈출 수 있는 조건이므로 기록 자리는 Phase 1의 몫임을 근거로 제시.
