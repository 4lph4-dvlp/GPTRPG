새 모듈 `src/gptrpg/rulebooks/threat_clocks.py`를 만들고, 그 값이 `ClockState` → `build_turn_context` → `_format_clock_state` → `_session_block_text`를 거쳐 실제 프롬프트 텍스트로 나오는 한 경로를 끝까지 잇는다. 이 태스크는 **경로를 뚫는 것**이 목적이므로 캐스트는 한 명만, 칸 설명은 네 줄만 채운다 — 캐스트 확장과 본문 저작은 Task 2다.

`threat_clocks.py` 구성:
- 모듈 도크스트링은 `openquest_creatures.py`의 세 요소 관례를 따른다 — ① 출처(이 시나리오는 Claude가 창작한 것이며 던전월드를 포함한 어떤 룰북·저작물의 원문도 아니다, D-46) ② 일부러 담지 않은 것(D21 데이터 구조 중 「진행 조건」과 「상태(대기/진행됨/무효화됨)」는 넣지 않는다 — 진행 시점은 `SessionActor`의 실패 카운터가, 현재 상태는 `GameState.clock_segment`가 이미 유일한 출처다) ③ 관련 결정 번호(D-46·D-47·D-48·D21).
- `THREAT_CLOCK_SEGMENT_COUNT = 4` — EXP-01이 요구한 칸 수이자 D21의 4~6칸 범위 안 값.
- `@dataclass(frozen=True) class ThreatClockContent`, 칸 여섯: `clock_id: str`, `name: str`, `identity: str`, `wants: str`, `segment_descriptions: tuple[str, ...]`, `catastrophe: str`.
- `M0_THREAT_CLOCK: ThreatClockContent` 인스턴스 하나. `clock_id`는 반드시 `"threat"` — `build_turn_context`가 이미 그 이름으로 `ClockState`를 만들고 `SessionActor`의 자동 진행도 같은 시계 id를 쓴다. `segment_descriptions`는 길이 4.
- `THREAT_CAST: tuple[Entity, ...]` — 이 태스크에서는 `Entity` 하나만. `entity_id`는 `scenario.` 접두사로 이름공간을 나누고, `rulebook_id`는 `DUNGEONWORLD_LIKE_ID`를 import해서 쓴다(문자열 재입력 금지).
- `rules_core`를 import하되 `rules_core`가 이 모듈을 알아서는 안 된다 — 판정 계산 코드에 시나리오 내용이 새면 D5 분리가 깨진다.

`src/gptrpg/agents/context.py`: `ClockState`에 기본값 있는 칸 다섯을 더한다 — `threat_name: str = ""`, `threat_identity: str = ""`, `threat_wants: str = ""`, `segment_descriptions: tuple[str, ...] = ()`, `catastrophe_text: str = ""`. 기본값이 있어야 `ClockState(clock_id=..., segment_index=..., segment_count=...)`만 부르는 기존 호출부 열 곳 남짓(`tests/test_master_gm.py`, `tests/test_action_classifier.py`, `tests/test_agents_retry.py`, `tests/test_turn_tracer.py`)이 한 글자도 안 바뀐다. **`TurnContext`에는 다섯 번째 칸을 만들지 않는다** — 같은 파일 55-57줄이 칸이 정확히 넷임을 `TURN_CONTEXT_FIELD_NAMES`로 코드에 못박아 뒀고, D-31이 「매 턴 넣는 것 네 가지 고정」이다. 시계 상태 칸의 유일한 담지자인 `ClockState` 안을 넓히는 것이 그 잠금을 지키는 방법이다.

`src/gptrpg/turn/context.py`: `PLACEHOLDER_CLOCK_SEGMENT_COUNT`의 값을 `threat_clocks.THREAT_CLOCK_SEGMENT_COUNT`에서 가져오게 바꾼다(이 태스크에서는 이름은 그대로 둔다 — 이름 정리는 Task 3). 도크스트링은 「시나리오 데이터가 생기면 거기서 읽어야 한다」던 자리표시자 설명을 지금 실제로 그렇게 되었다는 내용으로 갱신한다. `ClockState` 조립에 `M0_THREAT_CLOCK`의 다섯 값을 채워 넣고, `scene_entities`를 `EXAMPLE_SINGLE_STAT_FOE` 한 개짜리 튜플에서 `THREAT_CAST`로 바꾼다(D-48 — 국면별 필터링 로직은 만들지 않는다). `character_state`의 기본값은 `EXAMPLE_SINGLE_STAT_FOE.stats` 그대로 두고, 왜 여기만 남았는지(캐릭터를 안 고른 명령줄 경로의 기본값) 한 문장으로 도크스트링에 적는다. 도크스트링 57-61줄의 「`clock_advances`도 `fails_since_clock`도 넣지 않는다」 문단은 지우지 말고, 이번에 들어오는 것은 서사 내용이지 관측 지표가 아니라는 한 문장을 그 문단에 잇는다.

`src/gptrpg/agents/prompt_assembly.py`: `_format_clock_state(clock) -> str`를 넓힌다. 노출 범위는 **이름 / 위협의 정체 / 그것이 원하는 것 / 현재 칸 번호와 전체 칸 수 / 이미 지나온 칸들의 설명 / 바로 다음 칸의 설명**까지이고, 파국 문장은 마지막 칸에 도달했을 때만 넣는다 — 파국까지 미리 다 보여주면 AI가 결말을 알고 서사가 뻔해진다. 형제 포매터 두 개와 같은 관례를 지킨다: 문자열 연결은 f-string만 쓰고 `.format()`이나 템플릿 엔진을 새로 들이지 않는다(시나리오 텍스트에 중괄호가 섞여도 안전해야 한다), 값이 비어 있으면 한국어 「(없음)」 계열 자리표시자로 떨어뜨린다. 특히 `threat_name`이 빈 문자열인 기존 호출부에서는 지금과 같은 `"{clock_id}: {segment_index}/{segment_count}"` 한 줄 형태로 떨어져야 한다. 여기 들어가는 값은 **칸이 바뀔 때만** 바뀌어야 한다 — 시각·세션 식별자·경과 시간처럼 호출마다 달라지는 값은 한 글자도 넣지 않는다.

`tests/test_prompt_assembly_scenario.py`(신규): `tmp_db_path` 픽스처로 `EventStore`를 열고 `build_turn_context`를 직접 불러 `_session_block_text`로 펼친 문자열을 검사한다(가짜 제공자는 필요 없다 — 프롬프트 조립까지만 확인한다). 최소 네 가지: ① 시나리오 이름·정체·원하는 것 문자열이 결과에 들어 있다 ② 같은 칸에서 두 번 조립한 결과가 서로 같다 ③ `clock_advanced` 사건을 하나 넣어 칸을 넘긴 뒤 조립한 결과가 이전과 다르다 ④ `build_turn_context`가 돌려준 `scene_entities`가 `THREAT_CAST`와 같다.
