**D-49 준수 — 브람·나리의 수치는 건드리지 않는다.** `PLAYER_CHARACTERS["bram"]`·`["nari"]`의 `StatEntry` 튜플은 한 줄도 수정하지 않는다: 능력치 여섯 값(브람 `STR=2/DEX=0/CON=1/INT=-1/WIS=0/CHA=0`, 나리 `STR=0/DEX=2/CON=0/INT=1/WIS=1/CHA=-1`), 체력(브람 20/20, 나리 16/16), 브람의 `방어구=2` — 전부 지금 파일에 있는 값 그대로 남는다. 두 캐릭터를 아래 규격에 맞춰 다시 계산하거나 재배치하지 않는다. D-49가 「브람·나리는 그대로 유지(경험자 2명이 쓸 캐릭터)」라고 확정했고, 이 계획은 그 결정을 그대로 따른다.

**신규 캐릭터 규격 (적용 대상: 선·호두 자리, 즉 세션 당일 새로 만드는 두 캐릭터뿐):**
`characters_data.py` 모듈 최상단에 이름 있는 상수로 선언한다. 대본(Task 2)과 코드가 같은 숫자를 두 곳에 따로 적어 두면 어긋나므로, 숫자의 출처를 코드 상수 한 곳으로 둔다.
- `NEW_CHARACTER_STAT_NAMES = ("STR", "DEX", "CON", "INT", "WIS", "CHA")` — 능력치 여섯 칸 이름과 순서.
- `NEW_CHARACTER_STAT_ARRAY = (2, 1, 1, 0, 0, -1)` — 새로 만드는 사람이 여섯 자리에 배치할 값 묶음. 정렬하면 `[-1, 0, 0, 1, 1, 2]`다.
- `NEW_CHARACTER_HP_BASE = 16`, `NEW_CHARACTER_HP_PER_CON = 2` — 체력은 `NEW_CHARACTER_HP_BASE + CON * NEW_CHARACTER_HP_PER_CON`이고 `current`와 `max`를 같은 값으로 둔다. `depleted_effect_ref`는 `"dungeonworld_like.hp_depleted"`. 이것이 design-plan.md §6.1의 ⑦「자동 계산」에 해당하는 유일한 항목이다.
- 상수 도크스트링에 적용 범위를 명시한다: 이 규격은 세션 당일 구두 안내로 새로 만드는 두 캐릭터가 따르는 규격이고, 기존 브람·나리에는 적용되지 않는다는 것. 그 이유(D-49 — 경험자 둘이 쓸 캐릭터는 그대로 유지)도 한 줄로 적는다.
- 일곱 번째 상태값 `방어구`는 새 캐릭터에게도 선택 사항이다. **브람만 갖고 나리는 갖지 않는 현재 상태를 그대로 둔다** — `tests/test_web_characters.py`가 상태값 개수가 다른 쌍이 같은 화면으로 그려짐을 확인하는 데 이 쌍을 쓰므로, 이 비대칭을 반드시 유지한다.

**브람·나리 — 한 줄 소개만 다시 쓴다:**
- `CHARACTER_ARCHETYPES["bram"]`·`["nari"]`의 한 줄 소개를 05-01 시나리오의 세계·위협과 이어지게 다시 쓴다. 지금 값("무너진 성채의 파수병" 등)은 시나리오가 없던 시절의 자리표시자다. 한 줄 소개는 화면 캡션이므로 `Entity` 안에 넣지 않는다 — 지금처럼 `CHARACTER_ARCHETYPES`에 남긴다.
- 두 사람이 서로 다른 접근을 대표한다는 성질은 이미 기존 수치가 갖고 있다 — 브람은 `STR`이 가장 높아 `hack_and_slash`·`defend`가 자연스럽고, 나리는 `DEX`가 가장 높아 `volley`·`pick_lock_or_trap`이 자연스럽다. 새 한 줄 소개가 이 성질과 어긋나지 않게 쓴다. 수치를 소개에 맞추는 것이 아니라 소개를 수치에 맞춘다.
- `display_name`(브람·나리)과 `entity_id`(`player.bram`·`player.nari`)는 바꾸지 않는다 — 웹 라우트·쿠키·테스트가 이 식별자를 쓴다.

**선·호두 자리:**
- 이 두 칸은 세션 당일 통째로 교체될 자리표시자다(D-49). 위 규격에 맞는 값으로 정리해 둔다 — 지금 값은 규격을 벗어나 있다(선의 체력 14가 `16 + CON*2 = 16`과 다르고, 호두의 능력치 여섯을 정렬하면 `[-1, 0, 0, 0, 1, 2]`로 배열과 다르다). 정리해 두면 규격 단언이 처음부터 초록이 되고, 세션 당일 손으로 갈아 끼운 값이 규격을 벗어나는 순간 그 단언이 잡아 준다. `entity_id`(`player.seon`·`player.hodu`)와 딕셔너리 키는 바꾸지 않는다.
- 모듈 도크스트링을 고쳐 상태를 정확히 적는다 — 브람·나리는 D-49대로 기존 값 그대로 실험 준비물로 확정되었고, 선·호두 두 칸은 규격에 맞춘 자리표시자이며 세션 시작 직전에 손으로 교체되고, 그 절차와 필드 대응표가 `docs/experiment/character-creation-script.md`에 있다는 것. 도크스트링에 이미 있는 「`Entity` 칸을 늘리지 않는다」 경고는 지우지 말고 그대로 둔다.
