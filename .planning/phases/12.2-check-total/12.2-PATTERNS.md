### `src/gptrpg/event_log/schema.py` (model/config, event-driven) — D-01/D-02/D-03의 핵심 지점

**Analog:** 자기 자신 — `_require_identity_from_schema_5` 검증기(213행)와 그 필드(186-197행)

**베낄 전례 — 판 5 검증기, 전문** (`schema.py:186-197`):
```python
    person_id: str | None = None
    character_id: str | None = None
    """「어느 브라우저가 · 어느 캐릭터로」(TRUST-04, D-12). 판 5 이상
    기록에서는 아래 검증기가 두 칸을 필수로 강제한다 — 판정 기록에 누구의
    판정인지가 반드시 남는다. 판 5 미만 기록은 이 칸이 없어도 그대로 읽힌다
    (`.gptrpg/events.db`의 판 2 판정 기록 38건, D-13)."""

    @model_validator(mode="after")
    def _require_identity_from_schema_5(self) -> "CheckResolved":
        if self.schema_version >= 5 and (self.person_id is None or self.character_id is None):
            raise ValueError("판 5부터 person_id·character_id는 필수 칸이다")
        return self
```

**D-01/D-02/D-03이 그대로 복제할 신규 모양** (문자 그대로 치환, `if self.schema_version >= 10:`):
```python
    total: int | None = None
    rulebook_id: str | None = None
    """판정 합계와 룰북 이름(D-01/D-03). 판 10 이상 기록에서는 아래 검증기가
    두 칸을 필수로 강제한다. 판 10 미만 기록은 이 칸이 없어도 그대로 읽힌다."""

    @model_validator(mode="after")
    def _require_total_from_schema_10(self) -> "CheckResolved":
        if self.schema_version >= 10 and (self.total is None or self.rulebook_id is None):
            raise ValueError("판 10부터 total·rulebook_id는 필수 칸이다")
        return self
```

**검증기가 판을 읽는 정확한 메커니즘** — `self.schema_version`은 `EventEnvelope`의 인스턴스
필드(별도 컨텍스트 변수 아님). 쓰기 시점에 전역 상수를 그대로 박아 넣는 자리
(`session_actor/actor.py:638-646`, 전문):
```python
event = _EVENT_CLASSES[event_type](
    session_id=self._session_id,
    seq=seq,
    schema_version=EVENT_SCHEMA_VERSION,
    caused_by_seq=caused_by_seq,
    recorded_at=utc_now_iso(),
    event_type=event_type,
    **fields,
)
```
읽을 때는 저장된 옛 값이 그대로 검증기에 들어간다(`event_log/store.py:93-103` → `parse_event`).

**`Grade = str`로 넓힌 전례** (`schema.py:118-124`, D-10이 계산-조각 "역할" 필드 타입을 정할 때 따를 판단) 전문:
```python
Visibility = Literal["public"]

# rules_core.grading.Grade와 값은 같지만 별도로 선언한다 — 두 층은 서로를 모른다.
# str로 넓힌 이유: 등급 이름의 권위가 이제 룰북 선언에 있고(D32), 룰북마다
# 서로 다른 이름 집합을 쓸 수 있어야 하므로 고정 Literal로는 두 번째 룰북을
# 표현할 수 없다. 실제 이름 목록은 gptrpg.rulebooks 아래 각 룰북 선언에만 있다.
Grade = str
```

**`EVENT_SCHEMA_VERSION` 도크스트링 관례** — 판 8→9 절(22-42행 부근)의 문단 구조(무엇이
바뀌었나 → 새/늘어난 칸 → 하위 호환 근거 → reducer.py 같은 커밋 여부 선언)를 판 9→10 절도
그대로 복제할 것. 단 이번은 "새 사건 종류"가 아니라 "기존 종류에 칸 추가"이므로 reducer.py
같은 커밋 선언은 **"무변경"**으로 적어야 한다(아래 `reducer.py` 절 참조).

### `ModifierRecord` / `ModifierView` — 계산 조각(D-09) 구조의 최근접 전례

**사건 쪽** (`event_log/schema.py:153-159`, 전문):
```python
class ModifierRecord(BaseModel):
    """판정 사건 안에 남는 수정치 하나 — 유형·값·출처."""

    model_config = ConfigDict(extra="forbid", frozen=True)

    type: str
    value: int
    source: str  # (159행 다음 줄, 동일 파일에서 확인)
```

**응답 쪽** (`web/routes_actions.py:562-566`, 전문):
```python
class ModifierView(BaseModel):
    type: str
    value: int
    source: str
```

두 선언이 "유형(=역할) · 값 · 출처" 세 칸으로 정확히 짝을 이룬다. **계산 조각(segment)도
같은 3단 모양을 따를 것을 D-09/CONTEXT.md가 권고**한다 — 예:
```python
class CalculationSegmentView(BaseModel):
    role: str    # 자유 문자열(Grade = str 전례, D-10) — "십의 자리"/"일의 자리"/"백분위"/"눈"/"보정치"/"합계" 등
    value: int
```
