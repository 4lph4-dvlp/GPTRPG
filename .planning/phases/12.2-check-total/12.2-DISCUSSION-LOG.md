## 합계를 어디서 만드나

### 규칙 코어가 계산해 둔 합계를 화면까지 어떻게 전달할까요?

| 선택지 | 설명 | 선택 |
|--------|------|------|
| 사건에 합계 칸을 늘린다 (ⓐ) | 판정 기록에 `total` 칸을 늘려 규칙 코어의 계산을 그대로 저장. 판 5 전례 덕에 옛 기록 이전 불필요 | ✓ |
| 「더해도 되나」 신호만 (ⓑ) | 사건은 그대로, 서버가 「더할 수 있다/없다」만 알림. d100에서 검산은 여전히 불가 | |
| 둘 다 | 합계도 저장하고 신호도 별도로 | |

**Notes:** 로드맵이 적은 ⓐ의 대가(「기록 이전이 따라온다」)가 실제와 다르다는 것을 코드 확인 중 발견 — `CheckResolved`가 판 5에서 `person_id`/`character_id`에 쓴 검증기 패턴을 그대로 쓰면 이전이 필요 없다.

### 새로 늘리는 합계 칸을 얼마나 엄격하게 강제할까요?

| 선택지 | 설명 | 선택 |
|--------|------|------|
| 이번 판부터 필수 | 옛 기록은 빈 칸 허용, 판 10 이상에는 합계가 빠질 수 없다 | ✓ |
| 선택 칸으로만 둔다 | 채우면 좋고 안 채워도 통과. 「안 남겼다」와 「진짜 0」이 구분 안 됨 | |

### 같은 산수를 하는 화면 세 자리를 어떻게 정리할까요?

| 선택지 | 설명 | 선택 |
|--------|------|------|
| 세 자리 다 고치고 검산 줄은 한 곳에서만 | 「숫자를 어떻게 읽히는가」를 한 곳으로 모으고 세 화면이 가져다 쓴다 | ✓ |
| 세 자리 다 고치되 각자 따로 | 덜 움직이지만 네 번째 화면에서 같은 실수 재발 가능 | |
| 검산 화면 하나만 (로드맵 원문) | 지난 판정 목록·굴림 연출은 d100에서 계속 틀린 숫자 | |

**Notes:** 로드맵은 `CheckBreakdown` 하나만 지목했으나 `TurnCard.tsx:56`·`DiceModal.tsx:136`도 같은 산수를 한다는 것을 코드 확인 중 발견.

### 저장된 합계가 나중에 규칙 코어와 어긋나는 일을 어떻게 막을까요?

| 선택지 | 설명 | 선택 |
|--------|------|------|
| 재생으로 대조하는 시험을 둔다 | 기록된 눈을 `replay_roller`로 다시 흘려 저장된 합계와 비교 | ✓ |
| 저장할 때 서버가 매번 대조 | 더 엄격하나 같은 코드로 두 번 계산이라 방어력이 적다 | |
| 따로 두지 않는다 | 기존 판정 시험에 맡긴다 | |

## 옛 판정 38건의 검산 줄

### 합계가 안 남은 예전 판정을 화면이 어떻게 보여줄까요?

| 선택지 | 설명 | 선택 |
|--------|------|------|
| 눈과 보정치만 보이고 합계 자리는 비운다 | 모르는 것을 아는 척하지 않는다 | ✓ |
| 서버가 그때 룰북으로 다시 계산해 채운다 | 옛 기록도 검산이 살아나지만 룰북 식별이 필요하고 계산이 두 곳으로 나뉨 | |
| 지금처럼 화면이 더해서 보여준다 | 옛 기록에 한해 지금 산수 유지. 두 산수가 공존 | |

### 비운 합계 자리에 무엇을 보일까요?

| 선택지 | 설명 | 선택 |
|--------|------|------|
| 「합계 기록 없음」이라고 적는다 | 숫자가 있어야 할 자리에 이유를 적는다 | ✓ |
| 아무것도 안 보인다 | 조용하지만 사람이 왜 없는지 묻게 된다 | |
| 가운뎃점 기호로 빈 칸 표시 | 짧지만 뜻을 알 수 없다 | |

### 이번 판 올리기에 합계 말고 「판정 방향」도 같이 실을까요?

| 선택지 | 설명 | 선택 |
|--------|------|------|
| 합계만 실는다 — 방향은 응답으로 | 사건은 사실만, 해석은 룰북이 가진다는 경계 유지 | ✓ |
| 방향도 사건에 같이 싣는다 | 기록만 보고도 검산 가능. 룰북 선언을 고치면 어긋남 | |
| 방향은 이번에 안 다룬다 | 등급 도장이 해석을 말해준다고 보고 미룸 | |

**Notes:** 코드가 스스로 미뤄 둔 `succeeded`/`costs`는 「접기가 그 값을 필요로 하게 되면 그때」라는 조건을 달아 뒀고 그 조건이 아직 오지 않아 이번 판에 넣지 않기로 확인.

### 한 세션 안에 두 모양이 섞이는 것을 어떻게 할까요?

| 선택지 | 설명 | 선택 |
|--------|------|------|
| 그대로 둔다 — 사실이니까 | 기록이 실제로 다른 판으로 쓰였고 화면은 그것을 그대로 보인다 | ✓ |
| 새 세션부터 적용하고 안내 | 섞임은 없지만 세션마다 다른 규칙, 지금 세션은 계속 틀림 | |
| 섞임을 화면이 접어서 숨긴다 | 깔끔하지만 검산이 한 번 더 멀어진다 | |

## 눈이 합계가 되는 과정

### 눈이 합계가 되는 과정을 화면이 어디까지 보여줄까요?

| 선택지 | 설명 | 선택 |
|--------|------|------|
| 서버가 「계산 줄」 자체를 만들어 보낸다 | 조각을 서버가 만들고 화면은 그리기만 | ✓ |
| 숫자와 목표만 보인다 | 틀린 숫자는 멈추지만 눈→합계 길은 여전히 안 보임 | |
| 화면이 룰북별로 그리는 법을 안다 | 규칙을 화면에 중복 구현 — 12-07 주석이 금지한 것 | |

### 서버가 보내는 「계산 줄」은 어떤 모양이면 좋을까요?

| 선택지 | 설명 | 선택 |
|--------|------|------|
| 역할이 붙은 조각 목록 | 한국어 문구는 화면(`labels.ts`)이 계속 갖고, 세 화면이 제 모양으로 그린다 | ✓ |
| 완성된 문장 하나 | 간단하나 문구 권위가 서버로 넘어가고 굴림 연출이 못 쓴다 | |
| 조각 + 예비 문장 | 안전하나 보낼 것이 둘로 늘고 어긋날 수 있다 | |

### 지난 판정의 계산 줄을 서버가 다시 그리려면 룰북을 알아야 합니다. 어떻게 할까요?

| 선택지 | 설명 | 선택 |
|--------|------|------|
| 판정 기록에 룰북 이름도 같이 남긴다 | 같은 판 올리기에 합계와 함께. 언제든 계산 줄·방향을 다시 만들 수 있다 | ✓ |
| 계산 조각을 사건에 그대로 저장한다 | 그때 보였던 것이 영원히 남지만 사건이 표현까지 담게 된다 | |
| 방금 굴린 판정에만 계산 줄을 보인다 | 가장 작지만 지난 판정을 되짚는 순간이 검산이 필요한 때 | |

**Notes:** `CheckResolved`에 `rulebook_id`가 없다는 것을 코드 확인 중 발견. `rulebook_id`는 해석이 아니라 사실이므로 「사건은 사실만」 원칙과 어긋나지 않는다고 판단.

### 계산 조각의 「역할」을 어떻게 정할까요?

| 선택지 | 설명 | 선택 |
|--------|------|------|
| 룰북이 자유롭게 붙인다 | 등급 이름(`Grade`)을 자유 문자열로 넓힌 것과 같은 방식 | ✓ |
| 플랫폼이 아는 닫힌 목록 | 화면이 종류별로 알맞은 모양을 주지만 새 룰북이 막힌다 | |
| 지금 두 룰북만 담을 만큼 | 빠르지만 「범용 시스템」 목표와 정면 충돌 | |

## 안 쓰인 눈과 다시 굴린 눈

### 굴렸지만 안 쓰인 눈을 화면이 어떻게 보여줄까요?

| 선택지 | 설명 | 선택 |
|--------|------|------|
| 흐리게 함께 보인다 | 기록이 버려진 눈을 남기는 이유(D-16)를 화면도 따른다 | ✓ |
| 아예 안 보인다 | 깔끔하나 보너스 주사위의 효과가 화면에서 사라짐 | |
| 접어 두고 펼치면 보인다 | 조용하나 검산이 한 번 더 멀어진다 | |

### 다시 굴림이 일어난 판정은 어떻게 보여줄까요?

| 선택지 | 설명 | 선택 |
|--------|------|------|
| 「처음 굴림 / 다시 굴림」으로 나눈다 | 굴림마다 줄을 나누고 합계는 마지막 줄에만 | ✓ |
| 한 줄에 이어 붙이되 앞 눈은 흐리게 | 일관되나 「안 골린 눈」과 「앞서 굴린 눈」이 섞여 보임 | |
| 마지막 굴림만 보인다 | 간단하나 「한 번 더 굴렸다」는 사실이 사라짐 | |

**Notes:** 두 룰북 다 다시 굴림이 「이어 붙이기」임을 코드에서 확인 — 2d6에서도 화면 합계가 틀려진다. 다만 `reroll_2d6`/`push_d100`이 아직 시험에서만 불려 지금은 드러나지 않는다.

### 굴림 연출은 어디까지 보여줄까요?

| 선택지 | 설명 | 선택 |
|--------|------|------|
| 전부 굴리고 안 골린 것이 가라앉는다 | 「이득을 받았다」가 그 순간 눈으로 보인다 | ✓ |
| 쓰일 눈만 굴린다 | 연출은 간단하나 이득을 받은 느낌이 없다 | |
| 연출은 이번에 안 건드린다 | 작지만 연출과 검산 줄이 다른 이야기를 하게 된다 | |

### 이 단계가 끝났다는 것을 어떻게 확인할까요?

| 선택지 | 설명 | 선택 |
|--------|------|------|
| d100 룰북으로 브라우저에서 한 번 굴려본다 | 이 단계가 고치려는 바로 그 상황을 사람이 눈으로 확인 | ✓ |
| 시험 통과로 충분하다 | 빠르나 「사람이 따라갈 수 있는가」는 기계가 판단 못 한다 | |
| 두 룰북을 나란히 비교해본다 | 더 확실하나 준비가 더 든다 | |
