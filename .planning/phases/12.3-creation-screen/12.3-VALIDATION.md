# Phase 12.3 — Validation Strategy

> 이 단계의 검증 계약. **실행 뒤에 재구성한 문서다**(상태 B) — 계획 시점에
> 세워진 것이 아니라, 계획 14건·SUMMARY 14건·UAT 9회차 기록을 되짚어

## Manual-Only Verifications

**이 절이 이 문서에서 가장 중요하다.** 이 단계의 가장 비싼 결함 둘이
「시험이 없어서」가 아니라 **「시험이 원리적으로 닿을 수 없어서」** 살아남았다.

| Behavior | Requirement | Why Manual | Test Instructions |
|----------|-------------|------------|-------------------|
| **AI 호출의 실제 지연과 응답 길이** | CHAR-06 / D-02 | **가짜 제공자는 즉시·짧게 답한다.** 시간 제한에 닿는 경로도, 토큰 상한에 닿는 경로도 시험에서 한 번도 실행되지 않는다. 그래서 5초 제한(실측 12~30초)과 512토큰 상한(모델이 생각에 다 씀)이 **다섯 라운드의 검증을 통과했다.** 지금 있는 시험은 「상수가 되돌아가지 않았나」만 지킨다 — 값이 **옳은가**는 못 본다 | 실제 제공자로 되묻기를 4회 부르고 응답 시간을 잰다(`CREATION_GM_TIMEOUT_S`의 절반을 넘으면 제한을 올린다). 모델을 바꿀 때마다 다시 잰다 |
| **주사위 만들기 연출(D-07)** | CHAR-06 | `roll_to_fill`은 **케언·오픈퀘스트에만** 있는데, 화면이 룰북을 `dungeonworld_like`로 못 박아 둔다(`CreationScreen.tsx`의 `DEFAULT_RULEBOOK_ID`). **화면으로 실행할 방법이 없어 사람 눈으로 확인된 적이 없다.** 서버는 세 룰북을 전부 받는다 — 못 고르는 것은 화면 쪽 사정이다 | 방 설정 화면(UAT의 Deferred Follow-Ups)이 서면, 케언으로 세션을 열어 능력치 3d6·Hit Protection 1d6이 판정 화면과 같은 연출로 뜨는지 본다 |
| **화면 지역 상태 전이** | D-09 / D-13 / D-14 | 이 저장소에 React Testing Library가 없다. 자동 스크롤(G-12.3-8), 기다림 표시(G-12.3-9), 「동의함」 잠금(G-12.3-17), 초안 보존(G-12.3-18), 방장 전용 단추(G-12.3-16)가 전부 JSX 지역 상태라 순수 함수로 못 뽑힌다. 순수 함수로 뽑을 수 있는 판정은 이미 `creationView.ts`로 옮겨 시험한다 | UAT 절차대로 브라우저 셋으로 걷는다. RTL을 들이면 이 줄들이 자동으로 넘어온다 |
| **평문 http + 일반 IP에서 화면이 뜬다** | CHAR-06 | 유닛/통합 시험은 서버를 직접 부르고 브라우저를 안 띄운다. 참가자 넷 전원이 빈 화면을 본 사고(G-12.3-1)가 이 자리에서 났다 | **자동화됨** — `scripts/check_insecure_origin.py`가 매번 돈다. 종료 코드 `2`(확인 불가)를 통과로 접지 않는다 |
| **되묻기가 실제로 좋은 질문인가** | D-05 | 「갈고리가 두어 개 나왔나」는 사람의 판단이다. 코드는 횟수 상한(4)만 지킨다 | 실험 당일 사람이 읽는다 |
