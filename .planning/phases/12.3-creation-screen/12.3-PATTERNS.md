## Pattern Assignments

### `src/gptrpg/event_log/schema.py` (model, event-driven)

**Analog:** 같은 파일의 판 9 추가분 (`PartySizeFixed`, `CreationStepCompleted`, `CreationInterjection`, `CharacterCreated`, `PartyRosterLocked`, 525-599행)

**사건 dataclass 패턴** (`schema.py:525-548`):
```python
class PartySizeFixed(EventEnvelope):
    """방을 여는 사람이 이 세션의 인원을 확정했다(D-01, 판 9).
    ...
    """

    event_type: Literal["party_size_fixed"]
    player_character_count: int
    rulebook_id: str
    rulebook_min: int
    rulebook_max: int | None = None
```
→ GM 말 4종(`CreationAnnounced`/`CreationSpeakerNominated`/`CreationFollowUpAsked`/`CreationWrappedUp` 등, 이름은 계획 재량)과 동의 사건도 이 모양 — `EventEnvelope` 상속 + `event_type: Literal[...]` + docstring에 "판 11"과 왜 이 칸이 필요한지 적는다.

**GameEvent 유니온에 등록** — `schema.py`의 `GameEvent = Annotated[Union[..., PartyRosterLocked], ...]` 목록 끝에 새 타입들을 추가해야 pydantic이 판별한다(누락하면 조용히 파싱 실패).

**부수효과 없는 최소 사건 형태** (`CreationInterjection`, `schema.py:565-580`):
```python
class CreationInterjection(EventEnvelope):
    """...어느 캐릭터의 구조화된 데이터도 바꾸지 않는다..."""
    event_type: Literal["creation_interjection"]
    speaker_character_id: str
    browser_id: str
    during_character_id: str
    mentioned_character_ids: tuple[str, ...] = ()
    text: str
```
→ GM의 안내/지목/되묻기/정리 말은 캐릭터 데이터를 안 바꾸므로 이 형태(최소 페이로드 + `last_seq`만 갱신)를 따르면 된다.

**규율:** `EVENT_SCHEMA_VERSION = 10`(`schema.py:19`)을 11로 올리는 것을 **같은 커밋**에서 한다(D-02가 명시).

### `src/gptrpg/rules_core/reducer.py` (service, event-driven)

**Analog:** 같은 파일 자기 자신 — `GameState`의 만들기 칸 넷(150-169행) + `apply_event`의 만들기 분기(397-467행)

**GameState 새 칸 패턴** (`reducer.py:150-169`):
```python
party_size_fixed: int | None = None
"""이 세션의 확정 인원(판 9+, D-01, Phase 12.1). ... `None`은 「아직 인원이
확정되지 않았다」다 — 사건에서 다시 접은 값이라 서버 재시작에도 살아남는다."""
creation_step_values: dict[tuple[str, str], CreationStepFold] = field(default_factory=dict)
...
```
→ GM 말 기록·동의 기록·방장(host) 칸도 이 방식(`None` = 아직 없음, 사건에서만 채워짐, docstring에 판 번호와 근거 결정 번호 명시)으로 추가한다.

**apply_event 분기 패턴 — 최소 갱신** (`reducer.py:429-434`, `creation_interjection` 분기):
```python
if event_type == "creation_interjection":
    # 끼어든 말(판 9, D-09)은 어느 캐릭터의 구조화된 데이터도 바꾸지
    # 않는다 ... **그래도 분기가 있어야 한다** — 없으면 이 종류가
    # 하나라도 있는 세션이 폴링마다 UnknownEventType을 맞고 영구히
    # 안 열린다.
    return replace(state, last_seq=seq)
```
→ GM의 안내/지목/되묻기/정리 사건 분기는 대부분 이 최소형(last_seq만 갱신 + 대화 기록에 얹기)이면 충분. **분기 없이 넘어가면 `UnknownEventType`으로 세션이 영구히 안 열린다** — reducer.py 244~282행에 이 사고가 세 번 주석으로 남아 있다.

**동의는 덮어쓰기 방식** — `creation_step_completed` 분기(`reducer.py:404-426`)가 `(character_id, step_id)` 키를 덮어쓰는 것과 같은 방식으로 `character_id -> consented: bool` 딕셔너리를 만들면 D-03("누가 아직 안 눌렀는지 이름까지")을 그대로 만족한다.

### `src/gptrpg/web/routes_creation.py` (route, request-response → event-driven)

**Analog (기록을 남기는 POST 경로):** `record_interjection` (`routes_creation.py:356행` 부근) — `actor.submit`으로 사건 하나를 기록하고 `SeqResponse`를 돌려주는 이미 존재하는 패턴. `announce_creation`/`nominate_creation_speaker`/`creation_follow_up`/`wrap_up_creation` 넷은 지금 이 호출이 없다(D-02가 채우는 구멍).

**현재 구조(고칠 대상) — `announce_creation`** (`routes_creation.py:512-538`):
```python
@router.post("/sessions/{session_id}/creation/announce", response_model=AnnounceCreationResponse)
async def announce_creation(
    session_id: str, body: AnnounceCreationRequest, request: Request
) -> AnnounceCreationResponse:
    actor = request.app.state.registry.get_or_create(session_id)
    if actor.state.party_roster is not None:
        raise HTTPException(status_code=409, detail="파티 명단이 이미 잠겼다")
    ...
    message = await asyncio.to_thread(announce_requirements, rulebook, provider, model)
    return AnnounceCreationResponse(message=message)
```
→ 사건화하려면 `message`를 얻은 뒤 `actor.submit(CreationAnnounced(...))` 한 줄을 추가하고 반환값에 `seq`를 실어야 폴링과 이어진다(D-02). `AGENT_RESOLUTION_ERRORS`(503)와 `CreationGmContractViolation`(폴백, 200) 두 예외 계층은 그대로 유지 — D-13이 이 구분을 화면에서도 그대로 쓴다.

**503 vs 폴백 200 vs 409 세 계층 패턴** (`routes_creation.py:512-608` 전역에서 반복):
```python
try:
    provider, model = _resolve_creation_gm_provider(request)
except _AGENT_RESOLUTION_ERRORS as exc:
    raise HTTPException(status_code=503, detail=str(exc)) from exc
...
try:
    nomination = await asyncio.to_thread(nominate_speaker, ...)
except CreationGmContractViolation as exc:
    print(f"경고: ...", file=sys.stderr)
    # 폴백 값으로 200 반환 — 500을 내지 않는다(ARCH-05)
```
→ D-13의 근거 코드 그 자체. 화면 쪽 세 가지 문구(D-13 ①②③)는 이 세 갈래(200 폴백 / 503 / 네트워크 끊김)에 정확히 대응시킨다.

**D-04가 응답에 실을 계산은 이미 여기 있다:**
- `_unfinished_candidates` (`routes_creation.py:424`)
- `_required_steps_filled` (`routes_creation.py:462`)
→ `routes_events.py`의 `poll_events`가 이 두 함수를 그대로 호출해 `GameStateView`에 채우면 된다(새 계산 로직 불필요).

**신원 대조가 맨 앞에 오는 패턴** (`creation_follow_up`, `routes_creation.py:607`부근):
```python
identity = read_identity(request, session_id)
if identity is not None and identity.character_id != body.character_id:
    print("경고: 신원 검증 실패 — creation/follow-up 거부(쿠키 불일치)", file=sys.stderr)
    raise HTTPException(status_code=403, detail="캐릭터를 다시 선택해 주세요")
```
→ 동의 사건화(`/creation/consent`)에 그대로 적용 가능한 신원 대조 순서.

export async function selectCharacter(sessionId: string, characterId: string): Promise<unknown> {
