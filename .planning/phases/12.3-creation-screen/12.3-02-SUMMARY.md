## Decisions Made

- **follow_up 사건 유예 (계획 명시):** `needs_more=False`일 때 사건을 안 남긴다 — `RecordGmSpoke`가 빈 `say`를 거절하기도 하고, 대화 줄기에 남길 GM의 말 자체가 없다(D-02 ④). `CreationFollowUpResponse.seq`만 `int | None`이고 나머지 둘의 `seq`는 항상 `int`다.
- **`creation_state` 모듈째 import (실행 중 판단):** `routes_creation.py`가 `from gptrpg.web import creation_state`로 모듈을 통째로 들여온다 — `creation_follow_up` 함수 안에서 지역 변수 `required_steps_filled`가 같은 이름의 함수 import와 겹쳐 `UnboundLocalError`가 나기 때문이다. 개별 함수 import 대신 모듈 참조로 이 충돌을 피했다.
- **wrap_up dedupe-hit intros 재조립 (계획 원문 그대로):** 두 번째 호출부터는 `_fallback_intro_for`로 다시 계산한다 — 첫 호출의 실제 AI 산출 문장은 사건 로그(`character_created.one_line_intro`)에만 남고 `GameState`에는 없어, 재조회 없이 다시 조립하는 계획 원문의 방식을 그대로 따랐다. 두 번째 호출부터 `CreateCharacter` 재제출도 건너뛰므로 저장된 값 자체는 안 바뀐다.
- **`creation_reopened_step_ids`/`creation_step_values` 타입 (계획 문서 해석):** bullet 목록의 `list[str]` 표기보다 뒤 문장과 `artifacts_produced` 절이 명시한 `CreationReopenedStepView`/`CreationStepValueView` 목록을 실제 구현으로 채택했다.
