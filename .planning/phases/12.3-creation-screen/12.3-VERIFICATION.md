- `src/gptrpg/web/routes_creation.py:270-277,306-308`: 서버는 `FixPartySizeRequest.browser_id`
  (기본값 `""`)와 `actor.state.creation_host_browser_id`를 비교해, 방장이 이미 정해졌는데
  값이 다르면(`host != body.browser_id`) 403을 낸다.
- `frontend/src/screens/CreationScreen.tsx:215-248`: 방장 재실 비콘(`claimCreationHost`)이
  컴포넌트 마운트 즉시(그리고 `HOST_BEACON_MS`마다) 자동으로 부른다 — 사용자가 아무것도
  안 눌러도 방장이 곧바로 정해진다.
- **결과:** 사용자가 인원 확정 버튼을 누르는 시점에는 이미 방장이 정해져 있고, 그 요청은
  `browser_id: ""`으로 나가므로 **자기 자신에게도** 403이 돌아온다.

**라이브 재현 (`/browse`로 직접 확인):**

```
GET /?session=qa-verify-3 → 200, "캐릭터 만들기 / 이번 판 인원을 정해요"
POST /api/sessions/qa-verify-3/creation/host → 200 (자동 비콘, 방장 확정)
[사용자가 "인원 확정" 클릭]
POST /api/sessions/qa-verify-3/creation/party-size → 403
화면 텍스트: "...인원 확정방장만 인원을 정할 수 있어요"
```
`qa-verify-2`에서도 동일하게 재현됐다(재현율 2/2).

**왜 아무 시험도 이걸 못 잡았나:** `tests/test_creation_consent_host.py`의
`test_host_browser_can_fix_party_size`는 서버 엔드포인트를 **직접 HTTP로**
`browser_id="browser-a"`를 실어 호출한다 — 정확한 값을 보내므로 통과한다. 이
저장소는 RTL(React Testing Library)을 쓰지 않고 순수 함수만 단위 시험하므로,
**화면이 실제로 그 값을 채워 보내는지**는 어느 시험도 검증하지 않는다. 12.3-REVIEW.md의
CR-01이 정확히 같은 유형의 배선 누락(`nominateCreationSpeaker` 미호출)을 지적하고
고쳤지만, 같은 유형의 문제가 `fixPartySize`에도 있었고 이번에는 아무도 못 봤다.
