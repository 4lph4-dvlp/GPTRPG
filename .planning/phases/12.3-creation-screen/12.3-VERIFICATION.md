## 결론 먼저

**6차 검증이 BLOCKER로 남긴 secure-context 결함은 진짜로 닫혔다.** `frontend/src/session/browserIdentity.ts`의 `getBrowserId`가 이제 `crypto.randomUUID()`(secure context 전용) 대신 `crypto.getRandomValues` 기반 `newOpaqueId()`를 부른다 — 갈래를 더한 것이 아니라 호출 자체를 갈아 끼웠다(환경별로 도는 줄이 새로 안 생긴다). `frontend/src/main.tsx`가 `<App/>`을 `Notices.tsx`의 `ErrorBoundary`로 감쌌다.

**이번 검증이 이 두 성질을 SUMMARY 서술에 기대지 않고 직접 재현했다.**

1. `.venv/bin/python scripts/check_insecure_origin.py`를 지금 소스로 돌려 `exit=0`을 확인했다. `--host 127.0.0.1`을 주면 `exit=2`(확인 불가, 통과 아님)로 스스로 거절하는 것도 확인했다.
2. `frontend/src/App.tsx`(작업 트리가 깨끗함을 먼저 `git status`로 확인)의 `App` 함수 첫 줄에 예외를 직접 넣고(`npx vite build` — `tsc`가 아래 코드의 도달 불가 경고로 실패하는 것은 12.3-11-SUMMARY.md가 이미 기록한 것과 같은 이유이므로 같은 우회를 재현) `check_insecure_origin.py --skip-build`를 돌려, `#app` 안에 `화면을 여는 중에 문제가 생겼어요`와 임시 예외 문장이 실제로 렌더되는 것을 확인했다(빈 화면이 아니었다). 곧바로 `git checkout`으로 되돌리고 `npm run build`(tsc 포함) 정식 경로로 재빌드해 `exit=0`을 재확인했다.

오케스트레이터가 별도로 독립 재실행한 결과(수정 전 소스로 되돌려 `crypto.randomUUID is not a function`과 새 한국어 오류 경계 문구가 함께 뜨는 것 확인, 수정 후 exit=0, `--host 127.0.0.1`이 exit=2)도 이 결론과 일치한다.

**그런데 코드 수준의 수리와 phase 목표 달성은 다른 층위다.** 이 결함이 정확히 막고 있던 것은 「참가자가 자기 기기로 화면을 볼 수 있는가」였다 — 그리고 그 뒤로 이어지는 「안내 → 값 확정 → GM 정리 → 동의 → 점유」 여덟 단계 전체를 화면 조작만으로 실제 기기에서 걸어 보는 것은 `12.3-UAT.md` 테스트 2~8이 여전히 `blocked`로 남겨 둔 채다. 12.3-11은 그 막힘의 **전제**를 풀었을 뿐 — 여덟 단계 자체를 자동으로 걸은 적은 없다. 이 확인은 코드 검증으로 대신할 수 없다(D-06/D-07/D-08/D-13이 실제로 사람 눈에 어떻게 보이는가, 동의 교차 전파가 다른 탭에 실제로 반영되는가는 시각적·상호작용적 판단이다).

**CHAR-06은 이번에도 완료로 표시하지 않는다.** `REQUIREMENTS.md:117`과 `:359`가 여전히 의도적으로 미체크(`- [ ]` / `Pending`)로 남아 있고, 이 검증도 그 판단을 유지한다 — 자동 증거는 「화면이 뜬다」까지만 증명하고, CHAR-06과 phase 목표 문장이 요구하는 「처음부터 끝까지」는 사람이 실제 기기로 걸어야 확정된다. 이 phase는 이제 **코드 결함 없이 사람 확인만 남은 상태**다 — 6차와는 질적으로 다른 위치다.
