## 일곱 가지 조작의 입력 모양

> **논의 중 확인한 사실:** 세 룰북이 실제로 쓰는 방식은 다섯이다 — `free_text` ·

> `pick_many`·`place_fixed_values`는 아무 룰북도 안 쓴다.

### 링크를 열었을 때 화면이 무엇으로 갈리나?

| 선택지 | 설명 | 선택 |

| 항상 만들기부터 | 단순하다. 대신 다 만든 사람이 재접속할 때 쓸데없는 화면을 한 번 거친다 | |
| 사람이 고른다 | 두 문을 보여준다. 대신 자기가 어느 쪽인지 모르는 사람이 틀린 문을 누른다 | |

### 이번 판의 인원은 누가 정하나?

| 선택지 | 설명 | 선택 |
|--------|------|------|
| 먼저 정한 사람이 임자 (추천) | Phase 8의 「먼저 잡은 사람이 임자」와 같은 결이고, 새 권한 개념을 안 만든다 | |
| 방장을 정한다 | 첫 접속자를 방장으로 둔다. 대신 「방장」이라는 새 권한 개념이 생긴다 | ✓ |
| 링크에 담아 둔다 | 깔끔하지만 방 만드는 화면이 이 단계 밖이다 | |

**사장님의 선택:** 방장을 정한다 → 이어서 **「방을 만든사람이 방장이」**

**후속 논의 (자유 서술):** 이 프로젝트에 방을 만드는 화면이 아직 없다는 사실
(세션은 링크 식별자로 저절로 생기고, 서버가 「누가 만들었나」를 기록한 적이 없다)을
알리고 두 갈래를 제시했다 — **(가)** 가장 먼저 들어온 사람을 방을 만든 사람으로 본다,
**(나)** 이 단계에서 링크 만드는 화면을 함께 만든다(범위 확장). 방장 이탈 처리도 함께
물었다.

**사장님의 답:** *"(가)로 가고, 방장이 나가면 다음 사람에게 넘긴다"*
**메모:** 추천안(먼저 정한 사람이 임자)을 물리고 방장을 새로 만들기로 한 결정이다.
방 만들기 화면이 생기면 방장 정의를 「링크를 만든 사람」으로 바꾼다. → CONTEXT D-11

## GM이 실패했을 때 화면

> **논의 전 확인한 사실:** 서버는 AI가 계약을 어기면 조용히 물러난다 — 되묻기는 「안
> 물음」, 지목은 「후보 첫 번째」, 정리는 「미리 만들어 둔 한 줄 소개」. 오류가 아니라
> 정상 응답(200)으로 나가므로 화면은 실패를 알 방법이 없다.

### GM 호출이 실패해 서버가 물러났을 때 사람에게 알리나?

| 선택지 | 설명 | 선택 |
|--------|------|------|

| 조용히 넘긴다 | 폴백이 자연스러우니 티 낼 필요 없다는 판단. 대신 GM이 이상하게 굴 때 이유를 알 수 없다 | |
| 다시 시도 버튼까지 | 친절하다. 대신 이미 폴백 값으로 진행된 뒤라 되돌리는 규칙을 새로 정해야 한다 | |
