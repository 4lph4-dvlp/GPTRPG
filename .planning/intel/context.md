# 맥락 (Context)

DOC로 분류된 문서 1건(`docs/GPTRPG-cost-analysis.md`)의 내용과, 잠금된 ADR이 **결정이 아니라고 명시한 미결·실측 대기 항목**을 주제별로 모았다.

> ⚠️ `docs/GPTRPG-cost-analysis.md`는 스스로 **참고용 분석**이며 "이 절은 결정의 출처가 아니다 … 권위는 `GPTRPG-M0-decisions.md`에 있다"고 적는다(§7). 아래 수치는 결정이 아니라 근거 자료다. 문서 스스로 "절대값이 아니라 구조와 비율을 참고할 것"을 요구한다.

## 원가 — 계산 전제

- source: docs/GPTRPG-cost-analysis.md §1
- 파티 규모 4인 / 세션 길이 3시간(상한 케이스) / 파티 전체 턴 수 약 80턴 / 턴당 LLM 호출 평균 1.5회 / 프롬프트 캐싱 적극 사용.
- 턴당 프롬프트 구성 = 시스템 프롬프트(GM 페르소나) ~2,000[영구 캐시] + 룰북 요약 ~3,000[영구 캐시] + 전선 상태 ~1,000[세션 캐시] + 엔티티 장부(관련분만) ~2,000[세션 캐시] + **최근 대화 20턴 ~6,000**[증분 캐시] + 이번 턴 결과 패킷 ~500[신규] = 입력 약 14,500 / 출력 약 800.
- ⚠️ 이 표의 「최근 대화 20턴」은 D31이 확정한 「최근 대화 몇 턴, 초기값 10턴」과 어긋난다. `INGEST-CONFLICTS.md` WARNING 참조.

## 원가 — 기준 수치

- source: docs/GPTRPG-cost-analysis.md §2 · docs/GPTRPG-design-plan.md §9.1
- 프론티어 단가 $5/$25 per MTok(입력/출력), 경량급 $1/$5 가정.
- 턴 합계 ≈ $0.039. 파티 3시간 세션(4인) 80턴 × $0.039 × 1.15(부대비용) ≈ $3.6. 1인당 3시간 ≈ $0.90.
- **1인 1시간당** — 프론티어 ≈ $0.30 / 중형 이원화 ≈ $0.20 / 저가 모델 $0.03~0.10 / 자체 호스팅 $0.07(이용률 30% 기준).

## 원가 — 발견 1: 솔로가 파티보다 7~8배 비싸다

- source: docs/GPTRPG-cost-analysis.md §3
- LLM 호출은 턴 수에 비례하지 사람 수에 비례하지 않는다. 4인 파티는 80턴 $3.6 → 1인당 $0.90, 솔로는 130~150턴 $6.0 → 1인당 $6.00.
- 파티는 한 사람이 입력하는 동안 나머지 3명이 같은 서사를 읽으므로 원가가 4분의 1로 나뉜다. 솔로는 안 나뉘고 대기 시간이 없어 턴이 더 많다.
- 함의 — M1(실시간 파티)이 원가 구조상 가장 유리하다(현재 로드맵 순서가 맞다) / M2(솔로 모드)는 별도 가격 정책이 필요하다 / **관전자는 원가가 0**이므로 스트리머 노출 전략은 원가 측면에서 공짜다.

## 원가 — 발견 2: 캐싱이 지배 변수다

- source: docs/GPTRPG-cost-analysis.md §4
- 캐싱 잘 설계 시 1인 1시간당 $0.30, 캐싱 없음 $1.10 (**3.7배**).
- 캐싱은 접두 일치(prefix match) 방식이라 프롬프트 앞부분이 1바이트라도 바뀌면 뒤쪽 전체가 무효화된다. 나중에 최적화할 항목이 아니라 처음부터 프롬프트 조립 구조를 그렇게 짜야 하는 항목이다.
- M0에서 확정할 규칙 3개 — ① 시스템 프롬프트를 동결한다(현재 시각·플레이어 이름 같은 동적 값을 넣으면 매 턴 전체 캐시가 깨짐, 동적 정보는 메시지 뒤쪽에) ② 프롬프트 조립 순서 = 안정성 순서(영구 고정 → 세션 고정 → 턴마다 변함) ③ 엔티티 장부를 결정론적으로 직렬화한다(딕셔너리 순서가 흔들리면 캐시가 깨짐).

## 원가 — 두 에이전트의 요구가 다르다

- source: docs/GPTRPG-cost-analysis.md §5.1
- `action_classifier` — 닫힌 집합 분류 + JSON, 난이도 낮음, 검증 객관적 가능(골든셋 정답률), 저가 모델 적합도 매우 높음, 원가 비중 약 5%.
- `master_gm` — 한국어 창작 서사·페르소나 유지·장기 일관성, 난이도 높음, 검증 주관적, 저가 모델 위험(실측 필요), 원가 비중 약 95%.
- 비용 절감의 실질은 전부 `master_gm`에 달려 있으나 여기가 제품의 재미 그 자체다.

## 원가 — 대체 모델 후보군

- source: docs/GPTRPG-cost-analysis.md §5.2
- 단가는 변동이 심하므로 배수로만 기재하며 도입 시점에 재확인 필수.
- 중국계 오픈/저가 API(Qwen·GLM·DeepSeek 계열) 프론티어 대비 대략 1/10~1/50, 한국어 서사 리스크 중간~높음 / NVIDIA NIM·Nemotron 계열 1/5~1/20, 한국어 상대적 약세 / 한국어 특화 모델(국내 벤더) 1/3~1/10, 한국어 리스크 낮으나 장문 일관성·지시 따르기가 약할 수 있음 / 자체 호스팅 오픈웨이트 70B~120B급.
- **한국어가 이 제품의 특수 변수다.** 대부분의 벤치마크가 영어 기준이라 참고가 안 된다.

## 원가 — 자체 호스팅과 이용률 함정

- source: docs/GPTRPG-cost-analysis.md §5.3
- 이론값(이용률 100%): 70B급 GPU 2장, 클라우드 GPU 시간당 $3~5, vLLM 배칭 시 30~80 파티 수용 → 파티당 $0.08 → 1인 1시간당 ≈ $0.02(프론티어 대비 약 15배 저렴해 보임).
- **함정:** TRPG는 이용률 패턴이 최악이다(저녁 8시~자정 집중). 현실적 추정 이용률 25~30% → 실효 $0.07. 초기(유저 적음) 5~10% → $0.20~0.40.
- 즉 자체 호스팅은 규모가 붙기 전까지 API보다 비싸거나 비슷하며, API에는 이용률 리스크가 아예 없다(안 쓰면 0원).
- 숫자에 안 잡히는 비용 — vLLM/추론 서버 운영·모니터링·장애 대응(사실상 인력 1명), 모델 업데이트마다 재검증, 피크 초과 시 큐잉으로 인한 체감 지연, GPU 조달 리드타임.

## 원가 — 전략별 종합 비교와 권고

- source: docs/GPTRPG-cost-analysis.md §5.4 · §5.5
- 프론티어 API 단독 $0.30 · 품질 리스크 없음 · **M0(품질 상한 측정)** / 프론티어 + 중형 이원화 $0.20 · M1~M2 / 저가 API(classifier만 교체) $0.29 · 리스크 거의 없음 · **M0에서 바로 가능** / 저가 API(GM까지 교체) $0.03~0.10 · 리스크 높음 · M2 이후 실측 통과 시 / 자체 호스팅 $0.07 · 운영 부담 높음 · 기저 부하가 생긴 뒤.
- 권고 5개 — ① M0에서 프로바이더 추상화 계층을 넣는다(지금은 공짜, 나중은 재작성) ② M0은 프론티어로 품질 상한을 잰다 ③ `action_classifier`는 M0에서 바로 저가 모델로 A/B(골든셋 정답률로 객관 비교) ④ `master_gm` 하향은 GM 품질 검증 방법론 완성 후에만 ⑤ 자체 호스팅은 M0의 결정 사항이 아니다.

## 수익 — 유저 유형별 월 원가

- source: docs/GPTRPG-cost-analysis.md §6.1
- 라이트(주 2시간 = 월 8시간) 프론티어 $2.4 / 이원화 $1.6 / 저가 $0.4. 미들(월 20시간) $6.0 / $4.0 / $1.0. 헤비(월 40시간) $12.0 / $8.0 / $2.0. **솔로 헤비(월 20시간) $40 / $27 / $7.**
- 월 9,900원(~$7) 기준으로 프론티어 단독일 때 파티 헤비 유저가 손익분기 근처이고 솔로 헤비는 확실한 적자다. **모델 선택이 곧 가격 정책의 자유도다.**

## 수익 — 무료 티어 원가

- source: docs/GPTRPG-cost-analysis.md §6.3
- 신규 파티 1,000팀에 1세션(3시간) 무료 제공 시 — 프론티어 $3,600 / 이원화 $2,400 / 저가 모델 $600.
- 문서 자체가 정정을 달아 둔다: 무료 단위는 D21에서 **"첫 에피소드"(위협 시계 1~2칸)**로 확정됐으며, 위 계산은 세션 하나 기준이었고 "첫 캠페인"은 시계 하나(4~6칸 / 8~15시간)를 통째로 주는 안이어서 원가가 4~5배 차이 난다.
- 무료 단위별 원가(D21 표) — 첫 에피소드(1~2칸) 2~5시간 파티 1팀 프론티어 $2.5~6 / 저가 $0.5~1.2, 1,000팀이면 $2,500~6,000. 첫 캠페인(4칸 전체) 8~12시간 $10~15 / $2~3, 1,000팀이면 $10,000~15,000.

## 수익 — 코스메틱과 UGC 마켓

- source: docs/GPTRPG-cost-analysis.md §6.4 · §6.5
- **서사 로그 테마가 과소평가되어 있다.** 이 제품은 화면의 대부분이 텍스트이며 폰트·색조·말풍선 프레임·주사위 결과 연출 스타일이 유저가 가장 오래 보는 화면이다. 주사위보다 노출 시간이 길다.
- **캠페인 기념품은 감정 가치가 가장 높은 상품이다.** 모먼트 연대기를 프리미엄 상품화할 수 있고 물리 인쇄 책자로 확장하면 객단가가 크게 올라간다.
- 말/토큰 스킨은 M0~M3에 팔 자리가 없다 — 던전월드에 그리드가 없어 좌표계 자체가 없고 토큰을 놓을 보드가 존재하지 않는다(M4).
- UGC 마켓(마인크래프트 마켓플레이스 모델)은 장기적으로 코스메틱보다 클 수 있다. 자동화율 표시가 여기서 품질 신호로 작동한다.

## 레이턴시 실측 기준

- source: docs/GPTRPG-cost-analysis.md §7
- `action_classifier`(경량) 0.2~0.5초 / 플레이어 확인 사람 시간 / 주사위 + 판정(순수 코드) ~0ms / `master_gm` 첫 토큰(프론티어) 1~2초 / 완결까지 5~10초.

## 미결 — 법무로 넘긴 것

- source: docs/GPTRPG-M0-decisions.md §2 D29 · §6 · docs/GPTRPG-design-plan.md §13.1
- ⚠️ 문서 스스로 "법적 결론이 아니다"라고 못박은 영역이다.
- 1. **AI 실시간 생성 콘텐츠의 게임물 등급 분류** — 사전 심의가 구조적으로 불가능한 서비스. 시급도 **높음, 출시 전 필수.**
- 2. **AI 생성물의 권리 귀속을 약관으로 어떻게 설계할 것인가** — 시급도 **높음, 수익 모델의 전제.**
- 3. 플랫폼 책임 제한 요건 충족 방법(신고·삭제 절차의 법적 요건) — 높음, 유저 업로드 개시 전.
- 4. CC-BY 고지문의 구체적 문구와 게재 위치 — 중간, 출시 전.
- 5. 낯선 사람 매칭 시 성인 인증 의무 — 낮음(D24로 M2 이후). 다만 서비스 자체의 등급 분류는 여전히 확인 필요.
- 6. **해외 서비스 시 각국 요건** — 중간. 초기 타깃 정의에 "국내 그리고 국외"가 포함되어 있으므로 빠뜨리지 말 것.

## 타깃 유저와 제품 전제

- source: docs/GPTRPG-M0-decisions.md §1 · docs/GPTRPG-design-plan.md §1
- 타깃 = TRPG를 잘 모르고 룰북을 읽을 시간도 없지만, 회사·학교가 끝나고 친구들 또는 처음 보는 모험가들과 실시간으로 몰입할 세계를 원하는 사람. 플레이 시간은 고정 세션이 아니라 하고 싶은 만큼.
- 전제 3가지 — ① 플레이어끼리의 대화는 외부 메신저에서 일어난다(플랫폼은 소셜 레이어가 아니며 입력창은 행동 선언용) ② 언제든 끊고 이어할 수 있다 ③ 처음 보는 사람과의 플레이를 전제한다(M2 — 매칭·안전 장치·드롭인/아웃 필수).
- 해결하는 문제 재정의 — 룰북을 읽어야 시작할 수 있다 → 숫자를 서술로 번역 / GM을 할 사람이 없다 → AI가 GM(판정은 코드가) / 언제 다시 모일지 못 정한다 → 세션 개념을 버린다 / 낯선 사람과 하기가 불안하다 → 안전 장치를 기본으로.
- 마케팅(제품 정의 아님) — 스트리머 노출은 채널이며 제품 요구사항을 규정하지 않는다. 관련 요구는 진행 정책 프리셋 하나로 흡수한다.

## 설계 원칙 — 세 개의 층

- source: docs/GPTRPG-M0-decisions.md §0.5 · docs/GPTRPG-design-plan.md §2.1
- ① 플랫폼 기능(룰북과 무관하게 우리가 제공) / ② 표현 어휘(룰북이 말하는 것을 담는 그릇) / ③ 룰북 규칙(룰북 설계자가 정한 것).
- **③을 ①에 올리면 다른 룰북이 망가진다.** 기능을 제안할 때 층을 명시하는 것이 규약이다.
- 원칙 3의 마지막 줄 — **첫 타깃이 던전월드라는 이유로 던전월드의 규칙을 플랫폼에 박지 않는다. 우리는 범용 시스템을 만든다.**
- 원칙 4 — 재방문 동기는 이야기에서 나온다. 성장·보상 시스템을 재방문 유인으로 설계하지 않으며 **성장이 없는 룰북도 정상 지원해야 한다.**

## 마일스톤 로드맵

- source: docs/GPTRPG-M0-decisions.md §3 (권위) · docs/GPTRPG-design-plan.md §11
- **M0** — 타당성 검토 + 아키텍처 결정 + **킬 크리테리아 실험**. 판정 방식 2종(2d6 등급식, d100 롤언더), 위협 시계, 효과 DSL 골격.
- **M1** — 실시간 파티(친구 초대 링크) · d20 판정 방식 · 노드 그래프 · 클루 웹 · 룰북 파일 업로드 · 안전 장치 1~3층.
- **M2** — 공개방 매칭 · 톤 필터 · 신고·차단 · 성인 인증 · 솔로 모드 · 비동기 PbP · 다이스풀/Year Zero 판정 방식 · 테이블 생성.
- **M3** — FATE 판정 방식 · UGC 마켓 본격화.
- **M4** — D&D 5e 어댑터 + 전술 그리드(⑥ 전술적 깊이 · 말·토큰 스킨).
- ⚠️ **M0에는 킬 크리테리아 실험이 포함된다. 설계 종결과 M0 종결은 다르다.** 로드맵 표의 이전 판은 M0을 "타당성 검토 + 아키텍처 결정"까지만 적어 설계가 끝나면 M0이 끝나는 것처럼 읽혔다.
- M2의 솔로·비동기가 "거의 공짜"인 것이 D3 아키텍처를 택하는 이유다.
