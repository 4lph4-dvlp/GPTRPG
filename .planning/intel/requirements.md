# 요구사항 · 수용 기준 (Requirements)

**PRD로 분류된 문서가 이번 수집 세트에 없다.** 아래 항목은 새로 만들어낸 요구사항이 아니라, 잠금된 ADR(`docs/GPTRPG-M0-decisions.md`)과 그 하위 명세서가 **명시적 수용 기준·멈출 조건 형태로 이미 적어 둔 것**을 추출한 것이다. 각 항목의 `source`에 원 위치를 남겼다. 출처가 PRD가 아니라는 사실 자체를 표시로 남긴다.

**M0는 완료가 아니다.** M0는 설계와 킬 크리테리아 실험 두 부분이고 끝난 것은 설계뿐이다. 아래 REQ-h1 ~ REQ-h6은 **아직 실행되지 않은** 실험의 판정 조건이며, REQ-h1과 REQ-h5는 프로젝트를 멈출 수 있는 진짜 킬 조건이다.

---

## REQ-h1-ai-gm-재미

- source: docs/GPTRPG-M0-decisions.md §2 D30 (ADR — PRD 문서 없음) · docs/GPTRPG-design-plan.md §12.1
- description: AI가 GM 노릇을 하면 재미있다. M0 킬 크리테리아 실험의 가장 중요한 가설이며, 등급은 **진짜 킬** — 실패 시 프로젝트를 멈춘다.
- acceptance: 위협 시계 1개로 실제 플레이(1세션 3~4시간 → 1주 간격 → 2세션 3~4시간). 핵심 측정은 **2세션에 몇 명이 왔나**이며 1주 간격이 실험의 핵심이다(시간을 두지 않으면 알 수 없다). 보조 측정 = 세션 완주 / 중간 흐지부지. 멈출 조건 = 참가자 대부분이 "두 번째 세션을 하고 싶지 않다". 제약 = 우리는 GM을 하지 않고 관찰만 한다(개입하면 H1을 못 잰다). 참가자 = TRPG 경험자 2명 + 비경험자 2명.
- scope: AI GM 품질, 재방문, 킬 크리테리아

## REQ-h2-위협시계-봐주기-방지

- source: docs/GPTRPG-M0-decisions.md §2 D30 · §2 D21 (ADR — PRD 문서 없음)
- description: 위협 시계가 AI의 봐주기를 막는다. 등급은 **재설계** — 실패 시 해당 부분만 다시 만든다.
- acceptance: 실패 횟수 대비 시계 진행 횟수를 집계한다(D21 ①의 실패 누적 카운터가 이벤트 로그에 남기므로 사후 자동 집계 가능). 멈출 조건 = 시계는 돌지만 이야기가 억지스럽다.
- scope: 위협 시계 진행 규칙, 관측 지표

## REQ-h3-룰북-데이터-표현

- source: docs/GPTRPG-M0-decisions.md §2 D30 · §2 D32 (ADR — PRD 문서 없음)
- description: 룰북을 데이터로 표현할 수 있다. 등급은 **전략 변경** — 실패 시 유저 콘텐츠 마켓이 소멸한다.
- acceptance: 판정 방식이 다른 룰북 2개(2d6 등급식 / d100 롤언더)를 같은 그릇에 넣는다. D32에 따라 **적 표현도 검증에 포함**한다 — 두 번째 룰북의 적이 같은 그릇에 들어가는지 확인. 멈출 조건 = 두 번째 룰북이 안 들어간다. 이 가설만 플레이 없이 데이터 작성만으로 확인된다.
- scope: 룰북 추상화, 판정 인터페이스, 적 표현

## REQ-h4-자유텍스트-마찰

- source: docs/GPTRPG-M0-decisions.md §2 D30 · §2 D28 (ADR — PRD 문서 없음)
- description: 자유 텍스트 입력이 쓸 만하다. 등급은 **전략 변경** — 실패 시 "말하듯 플레이" 셀링포인트가 소멸한다.
- acceptance: 정답 데이터 300개로 마찰을 측정한다. 목표 = 「첫 제안이 맞음(엔터 한 번)」 + 「첫 제안 틀렸으나 후보에 있음(클릭 한 번)」 합쳐 **95% 이상**. 멈출 조건 = 「후보 어디에도 없음(직접 찾아야 함)」 비율 **30% 이상**. 정답 데이터 조달 = 사용자 실험 세션당 약 80개 → 2세션 합계 약 160개 + 사내 플레이 보충 약 140개 = 300개. 측정할 실패 유형 5종 중 1순위는 판정 필요 여부 오판(양방향).
- scope: 파서 마찰, 정답 데이터, 한국어 입력 특수성

## REQ-h5-원가-사업가능범위

- source: docs/GPTRPG-M0-decisions.md §2 D30 (ADR — PRD 문서 없음) · docs/GPTRPG-design-plan.md §12.1
- description: 원가가 사업 가능 범위 안이다. 등급은 **진짜 킬** — 실패 시 프로젝트를 멈춘다.
- acceptance: 실측(한국어 토큰, 실제 턴 수)으로 확인한다. 멈출 조건 = **1인 1시간당 $1 초과 + 저가 모델로도 안 내려감**(두 조건이 함께 성립할 때). $1 기준 근거 = 월 20시간 유저의 원가가 $20이 되면 어떤 가격 정책도 성립하지 않는다. 측정 항목 = 실제 토큰 소모, 실제 턴 수. 주의 — 참조 원가 수치의 산출 전제에 미해소 불일치가 있다(`INGEST-CONFLICTS.md` WARNING 참조).
- scope: 원가, 사업 타당성, 킬 크리테리아

## REQ-h6-비경험자-진입

- source: docs/GPTRPG-M0-decisions.md §2 D30 (ADR — PRD 문서 없음)
- description: TRPG 비경험자가 룰북 없이 시작할 수 있다. 등급은 **재설계**.
- acceptance: 비경험자에게 캐릭터 만들기 + 30분을 시킨다(실험 준비물 중 캐릭터 절반은 미리 준비하고 절반은 참가자가 직접 만들어 H6 검증에 쓴다). 측정 = 비경험자가 캐릭터를 만들었나. 멈출 조건 = 비경험자 대부분이 캐릭터 만들기에서 포기.
- scope: 온보딩, 진입장벽, 비경험자

## REQ-캐릭터-애착-성공기준

- source: docs/GPTRPG-M0-decisions.md §2 D22 (ADR — PRD 문서 없음) · docs/GPTRPG-design-plan.md §6.2
- description: 캐릭터 만들기가 애착을 만든다. 애착은 투자에서 나오고, 투자가 일어나는 유일한 지점이 캐릭터 만들기다.
- acceptance: 완성 직후 유저가 **"내 캐릭터는 누구다"를 한 문장으로 말할 수 있는가.** 플레이테스트에서 "당신 캐릭터 어떤 사람이에요?"라고 물어 확인한다. 목표 소요 = 던전월드 기준 전 과정 5분. 30초 경로(완성품 집어들기)는 폐기되었으므로 수용 기준에서 제외한다.
- scope: 캐릭터 생성, 애착, 첫 만남 자기소개

## REQ-자동화율-목표

- source: docs/GPTRPG-M0-decisions.md §2 D7 (ADR — PRD 문서 없음) · docs/GPTRPG-design-plan.md §4.6
- description: 룰북을 효과 DSL로 얼마나 자동 처리하는가를 자동화율로 표시한다. 모든 룰북은 플레이 가능하며 다만 자동화율이 다르다.
- acceptance: 목표 = **룰북 100개 중 90개가 자동화율 80% 이상.** 예상 자동화율 — 던전월드 계열 95%+, 크툴루 계열 90%, D&D 5e 클론 70~85%, 섀도우런 클론 50%. 룰북 등록 시 자동 산출해 유저에게 표시한다. 원자 연산 규모 목표 30~50개.
- scope: 효과 DSL, 자동화율, 룰북 표현력

## REQ-응답속도-목표

- source: docs/GPTRPG-M0-decisions.md §2 D33 (ADR — PRD 문서 없음) · docs/GPTRPG-design-plan.md §3.6
- description: 사람이 기다림을 느끼는 두 지점에 각각 응답 속도 목표를 둔다. "전체 3초"는 폐기되었다.
- acceptance: 문장 입력 → 행동 확인 표시 **0.5초**. 확인 → GM 서사 첫 글자 **2초**. 완결까지는 목표 없음. 초과 시 행동 — 첫 글자 5초 초과 시 진행 표시, 15초 타임아웃 시 판정 결과를 먼저 내보내고 서사를 뒤이어 붙인다. 실제 응답 속도는 M0 실측 항목이다.
- scope: 레이턴시, 타임아웃 동작

## REQ-재개-압축품질

- source: docs/GPTRPG-M0-decisions.md §2 D11 (ADR — PRD 문서 없음) · docs/GPTRPG-design-plan.md §7.3
- description: 3주 만에 접속했을 때 이어할 수 있어야 한다. 온라인 TRPG 최대 이탈 원인에 대한 대응이다.
- acceptance: 압축 품질 검증 기준을 **"3주 뒤에 읽고 게임을 이어할 수 있는가"**로 한다(이전 기준인 스키마 준수 + 엔티티 누락 없음을 대체). M0 실험 측정 항목 = 2세션 시작 시 이어할 수 있었나. M0 실험에서 리캡은 손으로 써서 보여줘도 검증된다.
- scope: 재개(리캡), 압축 시스템, 이탈 방지
