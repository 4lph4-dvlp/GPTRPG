# Roadmap: GPTRPG

## Overview

이 로드맵은 **제품을 만드는 로드맵이 아니다.** 마일스톤 0의 나머지 절반인 **킬 크리테리아 실험**을 끝까지 돌려서, 이 프로젝트를 계속할지 여기서 멈출지 답을 내는 것이 전부다.

설계는 2026-07-30에 닫혔다. 실험은 아직 하지 않았다. 실험이 확인할 가설 여섯 개 중 둘(**재미**와 **원가**)은 프로젝트를 멈출 수 있는 조건을 들고 있다.

순서는 이렇다. 먼저 되돌릴 수 없는 결정 하나(사건을 순서대로 기록하는 구조)를 제대로 깔고(Phase 1), 룰북 두 개가 같은 그릇에 들어가는지를 플레이 없이 확인한 뒤(Phase 2), 한 턴이 끝까지 도는 것을 만들고(Phase 3), 네 명이 3~4시간 같이 볼 수 있는 상태로 완성한다(Phase 4). 그리고 실제로 사람 넷을 불러 1주 간격으로 두 번 플레이하고(Phase 5), 나온 숫자로 여섯 가설을 채점한다(Phase 6).

**Phase 6이 게이트다.** 여기를 통과하지 못하면 M1 이후는 없다.

만드는 것은 **제품이 아니라 실험 도구**다. 최소 도구 범위 표가 「안 필요」로 적은 것은 만들지 않는다 — 캐릭터 만들기 화면, 매칭·로비, 코스메틱, 룰북 저작 도구, 리캡 자동 생성, 안전 장치 UI, 결제·계정. 전부 손으로 대체한다.

## Phase Details

### Phase 1: 규칙 코어와 사건 기록

**Goal**: 게임의 진실이 순서대로 쌓인 사건 기록에만 있고, 규칙 계산은 시간을 모르는 순수 코드로만 일어난다
**Depends on**: Nothing (first phase)
**Requirements**: RIG-02, RIG-06
**Success Criteria** (what must be TRUE):

  1. 어떤 시점의 게임 상태든 사건 기록을 처음부터 훑어서 똑같이 다시 만들어낼 수 있다
  2. 주사위를 굴리고 판정 결과가 나오기까지 AI가 끼어드는 지점이 코드 어디에도 없다
  3. 같은 주사위 굴림을 다시 재생하면 같은 결과가 나온다 (굴림 원본이 기록에 남는다)
  4. 규칙 계산 코드에 타이머·접속 상태·현재 시각 같은 개념이 하나도 등장하지 않는다
  5. 한 세션에 대해 상태를 바꿀 수 있는 주체가 하나뿐이라는 것이 코드 구조로 강제된다

>
> **이 단계의 유일한 숙제는 기록에 필드를 빠뜨리지 않는 것이다.**

### Phase 2: 룰북 두 개를 같은 그릇에

**Goal**: 판정 방식이 서로 다른 룰북 두 개와 그 룰북들의 적이, 플랫폼 코드를 고치지 않고 데이터로만 들어간다
**Depends on**: Phase 1
**Requirements**: RIG-08, HYP-03
**Success Criteria** (what must be TRUE):

  1. 2d6 등급식 룰북과 d100 롤언더 룰북이 같은 판정 요청·판정 결과 형태 위에서 돈다
  2. 결과 등급이 코드에 박혀 있지 않다 — 룰북이 자기 등급 집합을 선언하고, 등급이 이름 목록인 경우와 수치 구간인 경우를 둘 다 받는다
  3. 수정치 네 유형(숫자 가감 / 주사위 추가·제거 / 목표값 변경 / 재굴림)이 모두 표현된다
  4. 두 룰북의 적과 NPC가 같은 그릇에 들어간다 — 플랫폼 코드에 체력·피해·태그 같은 룰북 고유 개념이 하나도 없다
  5. 두 번째 룰북을 넣으면서 플랫폼 코드를 고쳐야 했는지 아닌지가 명확히 기록된다

> **이 단계가 「룰북을 데이터로 표현할 수 있다」에 답한다.** 여섯 가설 중 유일하게 플레이 없이 데이터 작성만으로 확인되는 가설이다. 실패하면 유저 콘텐츠 마켓이 소멸하고 사업 규모가 바뀐다 — 프로젝트가 멈추지는 않지만 정체성이 달라진다.
>
> 판정 방식을 M0에 두 개 넣는 이유는, 판정 방향(굴려서 넘기기 vs 굴려서 밑돌기)과 성공 등급 체계가 서로 달라서 **둘이 같은 그릇 위에서 돌면 추상화가 옳다는 강한 증거가 되기 때문**이다. 하나뿐이면 잘못된 추상화를 만들어도 알 수 없다.
>
> **범위선:** 룰북 데이터의 필드 단위 상세 규격과 효과 원자 연산의 최종 목록은 M0이 아니다. 여기서는 목차와 인터페이스가 성립하는지만 본다.

### Phase 3: AI 진행자 한 턴

**Goal**: 플레이어가 자유 문장을 치면 분류 → 확인 → 주사위 → 서사까지 한 턴이 끊기지 않고 끝까지 돈다
**Depends on**: Phase 2
**Requirements**: RIG-01, RIG-03, MEAS-02, MEAS-04
**Success Criteria** (what must be TRUE):

  1. 플레이어가 "문을 부수고 들어간다" 같은 문장을 치면 시스템이 무브와 능력치를 제안하고, 플레이어가 확인해야만 주사위가 굴러간다 (자동 확정하지 않는다)
  2. 서사가 문장 단위로 흘러나오고, 플레이어는 완결을 기다리지 않고 읽기 시작할 수 있다
  3. 응답이 늦어도 게임이 멈추지 않는다 — 첫 글자가 5초를 넘으면 진행 표시가 뜨고, 15초를 넘으면 판정 결과(주사위·성공/실패·시계 변화)가 먼저 나가고 서사가 뒤이어 붙는다
  4. 매 턴 AI에게 넘어가는 것이 네 가지(현재 장면에 등장한 대상 / 내 캐릭터 상태 / 위협 시계 상태 / 최근 대화 10턴)로 고정되어 있고, AI가 저장소 전체를 훑는 경로가 없다
  5. 플레이어가 실제로 친 문장이 시스템의 제안·확인 여부와 함께 남아 그대로 정답 데이터가 된다

**Wave 2 (gap closure)** *(blocked on 03-05 — 같은 파일 두 개를 함께 고친다)*

> **프롬프트 조립 순서가 이 단계의 숨은 요구사항이다.** 캐싱은 앞에서부터 맞춰 보는 방식이라 앞부분이 1바이트라도 바뀌면 뒤가 전부 무효화된다. 조립 순서를 안정성 순서(영구 고정 → 세션 고정 → 턴마다 변함)로 짜고, 시스템 프롬프트에 현재 시각·플레이어 이름 같은 동적 값을 넣지 않는다. **캐싱 유무가 원가를 3.7배 가르므로 이것은 최적화가 아니라 이 단계의 설계 제약이다.**
>
> M0은 최상급 모델 고정이다. 여기서 재는 것은 원가가 아니라 **품질 상한선**이다 — 최상급으로도 재미없으면 거기서 판단이 끝난다. 다만 모델과 제공자는 에이전트별 설정값으로 빼 둔다(지금은 공짜, 나중은 재작성).
>
> **여기서 최소한만 정하고 넘어갈 것:** 에이전트 응답 껍데기와 가벼운/중간 모델의 타임아웃·재시도 규칙. 무거운 모델의 15초는 확정되어 있으나 나머지는 어느 문서에도 유지·폐기 진술이 없다. 실험을 돌릴 수 있는 최소한만 정하고 제품 규격은 M1에서 정한다.
>
> **화면은 만들지만 화면 설계는 하지 않는다.** 화면 배치·컴포넌트·반응형은 M0 범위 밖이다.

### Phase 4: 실험 도구 완성

**Goal**: 네 명이 링크 하나로 3~4시간 같은 세션을 보며 플레이할 수 있고, 여섯 가설에 답할 숫자가 그동안 저절로 쌓인다
**Depends on**: Phase 3
**Requirements**: RIG-04, RIG-05, RIG-07, MEAS-01, MEAS-03
**Success Criteria** (what must be TRUE):

  1. 링크 하나를 받은 네 명이 같은 세션 화면을 동시에 보고, 한 명이 행동하면 나머지 셋의 화면에도 같은 서사가 나타난다
  2. 인터넷이 끊겼다 다시 들어와도 놓친 부분이 이어 붙고 처음부터 다시 시작하지 않는다

  4. 플레이어가 자기 캐릭터 시트를 읽기 전용으로 열어 볼 수 있다
  5. 세션이 끝나면 실제 토큰 소모량·실제 턴 수·판정 실패 횟수 대비 시계 진행 횟수가 사람 손을 거치지 않고 집계되어 나온다

### Phase 6: 가설 판정 게이트

**Goal**: 여섯 가설에 답을 내고, 프로젝트를 계속할지·멈출지·무엇을 바꿀지 정한다
**Depends on**: Phase 5
**Requirements**: HYP-01, HYP-02, HYP-04, HYP-05, HYP-06
**Success Criteria** (what must be TRUE):

  1. **재미** — 2세션 참석 인원과 완주 여부로 답이 나온다. 참가자 대부분이 두 번째 세션을 하고 싶지 않았다면 **프로젝트를 멈춘다**
  2. **원가** — 실측한 한국어 토큰 소모와 실제 턴 수로 1인 1시간당 원가를 다시 계산한다. $1을 넘고 저가 모델로도 안 내려가면 **프로젝트를 멈춘다**
  3. **봐주기** — 판정 실패 횟수 대비 시계 진행 횟수 집계와 관찰 기록으로, 시계는 도는데 이야기가 억지스러웠는지 판단한다
  4. **자유 텍스트 마찰** — 세션에서 나온 약 160개에 사내 플레이 약 140개를 보태 정답 데이터 300개를 채우고, 「엔터 한 번」+「클릭 한 번」이 95% 이상인지, 「직접 찾아야 함」이 30% 미만인지 잰다
  5. **비경험자 진입** — 비경험자 2명이 캐릭터 만들기를 끝냈는지로 답한다
  6. 여섯 가설의 판정 결과와 그에 따른 다음 행동(계속 / 멈춤 / 전략 변경 / 재설계)이 문서로 남는다

**Plans**: 채점 규칙은 **실험 전에 이미 고정했다** — `docs/experiment/hypothesis-scoring-rules.md`.
Phase 6의 계획은 그 문서를 실행하는 것이고, 실행 순서는 이렇다.

1. `experiment-results.md` 완성 — 두 세션의 `gptrpg report` 산출물 + 관찰 기록 + 1세션 시작 시각에 적어 둔 기준 모델·단가
2. H4 라벨링 — 세션 문장에 사람이 라벨을 붙이고(`no_candidate`를 두 갈래로 쪼개고, 같은 의도의 재시도를 합친다) 부족분을 사내 플레이로 채워 300개를 만든 뒤, 배포 후보 모델로 재분류해 문턱을 적용
3. H5 계산 — 채점 규칙 §5의 식에 실측 토큰 세 값을 넣고 최상급·저가 두 기준을 다 계산. 무료 체험 획득 원가도 함께 낸다
4. H2·H6 판정 — 관찰 기록에서. 표본 부족이면 유보로 적는다
5. 여섯 가설의 판정 결과와 다음 행동을 문서로 남긴다. **유보는 통과로 적지 않는다**

> **이 단계가 게이트다.** 아래 「게이트」 절 참조.
>
> **채점 규칙을 실험 전에 못박은 이유.** D12가 이 프로젝트의 목표를 「완벽 방어」에서 「투명성」으로 바꿨는데, 그 원칙이 자기 킬 조건에는 적용되지 않고 있었다 — D-53이 2세션 완주 판정을 「관찰자의 주관」으로 열어 뒀고 그것이 H1의 유일한 입력이다. 표본이 4명이라 한 사람의 해석이 판정을 뒤집는다. 문턱값은 그대로 두고 **읽는 방법만** 미리 적었다.
>
> **원가 계산은 실측으로 처음부터 다시 한다.** 기존 문서의 $0.30 / $0.20 / $3.6은 「최근 대화 20턴」을 전제로 뽑은 숫자인데 확정된 규칙은 「초기값 10턴」이고, 10턴 기준으로 다시 계산한 문서가 하나도 없다. **이 숫자가 프로젝트를 멈추는 기준($1)의 입력값이다.** 실측값으로 대체하고, 대체한 결과를 원가 문서에 반영한다. 단 실측은 **압축(`context_summarizer`) 없는 상태**이고 **캐시 적중이 0으로 보고될 수 있는** 상태다 — 두 유보를 결과에 함께 적는다.
>
> 재미와 원가만 진짜 킬 조건이다. 나머지 넷이 실패해도 프로젝트는 살아남는다 — 다만 사업 규모나 정체성이 바뀌거나, 그 부분만 다시 만든다.

## 게이트 — 여기를 통과하지 못하면 아래는 없다

**Phase 6의 판정 결과가 나오기 전까지 M1 이후의 어떤 단계도 계획하지 않는다.** 로드맵에 번호를 붙이지 않은 것도 그래서다.

| 판정 | 해당 가설 | 다음 행동 |
|---|---|---|
| **멈춤** | 재미(H1) 또는 원가(H5) 실패 | **프로젝트를 멈춘다.** M1은 없다 |
| 전략 변경 | 룰북 데이터 표현(H3) 또는 자유 텍스트(H4) 실패 | 제품은 살리되 사업 규모·정체성을 다시 정한다. M1 범위를 새로 짠다 |
| 재설계 | 위협 시계(H2) 또는 비경험자 진입(H6) 실패 | 해당 부분만 다시 만들고 M1로 넘어간다 |
| **유보** | 표본·조건이 그 가설을 판정할 수 없다 | **통과가 아니다.** 조건을 갖춘 재실험을 M1 착수 **전에** 넣는다 |
| **통과** | 여섯 가설 모두 조건 충족 | M1 로드맵을 새로 작성하고 실시간 파티 제품을 만든다 |

원가만 실패한 경우가 애매해 보일 수 있는데 그렇지 않다. 멈추는 조건은 **$1 초과 + 저가 모델로도 안 내려감**이 함께 성립할 때다. 저가 모델로 내려간다면 전략 변경으로 살아난다.

**「유보」 행을 새로 넣은 이유.** 원래 표에는 판정 결과가 넷뿐이었고 「판정할 수 없다」는 칸이 없었다. 그러면 판정 불가가 암묵적으로 「통과」로 흘러간다 — 멈추지 않았으니 넘어가는 것이다. 이번 실험이 정확히 그 상태다: H1은 교란 셋(간격 1~3일 / 무료 티어 모델 / 오너가 참가자라 실질 표본 3명) 때문에 어느 방향으로 나와도 D30의 규칙을 적용할 수 없고, H2는 진행 규칙 ①만 구현되어 관측 지표가 항상 3.0에 고정된다. 상세와 판정 조건은 `docs/experiment/hypothesis-scoring-rules.md` §2·§3, 결정 제안은 PROJECT.md의 D-59·D-60(승인 대기)이다.
