# GPTRPG

## What This Is

TRPG를 잘 모르고 룰북을 읽을 시간도 없지만, 친구들과 실시간으로 몰입할 세계를 원하는 사람을 위한 온라인 플랫폼이다. AI가 이야기 진행자 노릇을 하고, 주사위와 판정은 사람이 검산할 수 있는 순수 코드가 처리한다. 특정 룰북 전용 시스템이 아니라 **룰북을 데이터로 받아들이는 범용 시스템**을 만든다.

## Core Value

**이야기가 어떻게 끝나는지 보고 싶어서 일주일 뒤에 다시 접속한다.**

위협 시계가 돌고 있고 아직 멈추지 않았다 — 이 제품이 팔아야 하는 감정은 그것 하나다. 성장·보상은 재방문 유인이 아니다.

---

## ⚠️ 지금 어디에 있나 — 마일스톤 0은 완료가 아니다

마일스톤 0은 **설계**와 **킬 크리테리아 실험** 두 부분이다. 끝난 것은 설계뿐이고(2026-07-30 종결), 실험은 아직 하지 않았다.

실험은 가설 6개를 확인한다. 그중 둘은 **프로젝트를 멈출 수 있는 조건**을 들고 있다.

| 등급 | 해당 가설 | 실패하면 |
|---|---|---|
| **진짜 킬** | **H1 — AI가 진행하면 재미있다** / **H5 — 원가가 사업 가능 범위다** | **프로젝트를 멈춘다** |
| 전략 변경 | H3 — 룰북을 데이터로 표현할 수 있다 / H4 — 자유 텍스트 입력이 쓸 만하다 | 제품은 살리되 사업 규모와 정체성이 바뀐다 |
| 재설계 | H2 — 위협 시계가 봐주기를 막는다 / H6 — 비경험자가 시작할 수 있다 | 해당 부분만 다시 만든다 |

**이 로드맵의 첫 일은 제품 기능이 아니라 실험이다.** 실험 게이트를 통과하기 전까지 M1 이후의 어떤 단계도 계획하지 않는다.

지금 만드는 것은 **제품이 아니라 실험 도구**다. 화면이 투박해도 "재미있나"를 재는 데 방해만 안 되면 된다.

## Business Context

- **Customer**: TRPG를 잘 모르는 국내·국외 일반 유저. 친구 파티가 1순위, 낯선 사람 매칭은 나중(M2)
- **Revenue model**: 등급제 + 소프트 상한, 파티/솔로 요금 분리. 무제한 정액제는 성립하지 않는다(솔로가 파티보다 1인당 7~8배 비쌈). 무료 단위는 "첫 에피소드"(시계 1~2칸)
- **Success metric**: **1인 1시간당 원가.** $1 초과 + 저가 모델로도 안 내려가면 프로젝트를 멈춘다
- **Strategy notes**: `docs/GPTRPG-cost-analysis.md` (참고용 분석 — 결정의 출처가 아니다)

## Context

### 타깃 유저와 전제

회사·학교가 끝나고 친구들과 실시간으로 몰입할 세계를 원하지만, 룰북을 읽을 시간은 없는 사람. 플레이 시간은 고정 세션이 아니라 하고 싶은 만큼이다.

전제 세 가지 — ① 플레이어끼리의 대화는 외부 메신저에서 일어난다(플랫폼은 소셜 레이어가 아니고 입력창은 행동 선언용) ② 언제든 끊고 이어할 수 있어야 한다 ③ 언젠가는 처음 보는 사람과의 플레이를 받는다.

해결하는 문제 — 룰북을 읽어야 시작할 수 있다(숫자를 서술로 번역) / 진행할 사람이 없다(AI가 진행, 판정은 코드가) / 언제 다시 모일지 못 정한다(세션 개념을 버린다) / 낯선 사람과 하기가 불안하다(안전 장치를 기본으로).

### 세 개의 층 — 모든 기능은 어느 층인지 밝힌다

| 층 | 무엇 | 예 |
|---|---|---|
| ① 플랫폼 기능 | 룰북과 무관하게 우리가 제공 | 안전 장치, 끊고 이어하기, 이벤트 기록 |
| ② 표현 어휘 | 룰북이 말하는 것을 담는 그릇 | 캐릭터 만들기 7가지 동작, 판정 방식, 효과 표현 |
| ③ 룰북 규칙 | 룰북 설계자가 정한 것 | 성장·죽음·장비·회복의 구체적 규칙 |

**③을 ①에 올리면 다른 룰북이 망가진다.** 기능을 제안할 때 층을 밝히는 것이 이 프로젝트의 규약이다.

**첫 타깃이 던전월드 계열이라는 이유로 그 룰북의 규칙을 플랫폼에 박지 않는다.** 우리가 표현하지 못하는 규칙은 "자동화율이 낮다"로 정직하게 표시하고 재량 판정으로 넘긴다.

### 용어 — TRPG 용어를 그대로 쓰지 않는다

| 이 프로젝트의 용어 | 뜻 |
|---|---|
| **위협 시계** | 플레이어가 막지 않으면 순서대로 일어날 나쁜 일들의 목록. 시나리오의 뼈대 |
| **시계 칸** | 위협 시계의 항목 하나. "우물물이 검게 변한다" 같은 사건 하나 |
| **파국** | 시계가 끝까지 갔을 때 벌어지는 일 |
| **판정** | 주사위를 굴려 성공·실패를 정하는 것 |
| **무브** | 판정이 발동하는 상황의 종류 |
| **GM 대응** | 플레이어가 실패했을 때 진행자가 할 수 있는 일의 목록 |
| **재량 판정** | 룰북에 없는 상황을 그 자리에서 판단하는 것. 정통 TRPG의 절반이 이것 |
| **판정 방식** | 주사위 판정 수학을 담은 코드. 룰북 계열마다 하나 |
| **효과 표현** | 주문·특성의 효과를 조합 가능한 원자 연산으로 적는 데이터 형식 |
| **자동화율** | 룰북의 판정 중 시스템이 자동 처리하는 비율. 남은 몫은 재량 판정 |

### 아직 안 풀린 것

문서 정리 과정에서 자동으로 풀리지 않은 항목 3건과, 2026-08-05 코드 대조에서 새로 드러난 항목
3건이다. 앞의 셋은 `.planning/INGEST-CONFLICTS.md`, 뒤의 셋은 `docs/PIPELINE.md` §9가 상세다.

1. **폐기된 v1 기획서에 폐기 표기가 없다.** 파일명 말고는 단서가 없어서, 그 파일만 따로 열어 본 사람은 폐기된 설계를 유효한 명세로 읽는다. → 파일 머리에 상태 한 줄을 넣거나 이후 수집에서 제외한다.
2. **v1에만 있고 유지·폐기 진술이 어디에도 없는 구현 약속 2건.** ① 에이전트 응답 껍데기와 가벼운/중간 모델의 타임아웃·재시도 규칙 ② 연결 유지 신호 주기와 스트리밍 도중 재연결 시 이어붙이기 규칙. 응답 속도 결정이 무거운 모델의 15초 타임아웃만 확정했으므로 나머지는 비어 있다. → 실험 도구를 만들면서 최소한만 정하고, 제품 규격은 M1 착수 시 정한다.
3. **원가 수치의 계산 전제가 결정과 어긋난다.** 원가 문서는 「최근 대화 20턴」을 넣고 1인 1시간당 $0.30을 계산했는데, 확정된 규칙은 「초기값 10턴」이다. 10턴 기준으로 다시 계산한 문서가 하나도 없다. **이 숫자가 프로젝트를 멈출 수 있는 조건($1)의 입력값이다.** → 실험 실측으로 대체한다. **덧붙여 원가 문서 §1의 계산은 「캐시 읽기 14,000토큰」이 지배 항목인데, 지금 쓰는 제공자(OpenAI 호환)에는 `cache_control`을 전달할 방법이 없다** — 실측은 캐시 0% 상태일 수 있으므로 §1의 캐시 전제와 직접 비교되지 않는다.
4. **D-31이 「접지 않는다」고 적은 것이 애초에 주입되지 않는다.** 관계 장부(D-11)와 저장소 색인이 안전장치 절에는 「접지 않는 것」으로 명시되어 있는데 **매 턴 넣는 네 가지 안에는 둘 다 없다.** 캐스트 이름·상태값은 매 턴 들어가지만 「그 인물과 무슨 일이 있었는지」는 최근 10턴 밖으로 나가면 사라진다 — 3~4시간 세션에서 10턴은 20~30분이다. → M1-13.
5. **D-17이 정한 에이전트 넷 중 `context_summarizer`가 없다.** 그래서 D-31의 「턴당 토큰 예산 상한 + 오래된 대화 접기」가 미구현이고 지금은 그냥 10턴 자르기다. **M0 원가 실측은 「압축 없는 상태」의 값**임을 Phase 6이 알아야 한다. → M1-12.
6. **D-21의 진행 규칙 세 가지 중 ①만 구현되어 H2의 관측 지표가 죽었다.** 실패 3회마다 정확히 한 칸이 도므로 `failure_to_clock_ratio`가 항상 3.0이다. → 제안 D-60 + M1-09.

### D21과 D-47이 이번 실험의 시간 예산 안에서 양립하지 않는다

D21 규격은 「시계 하나 = 4~6칸 / **8~15시간**」이고 이번 실험은 2세션 합쳐 **6~8시간**이다.
즉 규격대로면 4칸을 다 돌지 못한다. 그런데 D-47은 「파국까지 도달하면 그것이 세션의 자연스러운
종료점」이라고 정했다. 게다가 실제 페이싱을 정하는 것은 이야기가 아니라 **주사위**다 —
파국까지 필요한 판정 횟수가 능력치에 따라 29~72회로 갈리고, 2세션 예상 판정 수(약 40회)가
정확히 그 경계선에 있다.

→ **D-61로 해소했다 (승인 2026-08-05).** 실험의 목표 범위를 「첫 에피소드(1~2칸)」로 잡고,
파국 도달을 목표나 성공 조건으로 삼지 않는다. 시계 데이터는 4칸 그대로 둔다 — 칸수를 2로
줄이면 파국 서사가 2칸에서 터져 이야기 자체가 바뀐다. 종료 판정 규칙은
`docs/experiment/hypothesis-scoring-rules.md` §9에 있다: 파국 도달 여부와 무관하게 예정
시간에 끝내고, 중간에서 끝난 것을 실패로 세지 않으며, EXP-03의 「완주 대 흐지부지」는 시계
도달 칸이 아니라 사람이 끝까지 있었는지로 판정한다.

부수 효과로 D21 표의 「1,000팀 $2,500~6,000」의 **입력값이 처음으로 존재한다** — 집계에
시계 칸별 누적 스냅샷(`episodes`)이 생겨 「1~2칸에 몇 시간·몇 토큰이 들었나」가 세션 합계에서
갈라진다.

## Constraints

- **실행 환경**: Python 백엔드 + TypeScript 프런트엔드 — 원본 문서가 정한 것이 아니라 이번 정리 과정에서 프로젝트 수준으로 새로 고른 것이다
- **아키텍처(되돌릴 수 없음)**: 모든 사건을 순서대로 기록하고 현재 상태는 그 기록에서 만든다 — 제자리 수정 방식으로 먼저 짜면 재접속 동기화·다시보기·비동기 참여·관전자 합류가 전부 나중에 불가능해진다. **M0에서 확정해야 하는 유일한 되돌릴 수 없는 결정**
- **아키텍처 불변 규칙 3개**: ① 규칙 계산은 시간을 모른다(타이머·접속 상태 개념 금지) ② 세션마다 쓰기 주체는 하나뿐이다 ③ 플레이 모드는 코드 분기가 아니라 설정값이다(새 모드 추가 = 표에 열 하나)
- **LLM 경계**: 주사위와 판정 계산에 AI가 끼어드는 지점을 만들지 않는다. AI는 닫힌 목록에서 고르는 일과 서술만 한다. 수치는 못 바꾼다
- **프롬프트 캐싱**: 조립 순서를 안정성 순서(영구 고정 → 세션 고정 → 턴마다 변함)로 짠다. 나중에 할 최적화가 아니라 처음부터 지켜야 하는 설계 제약이다 — 캐싱 유무가 원가를 3.7배 가른다
- **기억 주입**: 매 턴 넣는 것은 네 가지로 고정(현재 장면에 등장한 대상 / 내 캐릭터 상태 / 위협 시계 상태 / 최근 대화 10턴). AI가 저장소 전체를 훑는 경로는 만들지 않는다
- **응답 속도**: 문장 입력 → 행동 확인 표시 0.5초, 확인 → 서사 첫 글자 2초. 완결까지는 목표 없음. 첫 글자 5초 초과 시 진행 표시, 15초 초과 시 판정 결과를 먼저 내보내고 서사를 뒤이어 붙인다
- **모델**: M0은 최상급 모델 고정 — 여기서 재는 것은 원가가 아니라 **품질 상한선**이다. 최상급으로도 재미없으면 제품이 성립하지 않아 거기서 판단이 끝난다. 단 원가가 생존 가능한 범위인지는 답해야 한다
- **모델 교체 가능성**: 에이전트별로 모델·제공자를 설정값으로 만든다. 지금 넣으면 공짜고 나중에 넣으면 재작성이다
- **한국어**: 대부분의 모델 벤치마크가 영어 기준이라 참고가 안 된다. 한국어 서사 품질은 별도로 측정한다
- **M0 범위선**: 룰북 데이터의 필드 단위 규격 · 효과 원자 연산 최종 목록 · 적 상태값 묶음의 구체 형태 · 화면 배치와 컴포넌트는 **전부 M0 밖**이다

1. 무효화된 요구사항 → Out of Scope로 사유와 함께 이동
