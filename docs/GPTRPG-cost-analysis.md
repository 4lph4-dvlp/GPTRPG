## 2. 기준 원가 (프론티어 API 기준)

프론티어급 단가를 $5/$25 per MTok(입력/출력), 경량급을 $1/$5로 잡았을 때.

### 턴당

| 컴포넌트 | 계산 | 원가 |
|---|---|---|
| `action_classifier` (경량) | 캐시 2,000 + 신규 800 + 출력 150 | $0.002 |
| `master_gm` 캐시 읽기 | 14,000 tok × $0.50/MTok | $0.007 |
| `master_gm` 신규 입력 | 1,000 tok × $5/MTok | $0.005 |
| `master_gm` 캐시 쓰기 | 800 tok × $6.25/MTok | $0.005 |
| `master_gm` 출력 | 800 tok × $25/MTok | $0.020 |
| **턴 합계** | | **≈ $0.039** |

## 3. 발견 1 — 솔로가 파티보다 7~8배 비싸다

**LLM 호출은 턴 수에 비례하지 사람 수에 비례하지 않는다.**

| | 3시간 턴 수 | 총 원가 | **1인당 원가** |
|---|---|---|---|
| 4인 파티 | 80턴 (4명이 나눠 씀) | $3.6 | **$0.90** |
| 솔로 | 130~150턴 (혼자 계속 입력) | $6.0 | **$6.00** |

파티는 한 사람이 입력하는 동안 나머지 3명이 같은 서사를 읽는다. **원가가 4분의 1로 나뉜다.** 솔로는 안 나뉘고, 대기 시간이 없어 턴이 더 많다.

**함의**

- M1(실시간 파티)이 원가 구조상 가장 유리하다. 현재 로드맵 순서가 맞다
- **M2(솔로 모드)는 별도 가격 정책이 필요하다.** 파티와 같은 요금으로 무제한 제공하면 솔로 헤비유저가 적자의 진원지가 된다
- **관전자(시청자)는 원가가 0이다.** 읽기만 하므로. 스트리머 노출 전략은 원가 측면에서 공짜

## 4. 발견 2 — 캐싱 설계가 원가의 지배 변수다

| | 1인 1시간당 |
|---|---|
| 캐싱 잘 설계 | **$0.30** |
| 캐싱 없음 | **$1.10** (3.7배) |

캐싱은 **접두 일치(prefix match)** 방식이라 프롬프트 앞부분이 1바이트라도 바뀌면 뒤쪽 전체가 무효화된다. 나중에 최적화할 항목이 아니라 **처음부터 프롬프트 조립 구조를 그렇게 짜야 하는 항목**이다.

### M0에서 확정할 규칙 3개

1. **시스템 프롬프트를 동결한다.** "현재 시각", "플레이어 이름" 같은 동적 값을 시스템 프롬프트에 끼워 넣으면 매 턴 전체 캐시가 깨진다. 동적 정보는 메시지 뒤쪽에 넣는다
2. **프롬프트 조립 순서 = 안정성 순서.** 영구 고정 → 세션 고정 → 턴마다 변함
3. **엔티티 장부를 결정론적으로 직렬화한다.** 딕셔너리 순서가 흔들리면 캐시가 깨진다

W6(엔티티 장부 무한 성장)과 연결된다. 장부를 **전체 주입이 아니라 관련성 기반 선별 주입**으로 바꾸면 토큰도 줄고 캐시 안정성도 올라간다.

## 5. 대체 모델 분석 (저가 API / 오픈웨이트 / 자체 호스팅)

### 5.1. 핵심: 두 에이전트는 요구사항이 완전히 다르다

**모델 선택을 하나로 통일하면 안 된다.**

| | `action_classifier` | `master_gm` |
|---|---|---|
| 하는 일 | 닫힌 집합 분류 + JSON 출력 | 한국어 창작 서사, 페르소나 유지, 장기 일관성 |
| 난이도 | **낮음** | **높음** |
| 검증 가능성 | **객관적 가능** (골든셋 정답률) | 주관적, 어려움 |
| 저가 모델 적합도 | **매우 높음. 파인튜닝하면 더** | 위험. 실측 필요 |
| 원가 비중 | 전체의 약 5% | 전체의 약 95% |

**전략적 결론:** 검증 가능한 쪽부터 싼 모델로 내린다. `action_classifier`는 소형 모델 또는 파인튜닝된 모델로 거의 확실하게 대체 가능하다(원 기획안의 "Fine-tuned" 판단은 옳았다). `master_gm`은 실측 없이 내리면 안 된다 — 여기가 제품의 재미 그 자체이기 때문이다.

다만 원가의 95%가 `master_gm`이므로, **비용 절감의 실질은 전부 `master_gm`에 달려 있다.**

### 5.2. 후보군

> 단가는 변동이 심하므로 **배수로만** 기재한다. 실제 도입 시점에 재확인 필수.

| 계열 | 대표 | 프론티어 대비 단가 | 한국어 서사 리스크 |
|---|---|---|---|
| **중국계 오픈/저가 API** (Qwen, GLM, DeepSeek 계열) | 대형 MoE | 대략 **1/10 ~ 1/50** | 중간~높음. 영어·중국어 중심 학습. 한국어 문체 품질 실측 필요 |
| **NVIDIA NIM / Nemotron 계열** | Llama 파생 | 대략 **1/5 ~ 1/20** | 중간~높음. 한국어 상대적 약세 |
| **한국어 특화 모델** (국내 벤더) | — | 대략 **1/3 ~ 1/10** | **낮음.** 대신 장문 일관성·지시 따르기가 프론티어보다 약할 수 있음 |
| **자체 호스팅 오픈웨이트** | 70B~120B급 | 아래 5.3 참조 | 모델에 따라 다름 |

**한국어가 이 제품의 특수 변수다.** 대부분의 벤치마크는 영어 기준이라 참고가 안 된다. "한국어로 3시간 몰입할 만한 서사를 쓰는가"는 별도로 측정해야 한다.

### 5.3. 자체 호스팅 계산

**이론값 (이용률 100% 가정)**

| 항목 | 값 |
|---|---|
| 70B급 서빙 구성 | GPU 2장 (A100 80GB급) |
| 클라우드 GPU 시간당 | 약 $3~5 (약정 시 하락) |
| vLLM 배칭 시 동시 파티 수용 | 보수적으로 30~80 파티 |
| 파티당 시간 원가 | $4 ÷ 50 ≈ **$0.08** |
| **1인 1시간당** | **≈ $0.02** |

프론티어 API 대비 **약 15배 저렴**해 보인다. 그런데 이 숫자는 함정이다.

**⚠️ 실제값 — 이용률이 전부를 결정한다**

> **TRPG는 이용률 패턴이 최악이다.**
> 사람들은 **저녁 8시~자정에 몰린다.** 새벽과 근무 시간에는 거의 없다.

| | 이용률 | 실효 1인 1시간당 |
|---|---|---|
| 이론 (100% 균등) | 100% | $0.02 |
| **현실적 추정** (피크 집중) | **25~30%** | **$0.07** |
| 초기 (유저 적음) | 5~10% | $0.20~0.40 |

**즉 자체 호스팅은 규모가 붙기 전까지 API보다 비싸거나 비슷하다.** 그리고 API에는 이용률 리스크가 아예 없다 — 안 쓰면 0원이다.

**추가로 드는 비용 (숫자에 안 잡히는 것)**

- vLLM/추론 서버 운영, 모니터링, 장애 대응 → 사실상 인력 1명
- 모델 업데이트마다 재검증
- 피크 초과 시 큐잉 → 유저 체감 지연
- GPU 조달 리드타임

### 5.4. 종합 비교

| 전략 | 1인 1시간당 | 품질 리스크 | 운영 부담 | 권장 시점 |
|---|---|---|---|---|
| 프론티어 API 단독 | $0.30 | 없음 | 없음 | **M0 (품질 상한 측정)** |
| 프론티어 + 중형 이원화 | $0.20 | 낮음 | 낮음 | M1~M2 |
| 저가 API (classifier만 교체) | $0.29 | **거의 없음** | 낮음 | **M0에서 바로 가능** |
| 저가 API (GM까지 교체) | $0.03~0.10 | **높음. 실측 필수** | 낮음 | M2 이후, 실측 통과 시 |
| 자체 호스팅 | $0.07 (이용률 30%) | 모델 의존 | **높음** | 기저 부하가 생긴 뒤 |

### 5.5. 권고

1. **M0에서 모델 교체 가능성을 설계에 박는다.** 프로바이더 추상화 계층을 지금 만들면 공짜, 나중에 만들면 재작성이다. 각 에이전트가 어떤 모델을 쓸지는 **설정값**이어야 한다
2. **M0은 프론티어로 품질 상한을 잰다** (D18). 여기서 재미없으면 제품이 성립하지 않으므로 판단이 끝난다
3. **`action_classifier`는 M0에서 바로 저가 모델로 A/B한다.** 골든셋 정답률로 객관 비교가 가능하므로 리스크가 거의 없다
4. **`master_gm` 하향은 Task #9(GM 품질 검증 방법론)이 완성된 뒤에만 한다.** 측정 도구 없이 내리면 "모델이 작아서 재미없는 건지 설계가 틀려서인지" 구분할 수 없다
5. **자체 호스팅은 M0의 결정 사항이 아니다.** 안정적 기저 부하가 생긴 뒤의 최적화이며, 그때도 피크/오프피크 하이브리드(기저는 자체, 피크는 API)가 현실적이다

## 6. 수익 모델

### 6.1. 무제한 정액제는 성립하지 않는다

| 유저 유형 | 월 플레이 | 원가 (프론티어) | 원가 (이원화) | 원가 (저가 모델) |
|---|---|---|---|---|
| 라이트 (주 2시간) | 8시간 | $2.4 | $1.6 | $0.4 |
| 미들 (주 5시간) | 20시간 | $6.0 | $4.0 | $1.0 |
| 헤비 (주 10시간) | 40시간 | $12.0 | $8.0 | $2.0 |
| **솔로 헤비** | 20시간 | **$40** | **$27** | **$7** |

월 9,900원(~$7) 기준으로 보면, 프론티어 단독일 때 파티 헤비 유저가 손익분기 근처이고 솔로 헤비는 확실한 적자다.

**모델 선택이 곧 가격 정책의 자유도다.** 저가 모델로 내려가면 무료 티어와 정액제 여유가 모두 생긴다.

### 6.2. 확정 방향 — (다) 등급제 + 소프트 상한 & (라) 파티/솔로 분리

- **파티: 넉넉한 소프트 상한이 붙은 정액.** 대부분 유저는 상한을 인지조차 못 한다. 원가 상위 5%만 통제
- **솔로: 별도 취급.** 원가 구조가 다르므로

### 6.3. 무료 티어 (사업 초기)

목표: 사업 초기에 파티 플레이를 되도록 무료로 제공.

**실현 가능성은 모델 선택에 직결된다.**

| 모델 | 파티 1세션(3시간) 원가 | 신규 파티 1,000팀에 1세션 무료 제공 비용 |
|---|---|---|
| 프론티어 | $3.6 | **$3,600** |
| 이원화 | $2.4 | $2,400 |
| 저가 모델 | $0.6 | **$600** |

**⚠️ 무료 티어를 시간 카운터로 만들면 안 된다.**

"남은 플레이 시간 12시간"을 화면에 띄우는 순간 **시계를 보며 노는 게임**이 된다. TRPG 몰입과 가장 상극인 UX다.

**대신 콘텐츠 단위로 끊는다.**

> **"첫 캠페인 무료"** — 전선(Front) 1개를 끝까지 무료로 플레이.

> **정정 (D21).** 무료 단위는 **"첫 에피소드"(위협 시계 1~2칸)**로 확정됐다. 위 계산은 세션 하나 기준이었는데 "첫 캠페인"은 시계 하나(4~6칸 / 8~15시간)를 통째로 주는 안이어서 원가가 4~5배 차이 난다. 아래 서술의 논리(콘텐츠 단위로 끊는다)는 그대로 유효하고 단위만 작아진다.

이게 우아한 이유:

- 시계가 안 보인다. 유저는 게임을 하다가 이야기가 끝난다
- **전선(Fronts) 구조와 정확히 맞는다.** 전선 하나 = 콘텐츠 단위 = 과금 단위. D9에서 정한 시나리오 모델이 그대로 과금 모델이 된다
- 원가 예측이 가능하다. 전선 하나의 평균 플레이 시간을 측정하면 됨
- "게임 하나를 샀다"는 감각이라 구독 저항이 낮다
- 완결감이 있어서 다음 캠페인 구매로 자연스럽게 이어진다

**소프트 상한은 뒤에 숨긴다.** 비정상 사용(자동화, 어뷰징)만 걸러내는 안전장치로 두고, 정상 유저에게는 보이지 않게 한다.

### 6.4. 코스메틱 판매

웹 기반에서 시각적으로 보이는 요소를 판매.

**⚠️ 중요 — M0~M3에는 "보드 위의 말"이 없다.**

던전월드에는 그리드가 없다(D4). 좌표계 자체가 없으므로 토큰/말을 놓을 보드가 존재하지 않는다. **말 스킨은 M4(D&D 5e 전술 그리드) 이전에는 팔 자리가 없다.**

그 전까지 판매 가능한 시각 요소:

| 항목 | M0~M3 판매 가능 | 비고 |
|---|---|---|
| **주사위 스킨** | ✅ | 판정은 항상 있으므로 항상 보임. 최우선 |
| **캐릭터 초상화·아바타** | ✅ | 파티 화면에 상시 노출 |
| **캐릭터 시트 테마** | ✅ | 플레이 내내 열려 있음 |
| **서사 로그 테마** (폰트·색·프레임) | ✅ | **화면의 대부분을 차지하는 영역** |
| **캠페인 기념품** (모먼트 연대기) | ✅ | 기획안 4.2절에 이미 있음. 아래 참조 |
| 말/토큰 스킨 | ❌ → M4 | 그리드가 M4에 등장 |

**서사 로그 테마가 과소평가되어 있다.** 이 제품은 화면의 대부분이 텍스트다. 폰트, 색조, 말풍선 프레임, 주사위 결과 연출 스타일 — 이게 실질적으로 유저가 가장 오래 보는 화면이다. 주사위보다 노출 시간이 길다.

**캠페인 기념품은 감정 가치가 가장 높은 상품이다.** 기획안 4.2절의 "모먼트 연대기"(엔딩 시 로그를 마크다운·아카이브로 컴파일)를 프리미엄 상품으로 만들 수 있다. 실제 TRPG 문화에서 캠페인 기록은 강한 감정적 가치를 갖는다. 물리 인쇄 책자로 확장하면 객단가가 크게 올라간다.

### 6.5. UGC 마켓 (장기)

마인크래프트 마켓플레이스 모델. 장기적으로는 코스메틱보다 클 수 있다.

- 유저가 만든 **전선(Front)·시나리오** 판매 → 수수료
- 유저가 만든 **룰북** 판매 → **자작 오리지널에 한해 허용** (D29에서 재검토 완료. 판단 기준은 어느 판정 방식을 쓰는지가 아니라 문장과 고유명사가 자작인지이며, 자작 선언 → 유사도 검사 → 수익화 신청 시 별도 검수를 거친다)
- 자동화율(D7) 표시가 여기서 품질 신호로 작동한다

**목표를 "E2E 3초"에서 "확인 후 첫 글자까지 2초"로 교체한다.** 원 기획안의 목표는 완결 기준이었고 그건 달성 불가능하다.

> **이 절은 결정의 출처가 아니다.** 여기의 재산정을 근거로 **D33**이 목표를 확정했다 — 두 구간(입력→확인 0.5초 / 확인→첫 글자 2초)과 초과 시 행동(5초 진행 표시, 15초 타임아웃 시 판정 결과를 서사보다 먼저 내보냄)까지 포함한다. 권위는 `GPTRPG-M0-decisions.md`에 있다.

자체 호스팅 시에는 피크 큐잉으로 첫 토큰 지연이 튈 수 있다. 이용률 계산에 반드시 포함할 것.
