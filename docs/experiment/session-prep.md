체크리스트(`docs/experiment/dry-run-checklist.md`) ①~⑦을 CLI로 직접 실행해 확인했다. 웹 화면이 아니라 `uv run gptrpg turn` 명령으로 행동 1개를 돌렸다(빠른 수동 시험용 경로, 별도 스크래치 DB `/tmp/gptrpg-dryrun/events.db` 사용 — 본 세션 집계와 분리됨).

| 항목 | 결과 |

| ② 시나리오 반영 확인 | 통과 — "우물 안을 들여다본다" 행동에 대해 AI가 우물 속 수면, 물 밑에서 움직이는 정체불명의 것, 마을로 이어지는 발자국을 서술함. 05-01 시나리오("우물 아래의 것") 내용이 실제로 프롬프트에 실려 있음이 확인됨 |

| ④ 스트림 정지 워치독 | 오늘 별도 재현은 안 함 — Phase 3(03-06)에서 이미 구현·실전 확인됨(90초 워치독, 실제 ~22분 정지 재현 이력 있음). 코드 존재는 확인, 오늘 네트워크 차단 재현은 생략 |
| ⑤ 추론형 응답 확인 | 통과 — 서사가 분석/요약이 아니라 이야기체 문장으로 정상 출력됨. JSON 분류 응답도 정상 파싱됨 |

## 정정 — 드라이런 호출 수 환산 (2026-08-05, 코드 대조)

**위 ③ 칸의 「행동 1개 = AI 호출 3회」는 집계를 잘못 읽은 값이다.** 코드 경로를 따라가면 완주한
행동 하나가 만드는 AI 호출은 **정확히 2회**다 — 분류기 1회(`declare`) + 진행자 1회(`confirm`).
재시도(D-28)는 `RecordAiCall`을 늘리지 않는다(`call_with_one_retry`가 두 시도를 껍데기 하나로
접어 돌려준다). 판정 없이 끝난 행동은 1회다(분류기만).

드라이런 집계(`turn_count: 3` · `ai_calls: 3` · `check_count: 1`)를 코드에 맞게 읽으면
「행동 3개를 냈고 그중 1개만 확인·판정까지 갔다」다. `turn_count`는 **행동 선언 수**이므로
3을 「행동 1개」로 잡은 것이 오독이었다.

| | 잘못 적힌 값 | 정정 |
|---|---|---|
| 행동 1개당 AI 호출 | 3회 | **2회** (완주) / 1회 (판정 없이 끝남) |
| 세션 하나(4명·약 40행동) | 약 120회 | **약 60~80회** |

**한도 대응 결정은 바뀌지 않는다.** NIM에는 일일 상한이 없으므로 60회든 120회든 결론이 같다.
정정하는 이유는 **같은 숫자가 H5 원가 환산의 입력값**이라서다 — 3회로 두면 원가가 1.5배 과대
추정된다. Phase 6은 이 정정된 값을 쓴다.

## 한도 대응 결정 (Task 2)

**이 계획이 제시한 세 선택지(A: OpenRouter에 $10 결제 / B: 하루 50회 안에서 세션 축소 / C: 유료 모델로 전환)와 다른 네 번째 경로를 택함 — 실측 결과로 발견된 사실에 근거함.**

- **결정: NIM(NVIDIA)을 두 세션 모두 기본 제공자로 사용한다.** OpenRouter 무료 티어는 NIM에 문제가 생겼을 때만 쓰는 백업으로 둔다.
- **이유:** 사용자가 이미 NVIDIA NIM 키를 준비해 두었고, NIM은 분당 요청 제한만 있고 OpenRouter `:free`처럼 결제 이력에 따른 일일 상한(50/1000회)이 없다. 오늘 드라이런도 실제로 NIM 경로로 처리되어 정상 동작을 확인했다. 이렇게 하면 옵션 A(결제)나 옵션 B(세션 설계 축소) 없이도 T-05-14(무료 티어 DoS 위험)가 근본적으로 사라진다.
- **세션 당일 다르게 할 것:** `.gptrpg/agents.json`을 다시 건드릴 필요 없음(이미 NIM으로 설정됨). 만약 세션 도중 NIM 쪽에서 문제(429, 응답 실패 등)가 발생하면 `uv run gptrpg agents select`로 즉시 OpenRouter 무료 티어 모델로 전환한다 — 이 전환 절차를 사전에 숙지해 둔다.
