# 본 세션 전 사전 점검 (드라이런) 체크리스트

본 세션 며칠 전에 사람이 위에서부터 하나씩 확인한다. 각 항목은 「무엇을 친다 → 무엇이 보이면 통과 → 안 보이면 무엇을 한다」세 조각으로 되어 있다.

**⚠️ 요금제 스냅샷은 2026-08-03 기준이다. 1세션과 2세션 사이 1주 동안 바뀔 수 있으므로, 두 세션 각각 직전에 반드시 다시 확인하라.**

---

## ① 모델과 키 확인

- **무엇을 친다:** `uv run gptrpg agents show`
- **무엇이 보이면 통과:** 두 역할이 **NIM**으로 보인다 — `action_classifier: nim/meta/llama-3.1-8b-instruct`, `master_gm: nim/nvidia/nemotron-3-ultra-550b-a55b`. `.env.local`에 `NVIDIA_API_KEY`가 설정되어 있다(값 자체는 코드가 대신 확인해 주지 않으므로 사람이 눈으로 봐야 한다).
- **안 보이면:** README A절 2번의 `agents set` 두 줄을 그대로 친다. `설정 파일이 없다`가 나오는 것이 정상적인 초기 상태다 — 설정 파일은 저장소에 들어가지 않으므로(`.gitignore`의 `.gptrpg/`) 새 작업 사본에는 항상 없다. **이 상태로 서버를 띄우면 행동 선언이 전부 503으로 떨어진다.**
- **왜 OpenRouter가 아닌가:** 이 체크리스트를 처음 쓸 때는 제공자가 OpenRouter 무료 티어였다. 드라이런에서 일일 한도(무결제 계정 50회)가 세션 하나를 못 버틴다는 것이 확인되어 **NIM으로 바꾼 것이 「한도 대응 결정」**이다(`session-prep.md`). OpenRouter는 NIM에 문제가 생겼을 때만 쓰는 백업이다 — 그때는 `uv run gptrpg agents set --role … --provider openrouter --model …`으로 즉시 바꾼다.

## ② 시나리오가 실제로 프롬프트에 실렸는지 확인

- **무엇을 친다:** README의 「실험 당일 실행 절차」를 그대로 따라 서버를 띄우고 링크를 만들되, **드라이런에는 본 세션과 다른 저장소 파일(`GPTRPG_DB`)을 쓴다** — 드라이런 사건이 본 세션 집계에 섞이면 MEAS-01·MEAS-03 숫자가 오염된다. 임시 저장소로 짧은 세션 하나를 열어 두세 턴을 돌린다.
- **무엇이 보이면 통과:** AI가 05-01 시나리오("우물 아래의 것")의 세계를 알고 서술한다 — 우물, 촌장 담녹, 우물지기 이슬 같은 고유명사가 서사에 자연스럽게 등장한다.
- **안 보이면:** `src/gptrpg/rulebooks/threat_clocks.py`가 `build_turn_context`에 실제로 연결되어 있는지(05-01 산출물)를 확인한다.

## ③ 일일 요청 한도 (이 체크리스트의 핵심)

**계산.** 세션 하나당 플레이어 행동이 네 명 기준 약 40개이고, 행동 하나당 최소 두 번(행동 분류 + 서사) AI 호출이 나가므로 **세션 하나가 약 80회를 넘는다.**

OpenRouter 문서 기준(2026-08-03 확인) `:free` 모델은:
- 분당 한도: **20 RPM** (결제 이력 무관, 공통)
- 일일 한도, 평생 결제 이력이 **$10 미만**인 계정: **50 RPD**
- 일일 한도, 평생 결제 이력이 **$10 이상**인 계정: **1000 RPD**

즉 결제 이력이 없으면 세션 하나(약 80회)가 하루 50회 한도를 넘겨, 세션이 30분도 못 가 막힐 수 있다.

- **무엇을 친다:** 드라이런 세션이 끝난 뒤 `uv run gptrpg report`의 AI 호출 수를 확인한다. 그 값에 (세션 예상 행동 수 40 ÷ 드라이런 행동 수)를 곱해 세션 예상 호출 수를 낸다.
- **무엇이 보이면 통과:** 드라이런 도중 429 응답을 한 번도 받지 않았고, 계산한 세션 예상 호출 수가 계정의 일일 한도 아래다.
- **안 보이면(429를 한 번이라도 받았거나 예상 호출 수가 한도를 넘으면):** 본 세션 전에 반드시 대응을 정한다 — 예를 들어 계정에 결제 이력을 $10 이상 확보해 일일 한도를 1000으로 올려두는 방법이 있다(사용량 자체는 무료 모델만 계속 쓰면 되므로 실제 비용은 발생하지 않는다). 대응 결정은 05-04 Task 2의 결정 체크포인트로 넘어간다.

**⚠️ 이 스냅샷은 2026-08-03 기준이다. 두 세션 각각 직전에 다시 확인하라** — 1세션과 2세션 사이 1주 동안 정책이 바뀔 수 있다.

## ④ 스트림 정지 워치독

- **무엇을 친다:** 서사가 흘러나오는 도중에 네트워크를 잠깐 끊거나(또는 매우 느리게 만들어) 90초 안에 실패로 떨어지는지 확인한다.
- **무엇이 보이면 통과:** 90초 안에 스트림이 실패로 떨어지고, 이미 나온 문장이 보존된다. Phase 3에서 워치독 코드는 들어갔지만 실제 발동 확인은 skipped로 남아 있었으므로, 이번이 그 첫 실전 확인이 된다.
- **안 보이면:** 90초를 넘겨도 반응이 없으면 그 이상 기다리지 말고 재시도를 안내한다. 세션 중에도 서사가 멈춘 채 90초가 넘어가면 같은 대응(더 기다리지 않고 재시도 안내)을 쓴다.

## ⑤ 추론형 응답 확인

- **무엇을 친다:** 드라이런 중 무료 티어 모델의 응답을 눈으로 살핀다.
- **무엇이 보이면 통과:** 서사가 서사로 나오고, 분류 응답이 JSON으로 정상 파싱된다.
- **안 보이면:** 모델이 서사 대신 분석·요약을 내놓거나 응답이 JSON으로 파싱되지 않는 사례가 나오면, Phase 3에서 강건 파서와 지시문으로 이미 고쳤지만 모델을 바꾸면 다시 나올 수 있다는 뜻이다. 다른 무료 모델로 바꿔 다시 돌린다.

## 미리 알아 둘 캐비어트

무료 티어 모델을 쓰므로, H1(재미) 결과가 나빴을 때 「AI 진행자 개념의 한계」인지 「무료 모델이 약해서」인지 구분되지 않는다는 유보가 붙는다(D-58).

**H5(원가)도 영향을 아주 안 받는 것은 아니다.** 예전 판은 "H5는 이 캐비어트의 영향을 받지 않는다"고 적었는데 그건 과한 진술이다. 영향을 받지 않는 것은 **계산 방식**뿐이다 — 토큰 수에 공개 단가를 곱하는 절차는 어느 모델로 재도 같다. 그러나 **토큰 수 자체가 모델에 따라 달라진다**: 약한 모델은 「무브 없음」과 다시 쓰기를 더 자주 만들어 턴 수를 늘리고, 서사 길이도 다르다. 그래서 실측 토큰은 「이 모델로 이만큼」이고, 최상급 모델의 토큰 수와 같다고 가정하면 안 된다.

여기에 캐싱 문제가 하나 더 붙는다 — OpenAI 호환 표면(NIM 포함)에는 `cache_control`을 전달할 방법이 없어 캐시 적중이 0으로 보고될 수 있고, 그때의 원가는 **캐시 0% 가정의 상한선**이다. 상한선이 $1 이하로 나오면 확실한 통과지만, 넘으면 그 자리에서 멈춤을 결정할 수 없다.

두 유보를 어떻게 안고 채점하는지는 `docs/experiment/hypothesis-scoring-rules.md` §5가 정한다.
