# [GPTRPG] 마일스톤 0 종결 설계안

**작성:** 2026-07-30
**대상 문서:** `GPTRPG-M0-decisions.md`, `GPTRPG-design-plan.md`
**성격:** M0 설계 단계를 닫기 위한 변경 명세. 새 결정 3건 + 추적 표 정정 + 상태 전환.

## 0. 왜 이 문서가 필요한가

M0 결정 로그의 미결 표(§4 작업 15건, §5 지적 사항 대장)를 결정 본문(D1~D30)과 대조한 결과, **미결로 표시된 항목 대부분은 이미 답이 쓰여 있었다.** 표가 갱신되지 않은 것이다. 실제로 답이 없는 것은 3건이었다.

| 구분 | 건수 |
|---|---|
| 표에 🔄로 남았으나 이미 결정된 것 | 13 |
| 답이 없어 이번에 결정한 것 | 3 |
| 단위·표기 정정 | 2 |

답이 없던 3건은 아래 D31·D32·D33으로 결정한다.

## 1. 새 결정 3건

### D31. 기억 주입 규칙 — 장면에 있는 것만 넣는다

**해소하는 지적:** W6 (엔티티 장부 무한 성장 + "상시 주입" 설계 모순), Task #8 잔여분

**문제.** 세션이 진행되면 만난 인물·물건·단서가 계속 쌓인다. 원 기획안은 이것을 매 턴 AI에게 전부 보여준다고 설계했다. 장기 캠페인에서 프롬프트가 터지고, 목록이 매 턴 바뀌므로 프롬프트 캐싱도 깨진다. 원가 계산(1인 1시간당 목표)의 전제가 무너진다.

**결정.** 매 턴 AI에게 넣는 것을 네 가지로 고정한다.

| 매 턴 넣는 것 |
|---|
| 현재 장면에 등장한 대상 |
| 내 캐릭터 상태 |
| 위협 시계 상태 |
| 최근 대화 몇 턴 |

나머지 저장소는 **이름 + 한 줄 색인만** 보인다. AI가 특정 항목의 상세를 필요로 하면 그 항목을 요청하고, 코드가 꺼내서 다음 턴에 넣는다.

**금지.** AI가 저장소 전체를 훑는 경로는 만들지 않는다. 원 기획안의 "상시 주입"은 폐기한다.

**안전장치.** 턴당 토큰 예산 상한을 둔다. 넘치면 오래된 대화부터 요약으로 접는다. 단 다음 세 가지는 접지 않는다. 접히면 안 되는 것을 명시해 두지 않으면 구현할 때 가장 먼저 접힌다.

| 접지 않는 것 | 왜 |
|---|---|
| 저장소 색인 | 접히면 AI가 무엇을 요청할 수 있는지 모른다 |
| 위협 시계 상태 | 원칙 4 — "시계가 아직 멈추지 않았다"가 재방문 동기다 |
| 관계 장부 (D11) | 원칙 4 — 재방문 동기의 재료는 시계만이 아니라 NPC와의 관계와 심어둔 복선이다. 대화 요약에 접히면 사라진다 |

**캐싱과의 관계.** 룰북과 캐릭터 시트는 프롬프트 앞쪽에 고정되어 캐시가 붙고, 장면 정보만 뒤쪽에서 바뀐다. 주입량이 세션 길이와 거의 무관해지므로 원가가 예측 가능해진다.

**초기값과 실측.** "최근 몇 턴"의 초기값은 10턴. 이 값과 예산 상한은 M0 실측으로 확정한다.

**미룸.** 매 턴 관련 항목을 검색해서 꺼내오는 방식은 M0에 넣지 않는다. 검색 품질이라는 실패 지점을 추가하면 "AI GM이 재미있나"(H1)를 측정할 수 없게 된다. 장기 캠페인이 실제로 문제가 되는 시점(실서비스)에 재검토한다.

**폐기한 대안.** 예산 상한만 두고 오래된 것부터 접는 방식 — 구현이 가장 단순하지만 "오래됐지만 중요한 것"(1세션에 심은 복선)이 접힌다. 장기 캠페인에서 가장 아픈 지점이다. 예산 상한은 이 결정에서 안전장치로만 쓴다.

### D32. 적과 NPC의 숫자는 룰북이 선언한다

**해소하는 지적:** M2 (몬스터 스탯블록 + 전투 AI 부재, 검증 케이스에 "적의 턴"이 없음)

**절반은 이미 해소되어 있었다.** 첫 타깃 룰북을 PbtA 계열로 정한 뒤(D4), 적의 행동은 닫힌 대응 목록에서 나온다(D16). 별도의 전투 AI는 필요하지 않다.

**결정.** 플랫폼이 정하는 것은 다음뿐이다.

| 플랫폼이 정하는 것 | 룰북 데이터가 선언하는 것 |
|---|---|
| 식별자 | 상태값 묶음에 어떤 항목이 있는지 |
| 표시 이름 | 각 값의 뜻 |
| 상태값 묶음(키-값 그릇) | 특정 값이 바닥나면 무슨 일이 일어나는지 |
| 소속 룰북 | |
| 가시성 (D17) | |

상태 변경은 효과 표현(D7)을 통해서만 일어난다.

**저장.** 캐릭터와 같은 그릇을 재사용하고 유형으로만 구분한다. 성장·애착·인벤토리(D22, D25)는 캐릭터 유형에만 적용된다.

**금지.** 플랫폼 코드에 체력·피해·태그처럼 룰북 고유의 개념을 넣지 않는다. 이는 폐기한 "룰북별 전용 어댑터"(D5)와 같은 실수의 다른 얼굴이며, 원칙 2 수정판(판정 커널은 코드, 룰북은 데이터)과 원칙 3(룰북 설계자의 의도를 덮어쓰지 않는다)의 직접적 연장이다.

**대가.** 코드가 "체력"이라는 개념을 모르므로, 값이 바닥났을 때의 자동 처리를 룰북이 직접 선언해야 한다. 자동화율(D7)이 그만큼 룰북 작성 품질에 의존한다.

**범위.** 좌표계와 전술 그리드는 M4 유지(D13 ⑥).

**검증 추가.** "룰북을 데이터로 표현할 수 있다"(H3) 검증에 적 표현도 포함한다 — 두 번째 룰북의 적이 같은 그릇에 들어가는지 확인한다.

### D33. 응답 속도 목표와 초과 시 행동

**해소하는 지적:** W8 (레이턴시 목표 자기모순 — E2E 3초 vs 무거운 모델 타임아웃 15초)

**폐기.** "전체 3초". 완결 기준이었고 달성 불가능하다.

**결정 — 사람이 기다림을 느끼는 두 지점에 각각 목표를 둔다.**

| 구간 | 목표 |
|---|---|
| 문장 입력 → 행동 확인 표시 | 0.5초 |
| 확인 → GM 서사 첫 글자 | 2초 |
| 완결까지 | 목표 없음 (스트리밍이므로 체감은 첫 글자에서 결정된다) |

**초과 시 행동.**

| 상황 | 화면 |
|---|---|
| 첫 글자가 5초 초과 | 진행 표시를 띄운다 |
| 15초 타임아웃 | 판정 결과(주사위·성공/실패·시계 변화)를 먼저 내보내고, 서사를 뒤이어 붙인다 |

주사위와 판정은 순수 코드(D14)라 서사보다 먼저 끝나 있다. 추가 설계 없이 된다. 목표는 **"AI가 느려도 게임이 멈추지 않는다"**다.

**자체 호스팅.** 피크 대기로 첫 글자가 튀는 것은 이용률 계산에 포함한다(원가 문서 §7).

**측정.** 실제 응답 속도를 M0 실측 항목에 넣는다.

## 2. 정답 데이터 개수 — 단위 명시와 부족분 조달

**문제.** 같은 실험을 두 문서가 다른 숫자로 적었다. D28은 "실제 입력 약 80개", D30 측정 표는 "실제 입력 문장 약 160개". 단위 표기가 없어 모순으로 읽혔다. 그리고 가설 H4는 정답 데이터 300개를 요구하는데 실험은 160개만 만들어준다 — 나머지가 어디서 오는지 어느 문서에도 없었다.

**결정.**

| 출처 | 문장 수 |
|---|---|
| 사용자 실험 1세션 (3~4시간) | 약 80 |
| 사용자 실험 2세션 합계 | 약 160 |
| 사내 플레이 보충 | 약 140 |
| **H4 정답 데이터 목표** | **300** |

사내 플레이는 재미 가설(H1)을 측정하지 못한다. "우리는 GM을 하지 않고 관찰만 한다"는 규칙은 H1 때문이며, 파서 마찰 측정에는 그 제약이 적용되지 않는다. 우리가 굴린 세션의 입력 문장도 정답 데이터로 동일하게 유효하다.

D28과 D30 양쪽에 단위를 명시한다.

## 3. 마일스톤 로드맵 표 정정

**문제.** §3 로드맵 표가 D24·D26보다 오래되어 결정과 어긋났다. 표는 매칭·로비를 M1에 두지만 D24는 "M1은 친구 초대 링크만, 공개방 매칭은 M2 이후"로 확정했다. 기획 명세서 §11도 D24와 일치한다. 표를 결정에 맞춘다.

| | 내용 |
|---|---|
| **M0** | 타당성 검토 + 아키텍처 결정 + **킬 크리테리아 실험**. 판정 방식 2종(2d6 등급식, d100 롤언더), 위협 시계, 효과 DSL 골격 |
| **M1** | 실시간 파티(친구 초대 링크) · d20 판정 방식 · 노드 그래프 · 클루 웹 · 룰북 파일 업로드 · 안전 장치 1~3층 |
| **M2** | 공개방 매칭 · 톤 필터 · 신고·차단 · 성인 인증 · 솔로 모드 · 비동기 · 다이스풀/Year Zero 판정 방식 · 테이블 생성 |
| **M3** | FATE 판정 방식 · UGC 마켓 본격화 |
| **M4** | D&D 5e 어댑터 + 전술 그리드 (⑥ 전술적 깊이 · 말·토큰 스킨) |

**M0에는 킬 크리테리아 실험이 포함된다.** 결정 로그 §3 표에는 이 항목이 없었고 기획 명세서 §11에만 있었다. 설계가 끝난 것과 M0가 끝난 것은 다르며, 표에서 실험이 빠지면 그 구분이 사라진다. 표를 기획 명세서 쪽에 맞춘다.

M1에서 내려온 항목(공개방 매칭·톤 필터·신고·차단·성인 인증)은 낯선 사람을 받는 순간 함께 필요해지는 묶음이라 분리할 수 없다. 이것이 D24가 매칭을 미룬 이유다.

**용어.** 결정 로그는 "커널", 기획 명세서는 "판정 방식"으로 같은 것을 가리킨다. 용어 사전 방침(뜻이 드러나는 이름을 쓴다)에 따라 **"판정 방식"으로 통일**하고, 결정 로그 §3 표도 이 표기를 따른다.

## 5. 상태 전환과 "안 정한 것"의 명시

**M0는 설계와 실험 두 부분이고, 오늘 끝나는 것은 설계뿐이다.** 헤더가 이 구분을 드러내야 한다. 두 문서를 같은 방향으로 고친다 — 한쪽만 고치면 이번에 수집을 막았던 상태 불일치가 방향만 바뀐 채 남는다.

```
GPTRPG-M0-decisions.md
변경 전   상태: 논의 진행 중
변경 후   상태: 설계 확정 · 실험 미실시

GPTRPG-design-plan.md
변경 전   작성: 2026-07-30 (마일스톤 0 완료 시점)
변경 후   작성: 2026-07-30 (마일스톤 0 설계 종결 시점 · 실험 전)
```

"완료"라는 표현은 킬 크리테리아 실험이 끝나고 가설 H1·H5의 판정이 나온 뒤에만 쓴다. 그 실험이 진짜 킬 조건을 들고 있으므로, 실험 전의 "완료"는 프로젝트가 멈출 수도 있다는 사실을 지우는 표현이다.

**동시에 "안 정한 것" 절을 새로 만든다.** 이것이 없으면 "확정"을 읽은 사람이 모든 것이 정해졌다고 오해한다.

### M1 착수 시 결정할 것

| 항목 | 지금 어디까지 정했나 |
|---|---|
| 판정 커널 인터페이스 상세 | 방식 2개로 검증하는 것까지 (D27). 필드 단위 규격은 미정 |

| 상태값 묶음의 구체 형태 | 플랫폼이 정하지 않는다는 것까지 (D32) |
| 검색 기반 주입 여부 | M0에 넣지 않는다는 것까지 (D31) |

### M4로 미룬 것

좌표계, 전술 그리드, 시야 계산 (D13 ⑥, D17, D32).
